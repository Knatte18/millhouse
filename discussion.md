## Problem

The `.millhouse/millpy-*.py` wrapper scripts generated by mill-setup Phase 4.7 used `runpy.run_path`, bypassing `uv` entirely. When Claude invoked a wrapper directly without loading a skill, it fell back to bare `python` with a manual `PYTHONPATH=` export, violating the rule documented in CLAUDE.md.

The core fix — rewriting `_shortcuts.py` to generate PS1 wrappers that invoke scripts via `uv run --project` — **already landed in `main`** (commit `66e556f`, "18 — par-E — Migrate Python invocation to `uv run`"). This task's remaining work is: add the missing unit-test coverage for the legacy-cleanup behaviour, add a Phase 4.7 assertion to the integration test, and include an instruction to re-run Phase 4.7 on existing hubs.

## Scope

**In:**
- Add one unit-test case to `plugins/mill/unit_tests/test-shortcut-wrapper.py`: verify that `write_all()` deletes existing `.py` wrappers in `mill_dir`.
- Add Phase 4.7 assertions to `plugins/mill/integration_tests/test-bootstrap.ps1`: verify that PS1 wrappers exist and no legacy `.py` wrappers remain after the bootstrap run.
- Add a manual-step note at the end of `plugins/mill/skills/mill-setup/SKILL.md` (or Phase 4.7 section) instructing operators to re-run `/mill-setup` on any existing hub to flush old `.py` wrappers.

**Out:**
- No changes to `_shortcuts.py`, `shortcut-wrapper.ps1`, or any other production code — those are already correct on `main`.
- No changes to CLAUDE.md or other documentation beyond the one SKILL.md note.
- No automated migration script for existing `.millhouse/` directories; re-running `/mill-setup` is the upgrade path.

## Decisions

### Unit test for legacy .py cleanup

- Decision: Add a tempdir-based test that seeds `.py` wrappers for every `SHORTCUT_SCRIPTS` entry, calls `write_all()`, then asserts all `.py` files are gone and all `.ps1` files are present.
- Rationale: `write_all()` deletes `.py` files as a side effect; this path has zero test coverage today. The test pattern (tempdir fixture, no real git, no real LLM) matches all other unit tests in the suite.
- Rejected: Skipping the test — cleanup is a behaviour guarantee, not a cosmetic effect, and should be verified.

### Integration test assertion scope

- Decision: After the bootstrap run in `test-bootstrap.ps1`, assert that each script in `SHORTCUT_SCRIPTS` has a `.ps1` wrapper in `.millhouse/` and that no `.py` wrapper for any `SHORTCUT_SCRIPTS` entry remains.
- Rationale: The integration test already exercises mill-setup end-to-end; adding a Phase 4.7 check closes the gap without requiring a new test file.
- Rejected: A separate integration test file — unnecessary overhead for two assertions.

### Upgrade path for existing hubs

- Decision: Add a note in the mill-setup SKILL.md Phase 4.7 section: "If upgrading from a pre-PS1 hub, re-run `/mill-setup` — Phase 4.7 is idempotent and will replace `.py` wrappers with `.ps1` wrappers in a single pass."
- Rationale: Phase 8 verification already checks for absence of `.py` wrappers, so any re-run will both fix and verify. No additional automation is needed.
- Rejected: An automated migration script — overkill; re-running mill-setup is already the documented upgrade path for any Phase change.

## Technical context

**`plugins/mill/scripts/_shortcuts.py`** — `write_all(mill_dir: Path) -> list[Path]`

Two loops: (1) renders `shortcut-wrapper.ps1` template for each `SHORTCUT_SCRIPTS` entry and writes `mill_dir/<script>.ps1` (skips if byte-equal); returns list of written paths. (2) calls `(mill_dir / f"{script}.py").unlink(missing_ok=True)` for each entry — silent no-op if already absent.

**`plugins/mill/templates/shortcut-wrapper.ps1`** — the PS1 template. Uses `<SCRIPT>` token, rendered by `_render.render()`. Locates the latest plugin cache dir under `~/.claude/plugins/cache/millhouse/mill/` via `Get-ChildItem | Sort-Object Name -Descending | Select-Object -First 1`, then calls `uv run --project $latest "$latest\scripts\<SCRIPT>.py" @args`.

**`plugins/mill/unit_tests/test-shortcut-wrapper.py`** — existing tests: render substitution, write_all creates all PS1s, idempotent on second call, rewrites only stale file. Missing: cleanup of legacy `.py` wrappers.

**`plugins/mill/integration_tests/test-bootstrap.ps1`** — runs a full mill-setup sequence against a temp git repo. Phase 4 (junction) is covered; Phase 4.7 (shortcut wrappers) is not asserted. The test uses a `$millRoot` variable pointing at the plugins/mill dir and a `$scripts` variable for the scripts directory.

**`SHORTCUT_SCRIPTS` constant** (13 entries): `millpy-add`, `millpy-list`, `millpy-status`, `millpy-inspect`, `millpy-spawn`, `millpy-claim`, `millpy-cleanup`, `millpy-abandon`, `millpy-color`, `millpy-terminal`, `millpy-vscode`, `millpy-worktree`, `millpy-fetch-issues`.

## Testing

**Unit test (new case in `test-shortcut-wrapper.py`):**
- Seed a tempdir with `.py` wrappers for every `SHORTCUT_SCRIPTS` entry (write dummy content).
- Call `write_all(mill_dir)`.
- Assert: all `.py` files are deleted (`not (mill_dir / f"{s}.py").exists()` for each `s`).
- Assert: all `.ps1` files exist (`(mill_dir / f"{s}.ps1").exists()` for each `s`).

**Integration test (new assertions in `test-bootstrap.ps1`):**
- After the Phase 4.7 step in the bootstrap sequence, for each script in a hardcoded list (matching `SHORTCUT_SCRIPTS`):
  - Assert `.millhouse/<script>.ps1` exists.
  - Assert `.millhouse/<script>.py` does not exist.
- Failures increment the error counter like all other assertions in the file.

**Run the full unit suite** after changes: `python plugins/mill/unit_tests/run-all.py`.
