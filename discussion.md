## Problem

Three skills in `plugins/mill/` have no callers in the active codebase and create maintenance surface:
`mill-list` (superseded by `mill-status`), `mill-fetch-issues` (never called by `mill-ghissues-to-tasks`),
and `mill-worktree` (creates wiki-less worktrees, a use case not documented in the workflow).
Each has a SKILL.md, a script, and shortcut wrapper registration — all dead weight that confuses future
contributors.

## Scope

**In:**
- Delete skill directories: `plugins/mill/skills/mill-list/`, `mill-fetch-issues/`, `mill-worktree/`
- Delete scripts: `plugins/mill/scripts/millpy-list.py`, `millpy-fetch-issues.py`, `millpy-worktree.py`
- Delete test files: `plugins/mill/unit_tests/test-millpy-fetch-issues.py`, `test-millpy-worktree.py`
- Create `plugins/mill/unit_tests/test-gh-issues.py` (rescued `_render_body_with_comments` tests)
- Edit `plugins/mill/scripts/_shortcuts.py` — remove three entries from `SHORTCUT_SCRIPTS`
- Edit `plugins/mill/scripts/millpy-cleanup.py` — update orphan-worktree error message
- Edit `plugins/mill/scripts/_config.py` — remove `mill-worktree` from docstring
- Edit `plugins/mill/unit_tests/test-cleanup.py` — update assertion to match new message
- Edit `plugins/mill/unit_tests/test-shortcut-wrapper.py` — swap `"millpy-list"` fixture to `"millpy-status"`
- Edit `plugins/mill/unit_tests/test-skill-writer.py` — swap `"mill-fetch-issues"` fixture to `"mill-self-report"`
- Edit `plugins/mill/skills/mill-setup/SKILL.md` — replace `/mill-list` reference with `/mill-status`
- Regenerate `plugins/mill/SCRIPTS.md` — remove three script sections
- Regenerate `SKILLS.md` at repo root — remove three entries from mill table

**Out:**
- No changes to `mill-ghissues-to-tasks` skill or script logic
- No changes to `mill-status` or `mill-inspect`
- No changes to `_gh_issues.py` helper (the `_render_body_with_comments` tests are migrated, not the helper)
- No changes to `.millhouse/` shortcut PS1 wrappers on live worktrees (those are gitignored, regenerated by mill-setup)
- No migration of the `[P]` proposal marker from mill-list into mill-status

## Decisions

### Drop mill-list without migrating [P] marker

- Decision: Delete mill-list and its `[P]` (proposal file present) display feature; do not port the feature to mill-status.
- Rationale: Proposal presence is already conveyed by the linked heading form `[[slug]](proposal-slug.md)` in Home.md itself. Anyone reading Home.md directly sees it; mill-status shows the slug and title which are sufficient for workflow decisions.
- Rejected: Migrating `[P]` to mill-status — adds complexity for marginal value.

### Delete mill-fetch-issues CLI; rescue _render_body_with_comments tests

- Decision: Delete `millpy-fetch-issues.py` and its 3 CLI unit tests; extract the 7 `_render_body_with_comments` tests into a new `test-gh-issues.py`.
- Rationale: The CLI is dead code — `mill-ghissues-to-tasks` does its own inline fetch via `_gh_issues.fetch()`. The `_render_body_with_comments` tests cover real logic in `_gh_issues.py` (truncation at 10, ordering, deleted-author, empty-body) and are worth keeping.
- Rejected: Deleting all tests — loses coverage of core rendering logic. Keeping the script to retain the tests — wrong dependency direction.

### Update cleanup orphan message to git worktree remove

- Decision: Replace `run 'mill-worktree remove {entry}' to clean up` with `run 'git worktree remove --force {entry}' to clean up` in `millpy-cleanup.py` and update the corresponding assertion in `test-cleanup.py`.
- Rationale: `git worktree remove --force` is the correct raw command and remains valid after mill-worktree is deleted. Users running mill-cleanup can act on it without needing an additional mill wrapper.
- Rejected: Dropping the suggestion — less actionable for the operator.

### test-shortcut-wrapper.py fixture: millpy-list → millpy-status

- Decision: Change the template-rendering fixture in `test-shortcut-wrapper.py` from `"millpy-list"` to `"millpy-status"`.
- Rationale: The test exercises the template renderer, not actual script functionality. Any existing script stem works; `millpy-status` is a stable choice already in SHORTCUT_SCRIPTS.
- Rejected: Any other script name — no meaningful difference.

### test-skill-writer.py fixture: mill-fetch-issues → mill-self-report

- Decision: Change the hyphenated-name fixture in `test-skill-writer.py` from `"mill-fetch-issues"` to `"mill-self-report"`.
- Rationale: The test verifies that hyphenated skill names produce the correct directory structure. `mill-self-report` is also hyphenated and will remain in the codebase.
- Rejected: `mill-ghissues-to-tasks` — also valid but longer; `mill-self-report` is cleaner.

### SCRIPTS.md regeneration strategy

- Decision: Regenerate `SCRIPTS.md` by running all remaining `millpy-*.py --help` calls and rebuilding the file from the output (matching the existing generator pattern documented at the top of the file).
- Rationale: The file is auto-generated; editing it manually risks drift. Regenerating ensures it stays consistent with the remaining scripts.
- Rejected: Manual edit — acceptable but fragile.
