## Findings

### [BLOCKING] cfg["llm"] key read before fixture update breaks per-card verify
**Location:** B04 Cards 14→18; B05 Cards 21→22
**Issue:** Cards 14 (B04) and 21 (B05) add unconditional `cfg["llm"]["bulk_timeout"]` / `cfg["llm"]["holistic_timeout"]` reads to `_review_plan.py` and `_review_code.py`. The test-fixture updates that add the `"llm"` dict to cfg live in Cards 18 and 22, which come later. Between the code change and the fixture fix, every existing test in the affected flow-test files raises `KeyError`. The plan's stated requirement "Run-all unit tests must pass after every card" is impossible to satisfy in this window.
**Fix:** Either (a) split each problematic card into two: fixture-update first, then code change; or (b) explicitly require the `cfg["llm"]` fixture update to be part of Card 14 / Card 21 respectively, with Cards 18 / 22 only adding the new test cases.

### [BLOCKING] Step 4.5 placement bypassed for all-ERROR aggregate
**Location:** B08 Card 29, SKILL.md Phase: Plan Review
**Issue:** An all-ERROR run (all LLM calls fail) produces `verdict: REQUEST_CHANGES` and `blocking_count: 0` from `aggregate_verdict` + `sum(blocking_count)`. With step 4.5 placed *after* 4c, the flow evaluates 4a (APPROVE? No) → 4b (REQUEST_CHANGES AND blocking_count == 0? **Yes**) → applies NIT fixes, sets `approved: true`, breaks loop. Step 4.5 is never reached; the plan is incorrectly marked approved after an all-ERROR round.
**Fix:** Insert step 4.5 between step 4a and step 4b, or rewrite step 4b's guard to explicitly exclude the case where `reviews[].every(r => r.verdict == "ERROR")`.

### [NIT] Missing import instructions for new helpers in B04 (inconsistency with B07)
**Location:** B04 Cards 15 and 16
**Issue:** Cards 15 (`compute_deletes_union`) and 16 (`detect_resume_round`) call functions that are not yet in `_review_plan.py`'s import block, but neither card says to add them. B07 Card 27 is explicit: "Add `compute_deletes_union` to the existing `from _review_common import (...)` block." The inconsistency may cause a silent import error the first time the implementer runs verify after Card 15 or 16.
**Fix:** Add one sentence to each card: "Add `<name>` to the existing `from _review_common import (...)` block in `_review_plan.py`."

### [NIT] "bytes" comment inaccurate for text-mode Popen in Card 8
**Location:** B02 Card 8, timeout handler description
**Issue:** The plan states "`collected_stdout = exc.stdout` and `collected_stderr = exc.stderr` (both may be `None` or `bytes`)." With `text=True` Popen, `TimeoutExpired.stdout`/`.stderr` are `None` or `str`, not `bytes`. The comment misleads the implementer about the type; code that inspects or decodes these as bytes would be wrong.
**Fix:** Change the parenthetical to "both may be `None` or `str` in text mode" and remove the "preserve as-is to match subprocess.run's behaviour on timeout" note (the types already match).

### [NIT] B05 Card 22 test (b) stub-wrapping for retry LLMError is underspecified
**Location:** B05 Card 22 test (b)
**Issue:** The test requires stub.run to return NEED_CONTEXT on the first call and raise LLMError on the second. The plan says "wrap the original stub.run so first call returns the seeded NEED_CONTEXT and second call raises" without showing the closure or counter pattern. The stub's own queue raises `RuntimeError` (not `LLMError`) on empty; a naive monkey-patch that calls `stub.seed([(NEED_CONTEXT_TEXT, "sid-1")])` and then replaces `stub.run` with a raiser would lose the first-call behavior. An implementer unfamiliar with the pattern may end up patching incorrectly.
**Fix:** Add a four-line code sketch showing a `call_count` closure or a `side_effect` list approach to make the required two-call behavior unambiguous.
