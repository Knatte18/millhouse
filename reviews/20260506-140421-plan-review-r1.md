## Findings

### [BLOCKING] Integer deps serialized as strings in `_make_overview`
**Location:** batch-numbering / card 6
**Issue:** Card 6 updates `test_check_depends_on_unknown_dirty` to use `"depends-on": [99]` (integer) and adds `number:` emission to `_make_overview`, but never fixes the `deps_yaml` line — `"[" + ", ".join(f'"{d}"' for d in deps) + "]"` quotes every value, producing YAML `["99"]` (string) instead of `[99]` (integer). YAML parses the dep as string `"99"`, so `isinstance(dep, int)` is False in card 2's updated `_check_depends_on_unknown`, the string path fires instead, and the integer-dep code path is never exercised. The assertion `"99" in message` passes accidentally.
**Fix:** Add to card 6: update `deps_yaml` to `"[" + ", ".join(str(d) if isinstance(d, int) else f'"{d}"' for d in deps) + "]"` so integer deps emit without quotes.

### [NIT] "Explore targets" criterion retains old field name
**Location:** field-rename / card 9
**Issue:** Both `review-plan-batch.md` and `review-plan-holistic.md` contain the criterion "Explore targets — purpose-driven; subset of `Reads:`." Card 9's general instruction ("same field-name replacements as above") covers it conceptually, but the occurrence is not listed explicitly — an implementer scanning only the enumerated changes will miss it.
**Fix:** Add to card 9: replace `` `Reads:` `` with `` `Context:` `` in the "Explore targets" criterion in both templates.

### [NIT] `_check_reads_not_backtick_path` name inconsistent after rename
**Location:** field-rename / card 8
**Issue:** After the rename the function validates `Context:`/`Edits:`/`Creates:`/`Deletes:` fields yet still carries "reads" in its name; card 8 updates every error message but does not rename the function or its call site in `run()`.
**Fix:** Add to card 8: rename to `_check_ref_not_backtick_path` and update the single call site in `run()`.
