## Findings

### [NIT] Card 6 omits `import os` addition alongside `import shutil` removal
**Location:** Batch path-fix / Card 6
**Issue:** `_llm_claude.py` currently has no `import os`; the new `_claude_argv_prefix()` function uses `os.name == "nt"`. The card says drop `import shutil` but never says add `import os`.
**Fix:** Add "Add `import os`" to requirement list alongside the shutil removal note.

### [NIT] Card 20 `PLUGIN_ROOT` instruction doesn't match test-review-*.py naming
**Location:** Batch tests-and-docs / Card 20
**Issue:** The card instructs adding `PLUGIN_ROOT = HUB / "plugins" / "mill"` but `test-review-code.py`, `test-review-discussion.py`, and `test-review-plan.py` use `_HUB` and `_MILL_ROOT` (not `HUB`). The equivalent for those files is `_PLUGIN_ROOT = _MILL_ROOT`.
**Fix:** Clarify: for files using `_MILL_ROOT`, the constant is `_PLUGIN_ROOT = _MILL_ROOT`.

### [NIT] Card 19 removes test-bootstrap.ps1 self-containedness without flagging the regression
**Location:** Batch tests-and-docs / Card 19
**Issue:** Deleting `$env:PYTHONPATH = $scripts` makes the test dependent on global PYTHONPATH state (mill-setup having been run). Previously the test was self-contained — any dev could run it after cloning. Uv does not add `scripts/` to PYTHONPATH automatically for non-pytest invocations; `import _junction` in the `uv run python -c "..."` calls succeeds only when global PYTHONPATH already points at `scripts/`.
**Fix:** Add a comment to the card acknowledging this tradeoff and referencing the mill-setup prerequisite.

### [NIT] Batch path-fix prose contradicts DAG dependency
**Location:** Batch path-fix overview
**Issue:** "This batch is independent of `foundation`" conflicts with `depends-on: [foundation]` in the Batch Index. The prose should say "functionally independent but sequenced after foundation so the `verify:` command can use `uv run`."
**Fix:** Reword to "sequenced after foundation for verify purposes; the code changes themselves do not require uv."

APPROVE
Four NITs, no blocking issues; plan is comprehensive and correctly handles all known API shape errors.
