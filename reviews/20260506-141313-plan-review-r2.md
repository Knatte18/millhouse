## Findings

### [BLOCKING] Card 4 drops string-dep fix guidance from SKILL.md table

**Location:** batch-numbering / Card 4
**Issue:** The `depends-on-unknown` mechanical-fix row is *replaced* with integer-only guidance ("Compare the unknown number against the `number:` values in the Batch Index"). The existing string-dep guidance ("If it is a typo of an existing entry, correct it") is removed. Because both formats remain valid (Decision: backward-compat), plans using legacy string `depends-on:` would have no documented fix path for `depends-on-unknown` errors.
**Fix:** Extend the row to cover both cases: integer deps → compare against `number:` values; string deps (legacy) → compare against `name:` values and correct the typo.

### [BLOCKING] Card 11 misses hardcoded `**Reads:**`/`**Modifies:**` strings in two tests

**Location:** field-rename / Card 11
**Issue:** `test_check_reads_not_backtick_path_dirty` builds its batch text as a raw string containing `"- **Reads:** \`src/foo.py\` (used by foo)\n"`. After Card 8 renames `_RE_REFS_HEADER` to match `Context|Edits|Creates|Deletes`, this header no longer matches; the check never fires; the test expects 1 error but receives 0. `test_check_reads_not_backtick_path_clean` has the same raw-string issue (`"- **Reads:** \`src/a.py\`\n"`, `"- **Modifies:** none\n"`); it passes vacuously rather than exercising the check. Neither test uses `_make_batch_file`, so Card 11's helper-rename instructions leave them broken. Batch 02's `verify:` command runs `test-plan-validate.py` — this fails.
**Fix:** Add to Card 11 an explicit instruction to update the hardcoded batch strings in both `test_check_reads_not_backtick_path_clean` and `test_check_reads_not_backtick_path_dirty` from `**Reads:**`/`**Modifies:**` to `**Context:**`/`**Edits:**`.

### [NIT] Card 6 test name is inverted

**Location:** batch-numbering / Card 6
**Issue:** `test_check_depends_on_unknown_dirty_integer` is described as confirming "the old string-dep path still works — provide a batch with `depends-on: ["non-existent-batch"]` (no `number:` field)". The name implies it tests integer deps; the body tests string deps.
**Fix:** Rename to `test_check_depends_on_unknown_dirty_legacy_string` or similar.

### [NIT] `plan-overview.md` HTML comment retains old field names after batch 02

**Location:** field-rename (no card covers this)
**Issue:** The template comment in `plan-overview.md` reads "resolving card-level `Reads:`/`Modifies:` paths". No card in batch 02 touches `plan-overview.md`; the comment is stripped at render time so there is no runtime impact, but the template source is inconsistent with the renamed vocabulary.
**Fix:** Either add `plan-overview.md` to Card 9's scope with the single comment-line update, or explicitly note the omission is intentional.

### [NIT] `resolve_deps_as_names` unspecified for unresolved integer deps

**Location:** batch-numbering / Cards 1–2
**Issue:** Card 1 specifies `resolve_deps_as_names` translates integer `n` via `number_to_name[n]`, but does not specify the behaviour when `n` has no matching `number:` entry. If it KeyErrors, `_compute_transitive_ancestors` (called in `_check_parallel_modifies_overlap`) raises an unhandled exception from `_plan_validate.run()`. If it silently falls back, `_compute_transitive_ancestors` BFS misses the dep. Card 2 adds no guard here.
**Fix:** Specify that `resolve_deps_as_names` silently drops (or preserves as-is) unresolved integer entries, and note in Card 2 that `_compute_transitive_ancestors` tolerates this because `_check_depends_on_unknown` is the authoritative check for dangling deps.
