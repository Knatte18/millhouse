## Findings

### [BLOCKING] Crash-recovery glob pattern wrong in Card 6 step 2
**Location:** Batch 2 / Card 6, step 2
**Issue:** The plan specifies `*-code-review-holistic-r{H}.md` as the crash-recovery scan pattern. `_review_common.write_review_file` produces `{ts}-code-review-r{N}.md` when `scope` is `None` or `"holistic"` — no "holistic" segment in the filename. The pattern will never match; crash-recovery silently re-fires every holistic round.
**Fix:** Change the scan pattern to `*-code-review-r{H}.md`, matching the RE_SIMPLE convention. This is consistent with how `discover_round` and `detect_resume_round` identify holistic vs. per-batch files.

### [BLOCKING] `_llm_claude` missing from Card 5 Context list
**Location:** Batch 2 / Card 5, Context field
**Issue:** The Requirements block explicitly imports `import _llm_claude` and catches `_llm_claude.LLMError`. `_llm_claude` is absent from the Context list, so the implementer has no sanctioned read of that file. Per the plan-review criteria, referencing a class from a file not in Context/Edits is BLOCKING.
**Fix:** Add `plugins/mill/scripts/_llm_claude.py` to the Context list of Card 5.
