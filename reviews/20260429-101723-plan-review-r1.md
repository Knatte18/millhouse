## Findings

### [BLOCKING] Batch 01 verify gate fails: hub-form wiki-path tests in test-paths.py not updated
**Location:** Batch 01, Card 1
**Issue:** Card 1 changes `_sibling.resolve_path` from `name == "hub"` to `parent.name == "wts"`, but two `resolve_wiki_path` tests in `test-paths.py` create a fixture dir named `hub` under a random tempdir (where `parent.name != "wts"`) and assert the result equals `tmp_path / "wiki"`. Under the new rule these fall through to prefix-form and return `tmp_path / "hub.wiki"` — both assertions fail. Card 1 only touches `test-sibling.py`; Card 4 only updates the `worktrees_dir` fallback expectation. No card in batch 01 covers the two `resolve_wiki_path` hub-form fixture lines. Batch 01's `run-all.py` verify gate cannot pass.
**Fix:** Card 1 (or Card 4) must also update the two `resolve_wiki_path` hub-form tests in `test-paths.py`: either change the mock fixture to container-form (`container / "wts" / "repo"`) so the wiki result stays `container / "wiki"`, or update the assertion to expect prefix-form output.

### [BLOCKING] `upsert` removed in batch 01 but mill-setup SKILL.md invokes it until batch 04
**Location:** Batch 01, Card 5; Batch 04, Card 18
**Issue:** Card 5 removes `_gitignore.upsert`, justified as "no remaining callers after batch 04." But the live `mill-setup` SKILL.md Phase 4.5b executes `_gitignore.upsert(Path('.gitignore'), ...)` via a Python `-c` snippet. Running `/mill-setup` at any point between Card 5 landing and Card 18 rewriting the SKILL.md raises `AttributeError: module '_gitignore' has no attribute 'upsert'`. The existing operator constraint ("don't run mill-setup before migration") is stated for a different reason and does not cover this regression.
**Fix:** Either keep `upsert` through the full batch sequence and remove it atomically in Card 18 alongside the SKILL.md rewrite, or update the SKILL.md to call `upsert_split` directly in Card 5 (the SKILL.md's callsite is already in Card 5's `Reads:` list via the mill-setup SKILL.md reference).

### [BLOCKING] Card 12 tests invoke `_paths.resolve_main_worktree_root` via subprocess — no mock planned
**Location:** Batch 03, Card 12
**Issue:** The rewritten `resolve_path(path_tmpl, slug)` internally calls `_paths.resolve_main_worktree_root(Path.cwd())`, which shells out `git rev-parse --git-common-dir`. Card 12 describes tests as a "tempfile fixture that creates `<container>/wts/<slug>/.millhouse/active.slug.md`" with no git repo setup and no mention of patching `resolve_main_worktree_root` or `_subprocess_util.run`. The tests will error at the subprocess call — a non-git temp directory exits non-zero — and never reach the path-join assertion.
**Fix:** Card 12's test requirements must explicitly patch `_paths.resolve_main_worktree_root` to return `container_path` derived from the tempfile fixture, consistent with the `patch("_subprocess_util.run", ...)` pattern already used throughout `test-paths.py`. Without this, the batch 03 verify gate fails.

### [NIT] Migration script wiki resolution incorrect when run from new-code branch against old layout
**Location:** Batch 05, Card 22
**Issue:** Card 22 states the script "works on the OLD layout because the old `_sibling.py` rule still recognises `hub`-form via prefix-form fallback." This is wrong: prefix-form computes `<container>/hub.wiki/`, not `<container>/wiki/`. Running from a checked-out branch with the new sibling rule therefore silently resolves the wrong wiki path, and the pre-flight halt fails before the in-flight task check unless `paths.wiki:` is already set in `config.local.yaml`.
**Fix:** Add a note in Card 22 requirements that the "run from new-code branch" option requires `paths.wiki:` in `config.local.yaml`; or add a fallback in the migration script that detects a non-existent `resolve_wiki_path` result and checks `<container>/wiki/` directly when `cwd.name == "hub"`.
