## Findings

### [BLOCKING] Crash-recovery glob doesn't match actual holistic review filenames
**Location:** Batch 2 / Card 6, Step 2
**Issue:** Step 2 scans for `*-code-review-holistic-r{H}.md`, but `write_review_file` in `_review_common.py` produces `{ts}-code-review-r{N}.md` for holistic scope — the `else` branch runs for both `scope=None` and `scope="holistic"`, emitting `f"{ts}-{review_type}-review-r{round_num}.md"`. The `-holistic-` substring never appears in the filename. Crash recovery would silently find nothing, re-invoke the review CLI, and produce duplicate review files on restart.
**Fix:** Change the crash-recovery glob to `*-code-review-r{H}.md` (which won't collide with per-batch files since those always embed a batch-name segment).

### [NIT] Holistic review command omits `[--extra-file <p> ...]` clause
**Location:** Batch 2 / Card 6, Step 4
**Issue:** Step 8 delegates NEED_CONTEXT handling to "the same extra-files / notify path as per-batch," which accumulates `extra_files` across rounds and passes them to the next review invocation. Step 4's command snippet shows no `[--extra-file <p> ...]` argument, leaving the invoker without a concrete example for the NEED_CONTEXT round.
**Fix:** Add `[--extra-file <p> ...]` to the Step 4 command example, mirroring the per-batch review command format.
