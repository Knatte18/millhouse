## Findings

### [BLOCKING] `millpy-claim.py` calls `write_initial_status` with wrong kwarg and wrong value
**Location:** Batch: simple-fixes, Card 5
**Issue:** `millpy-claim.py` calls `_spawn_core.write_initial_status(wiki_path=wiki_path, slug=slug, ...)`. The function signature has `worktree_path` as its first positional param — `wiki_path` is an unexpected kwarg that raises `TypeError` at runtime on every successful claim. Additionally, even if the kwarg name were correct, passing `wiki_path` (the wiki clone) instead of `git_root` (the task worktree) would write `status.md` into the wiki. Card 5 modifies this file but neither fixes this call nor adds a test assertion to catch it. The existing mock (`MagicMock`) silently swallows any kwargs, hiding the bug.
**Fix:** Change to `_spawn_core.write_initial_status(worktree_path=git_root, slug=slug, ...)`. Add assertions to the Card 5 test: `assert "wiki_path" not in status_call.kwargs` and `assert status_call.kwargs.get("worktree_path") == Path("/fake/repo")`.

### [NIT] Cards 9 and 12 set `REPO` token to hub's dir name, not repo name
**Location:** Batch: spawn-worktree-dst, Cards 9 and 12
**Issue:** Both cards set `"REPO": hub_path.name`. For subfolder-install (hub = `.../repo/src/Models/`), this yields `"Models"` instead of `"millhouse"`. If any junction template in `wiki/config.yaml` uses `<REPO>` to reference the repository directory name, junction creation in spawned worktrees would target wrong paths.
**Fix:** Use `resolve_main_worktree_root(git_root).name` for the `REPO` token to always return the main worktree (repo root) directory name regardless of hub subpath.

### [NIT] Card 12 omits `resolve_container_path` from import additions
**Location:** Batch: spawn-worktree-dst, Card 12
**Issue:** Card 12 requires `CONTAINER_PATH=str(resolve_container_path(git_root))` in the tokens dict but lists only `resolve_hub_path` and `resolve_hub_relative_path` as imports to add. `resolve_container_path` is also needed but absent from the import list.
**Fix:** Add `resolve_container_path` to the imports enumerated in Card 12's Requirements.

### [NIT] Card 14 leaves `mill-skills-index/SKILL.md` modification ambiguous
**Location:** Batch: docs-gitignore, Card 14
**Issue:** Card 14 says "verify whether it is operational; if so, fix" for `mill-skills-index/SKILL.md`, listing it under Modifies. The file's operational command already reads `uv run --project "${CLAUDE_PLUGIN_ROOT}" "${CLAUDE_PLUGIN_ROOT}/scripts/millpy-skills-index.py"` — already correct. Leaving the implementer to discover this during execution creates unnecessary ambiguity and the file should not be listed in Modifies.
**Fix:** Remove `mill-skills-index/SKILL.md` from Modifies; confirm in the requirements text that the file is already correct and needs no change.
