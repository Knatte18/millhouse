## Findings

### [NIT] Card 11 omits "single-line legacy form" test from explicit fixture list
**Location:** batch-field-rename / card 11
**Issue:** The explicit `test-review-common.py` fixture list doesn't enumerate the "single-line legacy form" test (`"- **Reads:** \`x\`, \`y\`\n"`); after Card 7 renames `_RE_REFS_HEADER`, that fixture would fail `assert refs == ["x", "y"]` — not pass vacuously. It falls under the catch-all but is the most likely miss for an implementer scanning the named list.
**Fix:** Add `"- **Reads:** \`x\`, \`y\`\n"` → `"- **Context:** \`x\`, \`y\`\n"` to the explicit enumeration in Card 11's Requirements.

### [NIT] Card 11 "update all call sites" not enumerated for `test-plan-validate.py`
**Location:** batch-field-rename / card 11
**Issue:** ~10 call sites in `test-plan-validate.py` use `reads=`/`modifies=` keyword args (spread across `test_check_non_existent_path_*`, `test_check_parallel_modifies_overlap_*`, `test_wiki_config_mutation_*`, `test_reads_token_*`). A missed rename throws `TypeError` and fails verify — the verify command catches it, but the implementer must grep to find all sites not named in the Requirements.
**Fix:** Enumerate the affected test functions by name alongside the explicit list, or add a note: "grep for `modifies=` and `reads=` in the test file to find all call sites."

### [NIT] Intentional check-key / function-name asymmetry not documented
**Location:** batch-field-rename / card 8
**Issue:** Card 8 renames `_check_reads_not_backtick_path` → `_check_ref_not_backtick_path` but explicitly leaves the error-dict check key `"reads-not-backtick-path"` unchanged. The rationale (stable external API, SKILL.md mechanical-fix table references it) is sound but absent from the card's text; future maintainers will see a permanent mismatch without explanation.
**Fix:** Add one sentence to Card 8: "The check key `reads-not-backtick-path` in error dicts is intentionally unchanged — the SKILL.md mechanical-fix table references it by key."

### [NIT] `resolve_deps_as_names` contract for root batches unspecified
**Location:** batch-numbering / card 1
**Issue:** The Requirements describe `resolve_deps_as_names` as "maps each batch's `depends-on:` entries to names" but don't say whether root batches (with `depends-on: []`) are included in the returned dict. Callers use `.get(name, [])` in `_compute_transitive_ancestors` and pre-initialize `indegree`/`adj` from all batches in `_check_acyclic`/`topo_order`, so the omission is safe either way — but the docstring leaves the return shape ambiguous.
**Fix:** Add to the function docstring: "All batches are included in the returned dict; root batches (empty deps) map to `[]`."

## Verdict

APPROVE
Four NITs, no BLOCKINGs; the plan is structurally sound with correct backward-compat, sequencing, and test coverage.
