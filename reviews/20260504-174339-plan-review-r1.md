### [BLOCKING] B01 Card 7 breaks B01's own verify

**Location:** Batch 01 (content-helpers), Card 7 / `_reviewer_test_stub.py`
**Issue:** Card 7 adds `"timeout": timeout` to the stub's captured kwargs dict. The fixes are deferred to B04 Card 18(iii) and B05 Card 22, which come after B01.
**Fix:** Add `test-review-plan-flow.py` and `test-review-code-flow.py` to Card 7's Modifies list; update the three affected exact-equality assertions to expect `"timeout": None` within Card 7 itself.

### [NIT] B06 Card 23 — double-newline risk in `print_error`

**Location:** Batch 06 (cli-error-prefix), Card 23
**Issue:** Requirements say to write `f"ERROR: {exc}\n"` to stderr but also say to use `print(…, file=sys.stderr)` rather than `sys.stderr.write`. `print(f"ERROR: {exc}\n", file=sys.stderr)` emits a double trailing newline; Card 25 test (a) expects a single one.
**Fix:** State explicitly to call `print(f"ERROR: {exc}", file=sys.stderr)` (no `\n` in the format string; `print` adds one).

### [NIT] B04 Card 18 test (d) — per-batch prompt index non-deterministic with multiple batches

**Location:** Batch 04 (review-plan-integration), Card 18, test (d)
**Issue:** Assertion `captured_prompts()[0][1]["timeout"] == 900` pins the per-batch call at index 0. When the fixture has >1 batch, ThreadPoolExecutor workers complete in arbitrary order, making index 0 non-deterministic.
**Fix:** Specify that test (d) uses a single-batch fixture so `captured_prompts()[0]` is always the per-batch call and `captured_prompts()[1]` is always the holistic call.
