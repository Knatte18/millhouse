## Findings

### [NIT] `_status.read_full` lacks error handling in Card 3 common setup
**Location:** Batch 01 / Card 3, common setup step 6
**Issue:** `full = _status.read_full(status_path)` can raise `ValueError` (missing file, malformed yaml, missing timeline block) — unlike `load_config` (ReviewError caught) and `read_slug` (ActiveError caught), this propagates as an unhandled traceback.
**Fix:** Wrap in `try/except ValueError as e: print(str(e), file=sys.stderr); return 1`.

### [NIT] Missing unit test for `--resume --review-file <nonexistent>` path
**Location:** Batch 02 / Card 4, test matrix
**Issue:** The plan specifies "If not exists → stderr + return 1" for a non-existent review file (resume path step 1), but no test exercises this validation. Tests 5/5b test LLMError on resume; no test covers a missing review file.
**Fix:** Add Test 9: call `main(["test-batch", "--resume", "--round", "1", "--review-file", "/nonexistent/review.md"])`; assert exit code 1, no JSON on stdout.

### [NIT] SKILL.md holistic review section retains direct `_implementer_sonnet.run` call
**Location:** Batch 02 / Card 5, `## Holistic code review` section
**Issue:** After all six edits, the holistic review path still directly calls `_implementer_sonnet.run(...)` instead of the new CLI. Edit 4 only updates the inline signature. A future maintainer may wonder why holistic dispatch bypasses the CLI while per-batch dispatch uses it.
**Fix:** Add a one-sentence note in the holistic section: "Holistic review uses a fresh session spanning multiple batches; the `millpy-implement.py` CLI (scoped to a single batch) is not used here."

APPROVE
