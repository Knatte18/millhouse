## Findings

### [BLOCKING] path-fix verify requires pyproject.toml but omits foundation dependency
**Location:** plan/02-path-fix.md — batch header  
**Issue:** The verify command `uv run --project plugins/mill plugins/mill/scripts/millpy-vscode.py --help` requires `plugins/mill/pyproject.toml`, created only by the `foundation` batch; `path-fix` declares `depends-on: []`, so a topological sort may run it before `foundation`, causing verify to fail with "no pyproject.toml found."  
**Fix:** Change `path-fix`'s `depends-on` to `[foundation]`; the batch scope note ("functionally, the changes work with bare python") confirms this adds no implementation constraint, only a verify-ordering constraint.

### [BLOCKING] mill-resume Phase 8 broken `millpy.core.junction` import not addressed
**Location:** plan/04-skills-sweep.md — Card 15 + Card 18  
**Issue:** `mill-resume/SKILL.md` Phase 8 contains `from millpy.core.junction import create as junction_create` — a broken Python import; the `millpy` package does not exist. Card 15 fixes only `python -m millpy.entrypoints.regenerate_sidebar`; card 18's grep `python\s+-m\s+millpy\.` targets shell invocations and misses this inline Python import entirely. An operator running `/mill-resume` post-merge would hit an `ImportError` at Phase 8.  
**Fix:** Extend card 15 requirements to replace Phase 8's `from millpy.core.junction import create as junction_create` with `from _junction import create as junction_create` (or the `uv run python -c "import _junction; _junction.create(...)"` bash form consistent with the rest of the skill). Extend card 18's audit grep to also cover `from millpy\.[a-z]` patterns.

### [NIT] Card 3 smoke-check uses bare `python`, not `uv run`
**Location:** plan/01-foundation.md — Card 3  
**Issue:** Smoke-check reads `python -c "from pathlib import Path; import _shortcuts; ..."`. This requires PYTHONPATH to be set externally and contradicts the batch's own migration principle; will silently succeed only on machines with mill-setup already run.  
**Fix:** Change to `uv run --project plugins/mill python -c "..."` — consistent with the batch verify pattern and the migration goal.

### [NIT] Card 20 env-kwarg removal instruction is ambiguous for review tests
**Location:** plan/05-tests-and-docs.md — Card 20  
**Issue:** Requirement says "drop the `env=` kwarg entirely if no other override remains" — but `_run_script` in all three review tests also sets `PYTHONIOENCODING = 'utf-8'` in the same `env` dict, which must be preserved.  
**Fix:** Clarify: remove only the `env["PYTHONPATH"] = str(_SCRIPTS)` line from the dict; keep the `env=` kwarg with `PYTHONIOENCODING` still present.
