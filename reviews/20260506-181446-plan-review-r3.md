## Findings

### [NIT] Holistic APPROVE path does not commit the review file
**Location:** Batch 2 / Card 6, step 5
**Issue:** On APPROVE the plan says "Commit status" — only `status.md` is staged. The per-batch APPROVE path explicitly stages `<review_file_path>` alongside `status.md`. The holistic review file would be left as an uncommitted tracked file until mill-merge.
**Fix:** Change the APPROVE commit instruction to `git -C <worktree> add status.md <holistic-review-file> && git -C <worktree> commit -m "mill-go: holistic approved round {H}"`, mirroring the per-batch pattern.

### [NIT] Holistic phase names not added to Entry gate's resume row
**Location:** Batch 2 / Card 6 (Entry section edit)
**Issue:** `holistic-reviewing` and `holistic-fixing` are set as the top-level `phase:` field by `append_phase` (step 3 / step 13 of the CLI). The Entry gate's resume row only lists `implementing / reviewing / fixing`. If mill-go is killed and restarted during the holistic phase it falls to "any other → halt" and the Card 6 crash-recovery scan (step 2) never activates. This is consistent with the existing per-batch behavior but is a new phase space introduced by this PR.
**Fix:** Card 6's Entry-section addition should also extend the resume row: `implementing / reviewing / fixing / holistic-reviewing / holistic-fixing`.

APPROVE
