## Findings

### [NIT] `millpy-claim.py` local wrapper parameter name inconsistent
**Location:** `plugins/mill/scripts/millpy-claim.py:50`
**Issue:** The local `_load_config` wrapper still uses `git_root` as its parameter name, though the call site correctly passes `resolve_hub_path()`. Card 9 explicitly renamed the equivalent wrapper in `millpy-spawn.py` to `worktree_root`; Card 5 is silent on this, leaving an inconsistency.
**Fix:** Rename `def _load_config(wiki_path: Path, git_root: Path)` → `def _load_config(wiki_path: Path, worktree_root: Path)` and update the inner `_load_config_lenient(wiki_path, git_root)` reference.

### [NIT] `resolve_git_root()` called without capturing return value
**Location:** `plugins/mill/scripts/millpy-fetch-issues.py:57`
**Issue:** `resolve_git_root()` is invoked with its return value discarded — unusual for a function documented to return a `Path`. Its only observable effect is raising `SystemExit` on a non-git cwd. This is per-plan but is a code smell since nothing distinguishes it from an accidental drop.
**Fix:** Either assign (`git_root = resolve_git_root()`) with a comment explaining the guard-only intent, or extract a separate `_assert_in_git_repo()` helper. Out of scope for this task per plan guidance; note for a future cleanup pass.
