## Findings

### [BLOCKING] Card 3 LLMError handler omits stuck_type specification
**Location:** batch implement-cli / card 3 — initial dispatch step 7 and fix-cycle step 7
**Issue:** Card 3 says "print synthetic stuck JSON" when `_llm_claude.LLMError` is caught but never specifies what `stuck_type` to emit; card 4 tests 5 and 5b both assert `stuck_type: transient`, creating a cross-card spec gap the `py_compile` verify won't catch.
**Fix:** Add to card 3's error-handling requirement: the synthetic JSON must include `"stuck_type": "transient"` (matching `implementer-brief.md`'s definition — tool/network failure a retry might clear).

### [BLOCKING] Board discipline claims mill-go pushes Prepare/Approve/done but adds no push commands
**Location:** batch tests-and-skill / card 5 / Edit 3
**Issue:** The replacement Board discipline bullet states "mill-go handles push for Prepare, Approve, blocked, and done commits," but none of the three edits add a `git push` command after the Prepare, APPROVE, blocked, or Handoff commits; the SKILL.md would describe a policy its own instructions don't fulfil.
**Fix:** Either (a) add `git push origin <branch>` after each Builder commit in Prepare, APPROVE, blocked, and Handoff sections, or (b) narrow the Board discipline statement to millpy-implement.py only and defer Builder-side push to a later task.

### [BLOCKING] Edit 3 misidentifies Approve as having "(no push)"; Handoff commit is missed
**Location:** batch tests-and-skill / card 5 / Edit 3
**Issue:** The clarification "The affected lines are in the Prepare commit and the Approve commit annotations" is wrong — the current SKILL.md's APPROVE verdict line has no `(no push)` suffix, while the Handoff step-1 `done` commit does; an implementer following the clarification literally leaves Handoff's `(no push)` intact, compounding the Board discipline inconsistency above.
**Fix:** Change the clarification to: "The affected lines are in the Prepare commit and the Handoff step-1 done commit."

### [NIT] git add return code unchecked, contradicts Shared Decision git-error-handling
**Location:** batch implement-cli / card 3 — initial dispatch step 4 and fix-cycle step 4
**Issue:** The Shared Decision "git-error-handling" states add failures cause exit 1, but step 4 calls `subprocess.run(["git", "add", "status.md"], cwd=project_root)` with no return-code check or `capture_output`.
**Fix:** Add `capture_output=True, text=True` to the `git add` call and gate the commit on `returncode == 0`, printing `result.stderr` and returning 1 on failure.

### [NIT] overview_path.read_text() missing encoding parameter
**Location:** batch implement-cli / card 3 — common setup step 11
**Issue:** `overview_path.read_text()` uses the platform default encoding; every other file read in the codebase specifies `encoding="utf-8"` explicitly.
**Fix:** Change to `overview_path.read_text(encoding="utf-8")`.

### [NIT] Holistic section's _implementer_sonnet.run signature goes stale after card 2

**Issue:** Card 2 adds `timeout: int = 1800` to `_implementer_sonnet.run`; the Holistic section's inline `signature:` line omits `timeout`, and the plan explicitly forbids touching that section.
**Fix:** Allow a targeted fourth edit to update the Holistic section's `_implementer_sonnet.run` signature to include `timeout: int = 1800`.

**Issue:** Edit 2 replaces only the quoted `>` block and the `_implementer_sonnet.run` line, leaving the preceding sentence "**Resume the implementer session** with a new user message:" which now introduces a CLI invocation instead of a message.
**Fix:** Extend Edit 2's replacement start point to also remove "**Resume the implementer session** with a new user message:" from the REQUEST_CHANGES bullet.
