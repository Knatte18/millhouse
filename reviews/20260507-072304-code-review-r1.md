## Findings

### [NIT] Stale docstring prose in `write_initial_status`
**Location:** `plugins/mill/scripts/_spawn_core.py:write_initial_status` (body, ~line 9 of docstring)
**Issue:** First docstring line correctly says `task/status.md`, but the body still reads "writes the file to `worktree_path / "status.md"`" and the `Args.worktree_path` description ends with "`.millhouse/``). ``status.md`` is written here" — both are carry-overs from the pre-migration wording.
**Fix:** Change the body sentence to "writes the file to `worktree_path / "task" / "status.md"`" and trim the stale `status.md` suffix from the `worktree_path` arg description.

### [NIT] `from _paths import` placed function-local vs. module-level
**Location:** `plugins/mill/scripts/millpy-migrate-layout.py:_step_rename_junctions` and `main()`
**Issue:** Plan card 11 req 1 says to extend the existing top-level `from _paths import` line; no such line existed, so both functions use local imports instead. Functionally equivalent, but diverges from the spec and is inconsistent with the style used by every other `millpy-*.py` script.
**Fix:** Hoist `from _paths import resolve_git_root, resolve_wiki_path, resolve_container_path, resolve_main_worktree_root` to module level and remove the duplicated local imports in both functions.

### [NIT] `_apply_inplace_record` recomputes `_task_status`/`_legacy_status` twice
**Location:** `plugins/mill/scripts/millpy-cleanup.py:_apply_inplace_record` (~line 302 and ~line 330)
**Issue:** The fallback pair is computed once for `read_parent_branch` and again for `_read_phase` with different variable names (`_task_status` / `_legacy_status` vs. `_task_status_ip` / `_legacy_status_ip`). The duplication is verbose and introduces a subtle divergence risk if the worktree_path check condition is edited in one place only.
**Fix:** Hoist the pair to the top of the `if record.worktree_path is not None:` block and reuse across both calls.
