### [BLOCKING] Card 5 Edit 2 scope too narrow — dangling text and double-commit
**Location:** batch 02, card 5 — Edit 2
**Issue:** Edit 2 replaces only the blockquote (`> Load the mill-receiving-review skill...`) and `_implementer_sonnet.run` line, leaving "**Resume the implementer session** with a new user message:" as dangling prose before the CLI invoke block. More critically, the preceding `git add status.md reviews/<file> && git commit "mill-go: review-request..."` instruction stays in the Builder's steps, so the Builder commits status.md (state=fixing + review file) and then the CLI commits status.md again (review_round + review_file), producing two commits for one logical operation with contradictory semantics. The Builder's commit is also not pushed (no push command in that section), while the CLI's commit is — leaving the review file in an unpushed-then-pushed gap that violates the new push policy.
**Fix:** Expand Edit 2 to replace the entire REQUEST_CHANGES bullet from "set batch state → `fixing`." through "On stuck → escalate." — delegate all state mutation, append_phase, commit, and push to the CLI.

### [BLOCKING] `overview_path.read_text()` missing `encoding="utf-8"` in Card 3
**Location:** batch 01, card 3 — common setup step 10
**Issue:** Every `read_text` call in the provided codebase specifies `encoding="utf-8"` (`_plan_dag.py`, `_render.py`, `_review_common.py`, etc.). The plan specifies `overview_path.read_text()` without encoding. On Windows (the project's target platform) the default is cp1252; non-ASCII plan content (accented characters in task titles or slugs) will raise `UnicodeDecodeError` or silently corrupt.
**Fix:** `overview_path.read_text(encoding="utf-8")`.
