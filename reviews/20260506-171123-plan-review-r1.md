## Findings

### [BLOCKING] subprocess mock returncode unspecified for existing test_fo_* tests
**Location:** 01-bugfix-batch / Card 5
**Issue:** The note says to patch `millpy_implement.subprocess.run` in existing `test_fo_*` tests "to avoid real git calls" but does not specify what returncode to use. Using `returncode=0` causes `_forward_output` to overwrite `commit_sha` in the parsed dict, breaking `test_fo_1`, `test_fo_4`, and others that assert exact JSON equality via `assertEqual(json.loads(out.strip()), json.loads(json_str))`. Omitting the mock causes `FileNotFoundError` when subprocess tries `cwd=Path("/fake")`.
**Fix:** Specify that the subprocess.run mock for existing `test_fo_*` tests must return `returncode=1` (non-zero) so the "forward original JSON string unmodified" path is taken, preserving all current test assertions.

### [NIT] Import style inconsistency in Card 2 requirements
**Location:** 01-bugfix-batch / Card 2
**Issue:** Requirements show bare `set_batch_fields(...)` call syntax but also say "match the existing import style," which is module-style (`import _status`; all calls use `_status.set_batch_field(...)`). Bare name requires `from _status import set_batch_fields`, contradicting "match existing style."
**Fix:** Either use `_status.set_batch_fields(...)` in the call examples (consistent with module import) or explicitly say to add `from _status import set_batch_fields` and drop the "match existing import style" qualifier.

### [NIT] "Sequential-letter naming convention" misapplied to test-status.py
**Location:** 01-bugfix-batch / Card 4
**Issue:** Card 4 says to add tests "using the existing sequential-letter naming convention (continuing from the last letter in use)" but `test-status.py` has no letter-named tests — it uses descriptive `print("PASS: ...")` lines in a flat `main()` function; letter naming is `test-millpy-bg.py`-specific.
**Fix:** Remove the letter-naming reference; say "append to the existing sequential `print('PASS: ...')` block in `main()`." The explicitly listed print strings already match the correct style.
