## Findings

### [BLOCKING] Holistic gate dropped from replacement section
**Location:** Batch 2 / Card 6
**Issue:** The replacement requirements for `## Holistic code review` (items 1–8) start immediately with `max_holistic_rounds = cfg.get(...)` but never include the `only if review.code.holistic: true` guard present in the current section. An implementer following the spec exactly produces a section that always fires holistic review, ignoring `holistic: false` configs.
**Fix:** Prepend a gate condition to item 1: "Only proceed if `cfg.get('review', {}).get('code', {}).get('holistic', True)` is truthy. Read `max_holistic_rounds` and set `H = 1` inside that guard." Preserves the existing behaviour for `holistic: false`.

### [BLOCKING] `status.md` fixture in Card 7 missing yaml and timeline blocks
**Location:** Batch 2 / Card 7
**Issue:** The fixture spec says "`status.md` (with `## Batches` section listing `test-batch` with `state: pending`)" but omits the mandatory top ```yaml``` block and `## Timeline` ```text``` block. Both `_status.read_full()` (Card 5 step 6) and `_status.append_phase()` (Card 5 step 13) are unpatched and call `_split_fences(…, "```yaml")` / `_split_fences(…, "```text")` against the real file — raising `ValueError` on a Batches-only fixture. Tests 1, 2, 3, and 6 all invoke `main()` and would fail.
**Fix:** Extend the `status.md` fixture spec to mirror `test-millpy-implement.py`: add the ```yaml``` front-matter block (phase, slug, task, branch, parent) and the `## Timeline` / ```text``` fence before the `## Batches` section.

### [NIT] Superfluous `import sys` in `_implementer_common.py`
**Location:** Batch 1 / Card 1
**Issue:** The requirements list `import sys` as a needed import for `_implementer_common.py`, but `_forward_output` uses only `re`, `json`, and `print` — `sys` is never referenced.
**Fix:** Remove `import sys` from the requirements; list only `import json` and `import re`.

### [NIT] `holistic_rounds` absent from Entry config-reading list
**Location:** Batch 2 / Card 6 (SKILL.md Entry step 3)
**Issue:** Every other `review.code.*` key consumed by the holistic section is documented in Entry step 3 (`rounds`, `self_fix_rounds`, `holistic`, `per_batch`). The new `holistic_rounds` key read inline in the new holistic section is not listed there, breaking the convention used by the rest of the skill.
**Fix:** Add `- \`review.code.holistic_rounds\` — max holistic fix rounds (default 1).` to the Entry step 3 bullet list.

### [NIT] Shared Decision `from-import-style` contradicts Card 5 step 20
**Location:** Batch 2 / Card 5 (Shared Decision and step 20)
**Issue:** The Shared Decision declares "Use `from _implementer_common import _forward_output` in both … `millpy-implement-holistic.py`", but step 20 writes `return _implementer_common._forward_output(output)` — a module-qualified call that requires `import _implementer_common`, not a from-import. An implementer must resolve the contradiction by choosing one style.
**Fix:** Either update step 20 to `return _forward_output(output)` (consistent with from-import) or remove `millpy-implement-holistic.py` from the Shared Decision's scope. Both work; pick one.
