## Findings

### [NIT] Card 1 comment mis-attributes ls-remote error handler
**Location:** Batch helpers / Card 1
**Issue:** Path D spec says "The caller (Phase 2 in mill-setup) is responsible for translating this to a user-facing reachability message" — but Phase 2 has already exited by the time `clone_or_init` runs in Phase 3; Phase 3 prose is the actual handler.
**Fix:** Change the comment to "Phase 3 skill prose surfaces the WikiSetupError verbatim."

### [NIT] Phase 3.2 note misstates when `.millhouse/` is created
**Location:** Batch skill-and-template / Card 5, Phase 3.2 requirements
**Issue:** The note says "`.millhouse/` does not exist at the time this phase fires (it is created in Phase 4)" — in the `--from-url` case, `set_local_wiki_overrides` creates `.millhouse/` itself, before Phase 4.
**Fix:** Rephrase: "`.millhouse/` may not exist yet; `set_local_wiki_overrides` creates it via `mkdir(parents=True, exist_ok=True)`."

### [NIT] `test_pull_existing_repo_match` missing `branch=None` sub-case
**Location:** Batch helpers / Card 2
**Issue:** Card 1 Path A skips the `branch --show-current` call when `branch is None`, but Card 2 only tests the branch-present variant; the call-sequence assertion for `branch=None` (only `remote get-url` + `pull`) is unexercised.
**Fix:** Add a `test_pull_existing_repo_match_branch_none` test asserting no `branch --show-current` call is made.

### [NIT] Phase 3 Python inline leaves branch-ternary underspecified
**Location:** Batch skill-and-template / Card 5, Phase 3 update
**Issue:** The plan says "show how to translate empty `<wiki-branch>` to Python `None` (e.g. ternary expression)" but the code block uses opaque placeholder `<wiki-branch-or-empty-then-None>` without giving the concrete expression.
**Fix:** Supply the exact snippet, e.g. `branch=r'<wiki-branch>' if r'<wiki-branch>' else None`.

## Verdict

APPROVE — plan is sound; four NITs are documentation/coverage gaps that pose no correctness risk.
