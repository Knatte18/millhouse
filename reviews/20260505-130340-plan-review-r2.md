## Findings

### [BLOCKING] Fix-cycle path missing `_status.append_phase` call
**Location:** implement-cli / Card 3 (fix-cycle resume path); tests-and-skill / Card 5 (Edit 2)
**Issue:** Card 5 Edit 2 documents the CLI as atomically calling `_status.append_phase` for `fixing-{batch_name}-r{N}`, but Card 3's fix-cycle step-by-step contains no such call. The `_timestamp` module is also absent from Card 3's `Reads:`. The implementer following Card 3 will produce a CLI that silently omits the timeline entry; the Builder's phase-state invariants break silently.
**Fix:** Insert a step between the three `set_batch_field` calls and the git-add in Card 3's fix-cycle path: `_status.append_phase(status_path, f"fixing-{batch_name}-r{args.round}", _timestamp.now_utc_iso())`. Add `plugins/mill/scripts/_timestamp.py` (or equivalent) to Card 3's `Reads:`.

### [BLOCKING] Fix-cycle commit omits the review file
**Location:** implement-cli / Card 3 (fix-cycle path, step 4); tests-and-skill / Card 5 (Edit 2)
**Issue:** Card 5 Edit 2 states the CLI commits "status.md plus the review file." Card 3 step 4 only issues `git add status.md`. The review file already exists on disk (written by `millpy-review-code.py`) and must be committed on the task branch. Omitting it breaks the audit trail and violates the "all working state committed" contract; the file is silently untracked until an unrelated commit picks it up.
**Fix:** In Card 3 fix-cycle step 4, change the git-add to `git add status.md <review_file_relative_or_abs>`. Add a corresponding assertion in Card 4 Test 4 that the git-add call included the review file path alongside `status.md`.

### [NIT] Updated SKILL.md silent on exit-code-1-with-JSON behavior
**Location:** tests-and-skill / Card 5 (Edit 2 replacement text)
**Issue:** `LLMError` inside `millpy-implement.py` produces exit code 1 AND a `{"status":"stuck","stuck_type":"transient",...}` line on stdout (Card 3). Edit 2's replacement text says only "Parse the JSON report the same way as step 2." A Builder that treats exit code 1 as "no JSON, subprocess failure" will silently drop the stuck report and not enter the escalation path.
**Fix:** Extend the replacement text: "The CLI exits 0 when the implementer produces output — parse stdout JSON regardless. On exit code 1 (LLM-layer failure) stdout still carries a `{status: stuck, stuck_type: transient}` JSON line; parse it the same way and escalate."

### [NIT] `load_config` ReviewError not caught in Card 3
**Location:** implement-cli / Card 3 (common setup step 3)
**Issue:** `_review_common.load_config` raises `ReviewError` when `wiki_path/config.yaml` is absent. Card 3 does not catch this; the result is an unhandled traceback with no exit code 1, confusing the Builder's error-detection heuristic.
**Fix:** Wrap the `load_config` call in `try/except ReviewError as e: print(str(e), file=sys.stderr); return 1`, consistent with how `ActiveError` is handled two steps later.
