## Findings

### [BLOCKING] "0.6" Trigger check leaves PYTHONPATH unspecified for its own condition evaluation
**Location:** `plugins/mill/skills/mill-go/SKILL.md:428-441` (Trigger check, conditions 2 and 4)
**Issue:** The Invoke paragraph (SKILL.md:448-461) explicitly mandates worktree-form `PYTHONPATH="<git_root>/plugins/mill/scripts"` for the `--stage baseline` call and explains why the cache is "provably stale" for this purpose. The Trigger check immediately above it — which calls `_paths.is_self_hosting_task(git_root)` (condition 2) and `_plan_dag.extract_batch_index` / `_read_batch_frontmatter` / `parse_verify_field` (condition 4) — never states which copy (cache vs. worktree) to import these from. Every other python one-liner in this SKILL.md (wiki health-check, done-gate preflight, per-batch cleanup block) defaults to cache-form `PYTHONPATH="${CLAUDE_PLUGIN_ROOT}/scripts"`, so a Builder following the file's prevailing convention will most plausibly evaluate the gate against the frozen cache. That makes the trigger's own gating decision (esp. condition 4's `parse_verify_field` resolution) potentially inconsistent with what the worktree's own `millpy-implement.py --stage baseline` actually does once invoked — exactly the cache/worktree divergence this whole mechanism exists to avoid, just one step earlier in the same block.
**Fix:** State explicitly in the Trigger check paragraph that conditions 2 and 4 must also import `_paths`/`_plan_dag`/`_status` via the same worktree-form `PYTHONPATH="<git_root>/plugins/mill/scripts"` used by Invoke, not the cache form.

### [NIT] `is_self_hosting_task` omitted from `_paths.py`'s `__all__` and module-docstring "Public API" index
**Location:** `plugins/mill/scripts/_paths.py:110-131` (`__all__`), `:9-99` (module docstring "Public API:" list)
**Issue:** Every other public function in the file is listed in both the module docstring's "Public API" index and `__all__` (e.g. `sanitize_filename_component` — the function this card's requirements name as the docstring template — appears in both). `is_self_hosting_task` was added with its own well-formed docstring but appears in neither list, breaking that established one-to-one convention.
**Fix:** Add `is_self_hosting_task` to `__all__` and a matching entry to the module docstring's "Public API" section.

## Verdict

REQUEST_CHANGES
Trigger-check PYTHONPATH ambiguity risks evaluating the self-hosting gate against stale cache code, undermining the mechanism's own premise.
