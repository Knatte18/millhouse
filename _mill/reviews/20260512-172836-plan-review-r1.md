## Findings

### [BLOCKING] Broken Windows junction bypasses idempotency guard in Card 5

**Location:** Batch 2 / Card 5
**Issue:** The outer existence check `link_path.exists() or link_path.is_symlink()` silently fails to detect broken NTFS junctions on Windows. When a junction's target is deleted, `Path.exists()` returns False (it follows the junction and finds nothing) and `Path.is_symlink()` returns False (NTFS directory junctions are not Python symlinks). The if-block is skipped entirely, so `_junction.create()` is called with the broken reparse-point entry still in the filesystem; `mklink /J` then fails with "file already exists." The plan's prose explicitly promises this case is handled ("the drift branch fires"), but the code it prescribes does not reach the drift branch.
**Fix:** Replace `link_path.exists() or link_path.is_symlink()` with `os.path.lexists(str(link_path))` (matching `_junction.remove()`'s own guard). Add `import os` to `_setup.py`. `_is_junction_or_symlink` (added in Card 4) correctly detects broken junctions via the reparse-point bit when called from `points_to`, but it is never reached under the current outer check.

### [NIT] Card 8 describes wrong test-status.py counter pattern

**Issue:** Requirements say "all three tests count toward the file's existing `passed += 1` counters and surface failures via the existing `failed += 1` + `traceback.print_exc()` pattern," but `test-status.py` has no such counters — it uses a single top-level `try: ... except AssertionError` block. These counters exist in `test-setup-hub-links.py`, not `test-status.py`.
**Fix:** Implementer should add the three new test blocks inside the existing top-level `try:` block in `main()`, following the inline assertion + `print("PASS: ...")` pattern of the surrounding Tests 1–3.
