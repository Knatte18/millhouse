## Findings

### [BLOCKING:design] Holistic finalize replays one joined chain under a single per-command timeout
**Location:** Overview "Decision: one runner module, one seam" and the timeout rationale; batch 4 / Card 8 (`millpy-fix.py` label `fix:<scope>`); batch 6 / Card 12 ("replays every batch's verify sequentially")
**Issue:** `millpy-fix.py`'s `_resolve_holistic_verify` joins every batch's verify into one shell string (`" && ".join(f"({command})" ...)`) that finalize passes as `verify_cmd` to `_run_verify_gate`, so `pipeline.verify_timeout_minutes` (default 20, sized for one 2-4 minute suite) bounds the whole chain, a plan with several slow batches can false-time-out, and the `## Verify log` row carries one truncated joined `cmd`.
The discussion's rationale that a per-command bound is "independent of how many commands a gate chains" does not hold for this site, and neither the plan nor Card 8 states any disposition for it.
**Fix:** State in Card 8 (and the overview decision) how the holistic joined replay is bounded: a per-batch run through the runner, a budget scaled by the number of joined batches, or an explicit documented limitation.

### [NIT:design] Default fake's AssertionError is swallowed by the gate
**Location:** Batch 3 / Card 6, test bullet on the `main()`-level `_fake_run_verify`
**Issue:** `_run_verify_gate` wraps its body in `except Exception` (returns `verify gate raised: ...`), so the fake's `AssertionError` for an unexpected command becomes a stuck/verify result instead of failing loudly, as the card claims.
**Fix:** Have the fake also record unexpected commands and assert the list is empty at the end of `main()`.

### [NIT:consistency] Merge-in prepare envelopes omit `verify_runs`
**Location:** Batch 5 / Card 10 (last Requirements bullet on envelopes)
**Issue:** The card says every envelope printed after a verify run carries `verify_runs`, then leaves `emit_prepare` / `emit_prepare_no_dispatch` envelopes unchanged, so a prepare-stage verify that passes or leads to dispatch writes a Verify log row but reports no timings; the discussion lists "the merge-in subagent's envelope" without that exception.
**Fix:** Either state the exception as intentional in the card or attach `verify_runs` to those two envelopes.

### [NIT:consistency] mill-plan SKILL points at the note Card 12 removes
**Location:** Batch 6 / Card 12 vs `plugins/mill/skills/mill-plan/SKILL.md` ("This mirrors the finalize-stage timeout note in mill-go-base/SKILL.md")
**Issue:** Card 12 deletes that finalize-stage timeout paragraph, leaving the mill-plan reference dangling; the file is not in `All Files Touched`.
**Fix:** Reword or drop the mill-plan sentence in the same batch, or record why the dangling reference is accepted.

## Verdict

REQUEST_CHANGES
The holistic joined-chain replay has no stated timeout disposition, so the 20-minute per-command bound can false-fail multi-batch plans.
