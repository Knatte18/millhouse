## Findings

### [BLOCKING] Card 6: `write_commit_push` call is wrong on three counts
**Location:** Batch 2 / Card 6, Change B  
**Issue:** The inline script passes `{"agents.yaml": new_text}` as `relative_paths` (actual type: `list[str]`), uses the nonexistent keyword `msg=` (actual param: positional `commit_msg`), and never writes `new_text` to disk before staging — git add would receive a dict, crashing immediately.  
**Fix:** Write `(wiki_path / "agents.yaml").write_text(new_text, encoding="utf-8")` first; then call `_wiki.write_commit_push(wiki_path, ["agents.yaml"], "refactor(agents.yaml): ...", slug="config-env-interpolation")`.

### [NIT] Cards 2 and 5: new tests not added to `main()` tests list
**Location:** Batch 1 / Card 2; Batch 2 / Card 5  
**Issue:** Both cards specify new test functions but omit the step of adding them to the `tests = [...]` list in `main()`. Tests not registered there are silently skipped by the verify command, producing a false green.  
**Fix:** Add an explicit requirement line: "Append each new test function to the `tests` list in `main()`."

### [NIT] Card 5 test 9 does not exercise post-merge validation
**Location:** Batch 2 / Card 5, `test_required_field_missing_after_merge_raises`  
**Issue:** The fixture YAML (`a: {type: single, model: foo}`) has no `extends:` field, so `_resolve_extends` is a no-op; the test documents plain single-entry validation, not the post-extends path the name implies.  
**Fix:** Use `base: {type: single, model: foo}` (no provider) plus `child: {extends: base}` — missing provider only surfaces after merge, exercising the intended path.
