### [NIT] Test 11 uses U+00A0 but production may emit U+FFFD
**Location:** Batch 2 / Card 5, Test 11 snapshot
**Issue:** The shared decision endorses `[1:].lstrip()` to strip non-ASCII whitespace after `●`. Python's `lstrip()` strips U+00A0 (the test fixture) but NOT U+FFFD (the `errors="replace"` replacement for invalid UTF-8 bytes that the doc describes for the status-bar case). If the bullet-line space is the same invalid-UTF-8 bytes, `lstrip()` silently fails and the unit test would still pass.
**Fix:** The integration test (batch 3) will surface any live failure; consider noting this risk in the test comment, or add a second assertion variant using `"\ufffd"`.
