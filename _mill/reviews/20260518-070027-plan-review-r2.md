## Findings

### [BLOCKING] Card 9 Test C: CLAUDE_PLUGIN_ROOT not saved/restored
**Location:** Batch 4 / Card 9, Test C
**Issue:** The plan instructs `os.environ.pop("CLAUDE_PLUGIN_ROOT", None)` in `finally` without first saving the original value. In every mill environment `CLAUDE_PLUGIN_ROOT` is set by mill-setup; the pop permanently removes it. Subsequent tests that call `resolve_plugin_template_path` without patching will behave differently, and in a cache-only environment (no source checkout) this could accidentally flip the pre-existing failure in `test-review-common.py` from FAIL to PASS, corrupting the "exactly 1 failure" invariant.
**Fix:** Save the original before setting: `saved = os.environ.get("CLAUDE_PLUGIN_ROOT")`; in `finally`: `if saved is not None: os.environ["CLAUDE_PLUGIN_ROOT"] = saved` else `os.environ.pop(...)`. Matches the save/restore pattern already used in `test_interp_env_value_when_var_set`.

### [NIT] Batch 4 verify exits non-zero by design
**Location:** Batch 4, `00-overview.md` verify
**Issue:** `verify: "... && python plugins/mill/unit_tests/test-review-common.py"` exits 1 because the pre-existing failure returns exit code 1. mill-go interprets any non-zero verify exit as a stuck batch; the implementer must manually distinguish the known failure from new ones.
**Fix:** Either drop `test-review-common.py` from the batch-level verify (it is already exercised in Card 12's manual check) or document that the implementer must inspect output rather than rely on exit code.

### [NIT] Card 7 error message contains literal `None`
**Location:** Batch 3 / Card 7
**Issue:** When `wiki_root is None`, `wiki_cfg = None`, and the raised message reads `"no config source found: searched {mill_cfg}, None, and {plugin_tmpl}"`. The word `None` is unhelpful to an operator.
**Fix:** Use `wiki_cfg if wiki_cfg is not None else "<wiki unavailable>"` in the f-string, or conditionally omit the wiki clause when `wiki_root` is None.
