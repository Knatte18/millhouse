## Findings

### [BLOCKING] test_claim_in_wiki: TinyDB never seeded
**Location:** `plugins/mill/unit_tests/test-spawn-core.py:258` (`test_claim_in_wiki`)
**Issue:** `_make_wiki(tmp, _HOME_MD_UNMARKED_ONLY)` writes Home.md to disk but leaves `tasks.json` empty. When `claim_in_wiki(wiki, "task-one")` calls `wiki.set_phase(wiki, "task-one", "active")`, the daemon's `Store.set_phase` resolves the slug to `doc_id=None` and silently no-ops; `_render_and_commit_all` still fires and overwrites Home.md with the empty-TinyDB rendering (no tasks). The test then fails immediately: `"[active]" not in home_text`.
**Fix:** Before `claim_in_wiki(wiki, "task-one")`, call `wiki.upsert_task(wiki, "task-one", title="Task one")` and `wiki.upsert_task(wiki, "task-two", title="Task two")` to seed TinyDB, matching V3's daemon-centric model.

### [BLOCKING] test-spawn-core.py: V2 commit-message format in assertions
**Location:** `plugins/mill/unit_tests/test-spawn-core.py:287–294` and `:318–325`
**Issue:** `test_claim_in_wiki` asserts `"task: claim task-one" in log.stdout`; `test_multi_select_groom_then_claim_basic` asserts `"task: groom-and-claim 3->1 (merged-task; absorbed …)"`. The V3 daemon (`_server.py:_render_and_commit_all`) always commits `f"wiki: {slug_for_msg}"` — e.g. `"wiki: task-one"` and `"wiki: merged-task"` — so both assertions fail. These tests are in the batch-5 verify gate, blocking batch 6.
**Fix:** Remove the git-log commit-message assertions entirely (V3 daemon message format is an implementation detail) or update them to match `"wiki: task-one"` / `"wiki: merged-task"`.

### [BLOCKING] test-merge.py: TypeError from `wiki.set_phase()` return value
**Location:** `plugins/mill/integration_tests/test-merge.py:298–300`
**Issue:** `new_text = wiki.set_phase(wiki_path, slug, "done")` stores `None` (`set_phase` returns `None`). The next line `(wiki_path / "Home.md").write_text(new_text, encoding="utf-8")` raises `TypeError: expected str, bytes or os.PathLike object, not NoneType`. The V3 daemon renders Home.md internally; no manual write is needed.
**Fix:** Replace those three lines with `wiki.set_phase(wiki_path, slug, "done")` — one call, no assignment, no manual file write. Read Home.md afterward for the assertion directly from disk.

### [NIT] test-millpy-claim.py: residual V2 stubs in stub_map
**Location:** `plugins/mill/unit_tests/test-millpy-claim.py:111–118` (`_make_stub_map`)
**Issue:** The dict injects `"_tasks_md"` and `"_wiki"` MagicMock stubs into `sys.modules`. These modules are no longer imported by `millpy-claim.py` (V3-clean), so the stubs are harmless but are V2 references that survive the Card-13 grep (which only catches `^import _xxx`).
**Fix:** Remove `"_tasks_md": tasks_md_mod` and `"_wiki": wiki_mod` from the returned dict and delete their corresponding `MagicMock()` constructions.

## Verdict

REQUEST_CHANGES — two failing batch-5 verify-gate tests (TinyDB seeding gap + V2 commit-message assertions) and one integration-test crash must be fixed before the suite can go green.
