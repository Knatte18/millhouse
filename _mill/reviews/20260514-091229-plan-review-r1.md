## Findings

### [BLOCKING] Card 1 Context missing `_paths.py` and `_wiki.py`
**Location:** Batch 1 / Card 1
**Issue:** Requirements explicitly calls `_paths.resolve_wiki_path(git_root)` (from `_paths.py`) and `_wiki.write_commit_push` (from `_wiki.py`), but Card 1's Context field lists only `plugins/mill/scripts/_reviewers.py` — neither source file is present, so the implementer has no function signature to work from.
**Fix:** Add `plugins/mill/scripts/_paths.py` and `plugins/mill/scripts/_wiki.py` to Card 1's Context field.

### [NIT] Batch 1 verify uses `.wiki` junction path directly
**Location:** Batch 1 `verify:` field
**Issue:** `load(Path('.wiki'))` passes the junction path to `_reviewers.load()`, violating the CLAUDE.md invariant that scripts must resolve the real wiki path via `_paths.resolve_wiki_path`, never via junction.
**Fix:** Replace with `load(resolve_wiki_path(resolve_git_root()))` using the same `PYTHONPATH=plugins/mill/scripts` prefix, or use `git -C ...` to print the real wiki root first.

### [NIT] Card 4 run uses bare `python` — venv dependency undocumented
**Location:** Batch 3 / Card 4
**Issue:** The run command `python plugins/mill/integration_tests/bench-reviewers.py` relies on bare `python` having PyYAML and other mill script dependencies available; if the system Python lacks them the run silently fails at import.
**Fix:** Note that the mill venv must be active, or specify the cache venv binary (`${CLAUDE_PLUGIN_ROOT}/.venv/Scripts/python.exe`).
