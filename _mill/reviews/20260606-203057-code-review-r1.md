### [NIT] `_implementer_common._forward_output` regex misses nested JSON

**Location:** `plugins/mill/scripts/_implementer_common.py` (line `re.findall(r'\{[^{}]*"status"[^{}]*\}', output)`)
**Issue:** The flat-brace regex fails to match any status JSON that contains nested keys (e.g. `scope_violations` as a list, or an `envelope` sub-object). A nested object like `{"status":"success","scope_violations":["a"]}` is rejected because `[^{}]*` does not allow inner braces. In practice the happy path always emits flat JSON, but the inferred-success path that writes `scope_violations` directly to the parsed dict already bypasses this regex, so the risk is low.
**Fix:** Use `json.loads` on every `{`...`}` candidate (iterating balanced-brace spans), or document that the flat-only regex is intentional and callers must not embed nested objects in the top-level status line.

### [NIT] `millpy-merge-in-subagent.py` verify-fix finalize path skips `--checkpoint` guard

**Location:** `plugins/mill/scripts/millpy-merge-in-subagent.py:26591-26627`
**Issue:** When `--stage finalize` and `--mode verify-fix`, the code runs the post-fix verify and returns success/stuck correctly -- but `--checkpoint` is not required for `finalize` even though `full` mode requires it. The guard at line 26692 (`if args.checkpoint is None: ... return 1`) only fires for `full` mode via `_run_verify_fix`. The `finalize` branch exits before reaching `_run_verify_fix`, so `--checkpoint` is silently ignored. This is consistent with how `finalize` works in practice (no diff needed), but the argparse help text implies it is always required for `verify-fix`.
**Fix:** Add a comment that `--checkpoint` is only consumed by `_run_verify_fix` (full mode) and update the argparse `help=` to note it is not used in finalize mode; or move the guard to argparse with `required=False` and an explicit note.
