## Findings

### [BLOCKING] Card 4 puts merged_body in wrong V3 field
**Location:** batch 2 / card 4 (`multi_select_groom_then_claim` rewrite)
**Issue:** The example upsert dict uses `"body": merged_body`, but `merged_body` is `body_for_home` from `prompt_merged_entry` — i.e. the text shown in Home.md (V3 `brief`). The proposal content (V2 `proposal_body`) is what should go in V3 `body` (since `Store.list_tasks_brief` derives `has_proposal` from `bool(body)`). As written, has_proposal=False tasks would silently flip to has_proposal=True, and proposal_body would be discarded entirely.
**Fix:** Use `"brief": merged_body` in the upsert dict; when `has_proposal and proposal_body is not None`, also set `"body": proposal_body`. Drop the "write `proposal-<slug>.md` file" step (V3 daemon owns rendering). Add a grep guard: `grep -n '"body": merged_body' _spawn_core.py` must return zero.

### [NIT] Card 4 doesn't enumerate `_task_to_dict` call-site deletion
**Location:** batch 2 / card 4
**Issue:** The card deletes the `_task_to_dict` function (lines 257-268) but never instructs deletion of its 4+ call sites (`discover_active_worktrees:155`, `pick_task_single:295`, `pick_task_single_or_multi:405`, `multi_select_groom_then_claim:534`). Python will raise NameError at runtime; the existing greps don't catch it.
**Fix:** Add an explicit step: "Delete every `_task_to_dict(...)` call after the function definition is removed — `wiki.list_tasks_brief` already returns dicts." Add `grep -n '_task_to_dict' _spawn_core.py` to the zero-match guards.

### [NIT] Card 8 references wrong helper for wiki fixtures
**Location:** batch 5 / card 8 (test-fold.py rewrite)
**Issue:** Card directs the implementer to "use the existing `_test_helpers._make_task_worktree` pattern" for wiki fixtures, but `_make_task_worktree` builds a git worktree fixture, not a wiki-with-bare-origin fixture. test-fold.py already has `_setup_tempfile_wiki` which does exactly the bare-origin setup needed for daemon-mediated `upsert_task`.
**Fix:** Reference `_setup_tempfile_wiki` (line 47 in test-fold.py) as the canonical pattern; note that it already handles the bare-clone origin so the card 11 origin fix is not needed here.

### [NIT] Card 9 doesn't name `[s]` fast-path tests for deletion
**Location:** batch 5 / card 9
**Issue:** Card says "any test whose body iterates over the parsed fixture, picks the `s`-phase task as a fast-path... DELETE the test function entirely" but doesn't enumerate them at plan time. The concrete victims are `test_pick_task_single_fast_path_s` and `test_pick_task_single_or_multi_fast_path_s` (visible in test-spawn-core.py main runner list).
**Fix:** Name the two functions explicitly under a "Tests to delete:" sub-bullet so the implementer has a deterministic list rather than a judgment call.

## Verdict

REQUEST_CHANGES — the brief/body mapping in card 4 is a real data-shape bug; other findings are NITs.
