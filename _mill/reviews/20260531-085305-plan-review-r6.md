## Findings

### [NIT] compute_layers effective_deps too narrow
**Location:** Batch 3 / Card 12
**Issue:** `effective_deps` filters only `"__done__"` buckets, not `"__deferred__"` or `"Z"` (isolated). If a task somehow depends on an isolated/deferred task (e.g., direct DB insert bypassing `_validate_write`), `compute_layers` attempts `1 + max(level_of_deps)` with a dep whose topo level doesn't exist, risking KeyError or wrong level.
**Fix:** Expand filter: `d in task_map AND computed_bucket[d] not in ("__done__", "__deferred__", "Z")`. In valid store data this can't occur (write validation blocks it), so no plan test is affected, but defensive filtering prevents silent wrong output on corrupted data.

### [NIT] Test 16 carries stale group schema
**Location:** Batch 4 / Card 15 (existing test-wiki-protocol.py test 16)
**Issue:** Test 16 constructs a hardcoded response dict containing `"group": None`; the test only checks `FIELD_OK` and list length so it passes, but the mock dict will silently misrepresent the post-migration API to future readers.
**Fix:** Update the inline dict to use `"depends_on": [], "isolated": False, "deferred": False` instead of `"group": None` when updating the file in Batch 4.

APPROVE
Two minor NITs; no blocking issues found across all five batches.
