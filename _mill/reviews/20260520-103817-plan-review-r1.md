## Findings

### [BLOCKING] Batch 3 verify breaks existing test-paths.py mock tests
**Location:** Batch 3 / Cards 4–6
**Issue:** `test-paths.py` has three mock-based tests for `resolve_main_worktree_root` and several wiki-guard tests for `resolve_git_root` that all patch `_subprocess_util.run`. After migration to pygit2, those patches don't intercept the new `_pygit2_util.discover_workdir` / `_pygit2_util.resolve_common_dir_parent` calls. The `resolve_main_worktree_root` tests will get `SystemExit` (non-repo temp dir passed to pygit2); the wiki-guard tests will fail because `discover_workdir(None)` returns the actual millhouse repo root, not the mocked `/wiki` value. The batch verify `test-paths.py` will produce failures.
**Fix:** Add a card in Batch 3 that rewrites the `resolve_main_worktree_root` tests to use real git repos (following the same pattern as `_make_active_marker`) and updates the `resolve_git_root` wiki-guard tests to either use real repos with a `wiki`-named root dir or mock `_pygit2_util.discover_workdir` instead of `_subprocess_util.run`.

### [NIT] list_worktrees gitdir path stripping fragile on Windows
**Location:** Batch 1 / Card 2, `list_worktrees` linked-worktree section
**Issue:** The plan strips the `"/.git"` suffix from the `gitdir` file content as a string operation, then calls `.resolve()` relative to CWD. On Windows the content may use backslashes (`\`), and relative `gitdir` paths would resolve against CWD rather than the containing `wt_dir`.
**Fix:** Use `(wt_dir / Path(content.strip())).resolve().parent` to handle both separators and relative paths correctly.

### [NIT] Rename entries in status_porcelain deviate silently from porcelain v1
**Location:** Batch 1 / Card 2, `status_porcelain`; Shared Decision "porcelain string compatibility"
**Issue:** `repo.status()` returns only the new path for index renames (bit 8 → `"R"`), so the output is `"R  newpath"` instead of the subprocess porcelain v1 `"R  oldpath -> newpath"`. The `_filter_porcelain` rename-arrow handling in `_review_common.py` becomes dead code, and the snapshot format deviates from what was previously written to disk — though within-session comparisons remain self-consistent.
**Fix:** Document the format difference in the `status_porcelain` docstring and note that callers treating rename lines as opaque set-members (line-set arithmetic) are unaffected.

## Verdict

REQUEST_CHANGES — one blocking test-coverage gap prevents Batch 3's verify from passing.
