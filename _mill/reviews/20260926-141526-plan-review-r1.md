## Findings

### [BLOCKING:design] `halt()`'s `resume=[]` is a mutable default argument
**Location:** 01-merge-core-entry.md, Card 1 (`Stop`/`halt` definitions).
**Issue:** The spec writes `halt(reason, *, resume=[], data=None, step=None) -> Stop`. A bare `[]` as a Python function default is evaluated once at def-time and shared across every call that omits `resume`; unlike the `Ctx` dataclass's list fields (where Python itself forbids `= []` and forces `field(default_factory=list)`), a plain function signature accepts this silently, so the hazard survives into the implementation as written.
**Fix:** Make `resume` a required keyword-only argument (no default), matching `callback()`'s own signature — every call site in the plan already passes `resume=[]` or `resume=None` explicitly, so nothing depends on a default existing.

### [BLOCKING:scope] No test exercises the new script against real git
**Location:** 05-cross-references.md, Card 10 / Batch Tests; also 03-merge-cli.md Card 7.
**Issue:** Every `test-merge.py`/`test-millpy-merge.py` case runs against `FakeOps` (no real subprocess). The one real-git suite, `plugins/mill/integration_tests/test-merge.py`, independently re-implements the old skill's git sequences by hand and never calls `_merge.run_merge` or `millpy-merge.py`; Card 10 only retargets its comments. After this plan lands, nothing exercises the actual new entrypoint against real git plumbing (argv shapes, `-C` usage, real lock files, real push/rollback).
**Fix:** Add a card (batch 5 or a new batch) that invokes `millpy-merge.py` end-to-end against the existing `_setup_trio` fixture and asserts on its JSON result, or repoint the existing integration test's assertions at `run_merge`'s actual output.

### [NIT:consistency] Card 9 undercounts the Liveness-check references it must retarget
**Location:** 05-cross-references.md, Card 9, `mill-merge-in/SKILL.md` bullet.
**Issue:** The card describes "the Liveness check (#817) paragraph's two references to `mill-merge/SKILL.md` Entry Step 4," but that paragraph (current lines 25, 26, 28) contains three: "same call `mill-merge/SKILL.md` Entry Step 4 makes," "a deliberately *broader* exemption than `mill-merge/SKILL.md` Entry Step 4's own precedent," and "documented in `mill-merge/SKILL.md` Entry Step 4's ... paragraph."
**Fix:** Say "three references" (or "every reference in this paragraph") so an implementer doesn't stop after two. The card's own `grep` gate will catch the miss and force a second pass either way, so this is low-risk but worth tightening.
