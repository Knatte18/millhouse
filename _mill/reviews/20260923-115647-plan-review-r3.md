### [BLOCKING:scope] Card 5's "add a second batch" recipe doesn't fit already-two-batch fixtures
**Location:** batch 1, card 5. **Issue:** `test_check_context_completeness_symbol_cache_invoked_once_per_key` (test-plan-validate.py:3976) and `test_check_context_completeness_symbol_qualifier_cache_correctness_different_qualifiers` (line 5224) each already use two TESTED batches (alpha+beta), both requiring their declaring file(s) absent from their own refs; neither fixture cites its declaring file anywhere, so post-card-4 narrowing both lose their symbol match (0 errors instead of 2) unless a THIRD, citing-only batch is added — but card 5's literal recipe only describes appending "a second batch entry," and its own claim that "the mechanical fixture-edit rule is identical across all of them" is false for these two. **Fix:** call out these two tests explicitly and specify a third citing-only batch/card for each, distinct from the generic two-batch recipe.

### [BLOCKING:scope] Card 3's #1116 regression test is invisible to card 5's migration grep and will break
**Location:** batch 1, card 3 (new test) vs. card 5. **Issue:** `test_check_context_completeness_dirty_literal_enumeration_issue_1116` resolves `SteadyStateHydraulicSolver` through the symbol branch against a fixture `.cs` file that is, per card 3's own spec, "absent from the card's own refs" and not cited by any other card in that fixture plan — but card 5's audit is `Grep ^def test_check_context_completeness_symbol_`, which does not match this test's name (`..._dirty_literal_enumeration_issue_1116`). After cards 4/5 land, the fixture file is absent from `cited_files_map`, `_resolve_symbol_files` returns `[]`, and the test's "assert exactly one context-completeness error" fails — the batch's own verify: (full test-plan-validate.py run) would go red. **Fix:** either widen card 5's grep to catch every test resolving a symbol (not just the `_symbol_`-prefixed ones) or have card 3 itself cite the `.cs` fixture from a second card's Context: up front.

### [BLOCKING:design] Card 6's line-join elides quoted material, creating a new cross-gap backtick-pairing risk
**Location:** batch 1, card 6. **Issue:** `joined_text` is built by concatenating only non-quoted `included_lines` with `"\n"`, so two originally distant included lines (separated by an entire fenced block that gets fully elided) become directly textually adjacent. An unpaired/odd-count backtick on an included line immediately before a fence can now spuriously pair with a backtick on a much later included line, corrupting the span in between — the same "cross-line corruption" class this card fixes for ordinary line wraps, reintroduced across elided fence gaps. No test in card 6 (including the two new ones) covers a backtick left dangling immediately before a fenced/blockquoted region. **Fix:** insert an unpaired placeholder/boundary character in place of each elided quoted line (rather than pure omission) so a dangling backtick can never bridge across it, or add a regression test proving this scenario is safe and document the risk if intentionally accepted.
