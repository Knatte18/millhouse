## Findings

### [NIT] Stderr error message may be non-ASCII
**Location:** `plugins/codeguide/scripts/nb_digest.py:95`
**Issue:** `print(f"nb_digest: {e}", file=sys.stderr)` includes the raw exception message; if a path contains non-ASCII chars the OSError repr can be non-ASCII, crashing an unreonfigured cp1252 stderr — deviates from the plan's "ASCII-only warning to stderr" requirement.
**Fix:** Use `errors='replace'` on stderr too (`sys.stderr.reconfigure(errors="replace")`), or truncate the message to ascii: `str(e).encode('ascii', errors='replace').decode('ascii')`.

### [NIT] Test 1 stdout-stripping assertion is tautologically True
**Location:** `plugins/codeguide/unit_tests/test-nb-digest.py:47`
**Issue:** `assert "hello" not in digest or "print('hello')" in digest` is always True because `"print('hello')"` contains the substring `"hello"`, so the second disjunct is satisfied whenever the first fails.
**Fix:** Assert the absence of the stream output text directly: `assert "[1 output" not in digest.split("output(s)")[0] or ...` — or just drop it and rely on the base64 sentinel check, which correctly covers output stripping.

### [NIT] Test 3 truncation assertion is weak
**Location:** `plugins/codeguide/unit_tests/test-nb-digest.py:74`
**Issue:** `assert "line_50 = 50" not in digest or "line_100" not in digest` only requires one of the two clauses; in practice `line_50` IS in the head (clause False) and `line_100` is omitted (clause True), so only the second clause carries the test.
**Fix:** Assert a specific middle line is absent: `assert "line_100 = 100" not in digest` — direct, unambiguous, and covers the intent without relying on a disjunction.

## Verdict

APPROVE
Three NITs; no blocking issues — implementation is correct and plan-aligned throughout.
