## Findings

### [BLOCKING] Card 5 — MILL_PYTHON override points to non-existent worktree venv
**Location:** Batch 3 / Card 5
**Issue:** The override unconditionally sets `MILL_PYTHON="${WORKTREE_PLUGIN_ROOT}/.venv/Scripts/python.exe"`, but `.venv` is gitignored and absent in every fresh task worktree; every subsequent `$MILL_PYTHON` call fails with "file not found", breaking mill-go for all millhouse tasks.
**Fix:** Add `&& [ -f "${WORKTREE_PLUGIN_ROOT}/.venv/Scripts/python.exe" ]` to the guard and log a skip message when the venv is absent — `echo "[mill-go] SKIP: self-modifying repo but worktree venv absent -- using cache. Run 'uv sync --project ${WORKTREE_PLUGIN_ROOT}' to enable."` — so the cache path is used until the operator sets up the worktree venv explicitly.

### [NIT] Card 3 — Two equally-valid implementations without mandating one
**Location:** Batch 2 / Card 3
**Issue:** Requirements offer blockquote markers OR `~~~markdown` tilde fence as "either approach is acceptable", leaving the implementer free to choose either, which makes the resulting template harder to review consistently.
**Fix:** Mandate one approach (tilde fence `~~~markdown` is unambiguous for nested backtick blocks); mention the blockquote alternative only as a lesser option, not co-equal.

### [NIT] Card 9 — "blank when the file should exist" condition is semantically wrong
**Location:** Batch 4 / Card 9
**Issue:** Blank output from `git status --short -- _mill/status.md` means the file is present and unchanged, not deleted; the stated condition would never correctly trigger a restore, conflating a clean status with absence-from-disk.
**Fix:** Remove the "or is blank when the file should exist" clause; the guard should key only on `D` in the output (deletion from working tree), which is the actual failure mode being protected against.
