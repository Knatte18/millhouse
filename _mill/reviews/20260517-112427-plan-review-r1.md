## Findings

### [BLOCKING] Batch 2 breaks all existing flow tests: empty-repo git rev-parse HEAD

**Location:** Batch 2 (wire-guard-backends) / Cards 3–5

**Issue:** `_make_plan_fixture` in `test-review-plan-flow.py` (and its counterparts in the code/discussion flow tests) creates a git repo with `git init` + `git checkout -b` but **no initial commit**. `git rev-parse HEAD` returns exit code 128 on an empty repo. `_capture_head_sha` raises `ReviewError("worktree_snapshot_guard: git rev-parse HEAD failed...")` before `yield` is reached, so every test in the flow suites fails with `FAIL testN (unexpected ReviewError): ...`. Batch 2's claim that the three flow tests "must remain green with the guard wired in" is incorrect for this reason.

**Fix:** Either (a) update `_make_plan_fixture` (and the code/discussion equivalents) to make an initial commit — add `git add -A` + `git commit -m "seed"` after the `git init` — or (b) make `_capture_head_sha` treat the no-commits case as a safe sentinel (return `""`) instead of raising, and ensure the guard then compares empty-vs-empty on HEAD SHA without raising. Option (a) is safer and matches the pattern in `_init_repo` from Batch 1's test.

### [NIT] `run-all.py` not updated; new test file may be silently excluded from global verify

**Location:** Batch 1 / Card 2; Overview `verify:`

**Issue:** `test-review-guard.py` is a new file. The overview's global `verify: python plugins/mill/unit_tests/run-all.py` will only pick it up if `run-all.py` auto-discovers test files by glob. If `run-all.py` maintains an explicit list (common pattern when ordering matters), the new test runs only via the Batch 1 `verify:` and is silently skipped in the full suite.

**Fix:** Add a step to Card 2 (or a small addendum card) to confirm that `run-all.py` uses glob discovery or to explicitly register `test-review-guard.py` in it.

### [NIT] Case E fixture missing directory-creation step

**Location:** Batch 1 / Card 2, Case E

**Issue:** Case E writes `allowed/output.md` inside the with-block to test `expected_paths` filtering. `_init_repo` seeds only `seed.txt` at the repo root; `allowed/` is never created. `Path(tmp / "allowed" / "output.md").write_text("x")` raises `FileNotFoundError` on Python unless the parent directory is created first.

**Fix:** Add `(tmp / "allowed").mkdir()` (or `parents=True`) before the `write_text` call in Case E's requirement text so the implementer does not hit a silent fixture failure.
