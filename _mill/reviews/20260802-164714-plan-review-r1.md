## Findings

### [BLOCKING] Batch 6/Card 20 never implements the single-shared-checkout Decision
**Location:** `06-baseline-stage-wiring.md`, Card 20 ("Module-wide sub-step")
**Issue:** Card 20 keeps the module-wide sub-step as "the EXISTING logic (lines 114-161) UNCHANGED," meaning it still calls `compute_baseline` (which per batch-5/Card-17 still performs its own full `_checkout_parent_branch`/`_link_dependency_dirs`/teardown cycle internally). Meanwhile the new per-batch sub-step in the same card performs an entirely separate `_checkout_parent_branch` + `_link_dependency_dirs` cycle of its own. On the common case this feature targets — a fresh task, before batch 1, with a module-wide verify configured and no per-batch baselines cached yet — both sub-steps need computing in the same invocation, so TWO transient checkouts happen, not one. This directly contradicts the overview's Shared Decision "one shared parent-branch checkout for module-wide and every per-batch verify command" (explicitly "Applies to: batches 5, 6") and discussion.md's `gap2-checkout-teardown-extraction` Decision, which states verbatim: "when both a module-wide command and per-batch commands need computing in the SAME shared checkout, does NOT call `compute_baseline` (that would re-checkout) — it calls `_checkout_parent_branch` ONCE ... then `_run_module_wide_verify_algorithm` directly." Card 20 never mentions or calls `_run_module_wide_verify_algorithm` at all, even though batch 5/Card 16 built that function for exactly this purpose. Card 20 also has the per-batch sub-step link dependency dirs "among the module-wide command (if configured) and all enumerated batches" even though the module-wide command is never actually run inside that per-batch checkout — a leftover fragment of the intended sharing that was never completed.
**Fix:** Rewrite Card 20's module-wide sub-step so that when the per-batch sub-step's shared checkout is already being (or about to be) created in the same invocation, the module-wide command is computed via the shared checkout using `_run_module_wide_verify_algorithm` directly (bypassing `compute_baseline`) instead of the unchanged lines-114-161 body; only fall back to calling `compute_baseline` standalone when no per-batch computation is needed this invocation.

### [BLOCKING] Batch 3/Card 5's serialization-branch instruction is self-contradictory Python
**Location:** `03-status-batch-baseline-field.md`, Card 5
**Issue:** The requirement says: "add a new branch before the existing `if isinstance(value, str):` check: `elif isinstance(value, list):`". An `elif` clause cannot precede (or exist without) a preceding `if` — as literally specified this produces a `SyntaxError`. The two halves of the instruction ("insert before the `if`" vs. the literal text to insert being `elif ...`) are mutually exclusive.
**Fix:** State the intended structure unambiguously, e.g. "change the existing `if isinstance(value, str):` into `if isinstance(value, list): ... elif isinstance(value, str): ...` — the list branch becomes the new leading `if`, and the existing str check becomes its `elif`," so `_serialise_batches` compiles as `if list / elif str / else raw-str()`.

## Verdict

REQUEST_CHANGES
Batch 6 fails to implement the mandated single-shared-checkout Decision; batch 3's Card 5 instruction is syntactically self-contradictory.
