## Findings

### [NIT] assertLogs scope not specified per branch
**Location:** Batch 1 / Card 1
**Issue:** Plan says "around at least one call" without specifying which branch (fresh or stale) — both emit the breadcrumb, but `assertLogs` as a context manager will suppress the log if no message is emitted, making test failures cryptic.
**Fix:** Specify that `assertLogs` should wrap the fresh-mtime call (branch a), since that's the simpler case with no `utime` backdate needed.

### [NIT] Card 2 finally block file-handle scope unspecified
**Location:** Batch 1 / Card 2
**Issue:** Plan says "computing the code once and writing it in `finally`" but doesn't say whether the `finally` reuses the open `log_f` handle or opens a new append handle — the `with open(..., "w")` context manager closes before `finally` if `subprocess.run` raises inside it.
**Fix:** Note that `finally` must use `open(log_path, "a", ...)` — append mode — since the `"w"` handle is closed when the `with` block exits on exception. Consistent with the existing exception path already using `"a"` mode.
