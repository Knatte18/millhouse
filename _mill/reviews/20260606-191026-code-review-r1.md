## Findings

### [BLOCKING] `check_bg_status` discards `"exit"` state returned by `_probe_liveness`

**Location:** `plugins/mill/scripts/_bg.py:143-150`

**Issue:** `check_bg_status` reads the log once, checks `_EXIT_CODE_RE` on that text, then calls `_probe_liveness(log_path)` which reads the log a second time. If `[mill-bg] EXIT` appears between the two reads, `_probe_liveness` returns `("exit", pid)`, but `check_bg_status` only branches on `"affirmative-alive"` and `"assumed-alive"` -- the `"exit"` state falls through to `return ("dead", pid)`, incorrectly reporting a clean exit as dead.

**Fix:** After calling `_probe_liveness`, add `if state == "exit": return ("exit", ...)` (extracting code via `_EXIT_CODE_RE` on a fresh read or using `0` as the fallback), before the `"affirmative-alive"` check. Alternatively, pass the already-read `text` into `_probe_liveness` to eliminate the double-read entirely.

### [NIT] Tab character in `test-bg-liveness.py` `if __name__ == "__main__"` block

**Location:** `plugins/mill/unit_tests/test-bg-liveness.py:1068`

**Issue:** The `unittest.main()` call is indented with a hard tab while the entire rest of the file uses spaces; Python 3 raises `TabError` (inconsistent tabs and spaces) which would prevent the file running as a script.

**Fix:** Replace the tab with 4 spaces to match the surrounding indentation style.

## Verdict

REQUEST_CHANGES
One blocking correctness gap: `check_bg_status` silently drops the `"exit"` return from `_probe_liveness` in the TOCTOU window, reporting dead instead of exit.
