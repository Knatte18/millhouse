## Findings

### [NIT] `apply_env_overrides` fragile against non-dict intermediates
**Location:** `plugins/mill/scripts/_config.py:107-127`
**Issue:** If a config key on the override path exists but is not a dict (e.g. `roles: null` or an accidental scalar), `current.setdefault(seg, {})` returns the existing non-dict value and the next iteration raises `TypeError`. Unlikely but possible with a malformed merged config.
**Fix:** Defensive type-check each intermediate; coerce or warn-and-skip when an intermediate is not a dict.

### [NIT] `_config.load_config` `source_label` not refreshed for hub-real config layer
**Location:** `plugins/mill/scripts/_config.py:178-199`
**Issue:** When stub-aware logic loads BOTH the worktree-root stub AND the hub-real config (`hub_relative_path != "."`), `source_label` is set to `"config.local.yaml"` for the stub and never refreshed for the real file. Unknown-key warnings emitted for keys originating in the real config are attributed to the stub.
**Fix:** Update `source_label` to a path-distinguishing string (e.g. `f"config.local.yaml @ {hub_subpath}"`) when the real config is merged.

### [NIT] `_review_common.load_config` duplicates `_config.load_config` logic
**Location:** `plugins/mill/scripts/_review_common.py:898-991`
**Issue:** The two `load_config` functions share ~70% of their body (template load, repo-layer resolution, both-files warnings, env overrides). Drift between the two is a future bug source; the plan's shared-helper imports from `_config` covered the small helpers but not the orchestration.
**Fix:** Extract a shared `_load_template_and_repo_layer(repo_root) -> (cfg, template_cfg, source_label)` helper in `_config.py` and call from both. Follow-up — out of scope to demand here.

### [NIT] `mill-setup` SKILL Phase 3.0b precedes Phase 3.1 but documents it inline
**Location:** `plugins/mill/skills/mill-setup/SKILL.md` Phase 3.0b
**Issue:** The "Ordering constraint" callout is correct but easy to miss when scanning. The phase numbering (3.0b before 3.1) is the actual enforcement; the prose is supplementary.
**Fix:** No code change needed; consider a comment at the top of `millpy-migrate-config.py` reinforcing why it must run before any seeding.
