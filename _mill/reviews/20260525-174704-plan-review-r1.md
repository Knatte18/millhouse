## Findings

### [NIT] test-bg-launcher.py Home.md double-bracket not fixed
**Location:** Batch 2 / Card 8
**Issue:** `_make_container_form_worktree` writes `[[{slug}]] [active]` (V2 form); Card 8 adds `init_wiki_repo` + `upsert_task` but leaves the double-bracket unchanged. The in-file assertion `if f"[[{slug}]]" not in home_body` then passes, but any future call that reads Home.md through `parse_home_md` would miss the task.
**Fix:** Also change `home_body = f"## {title}\n[[{slug}]] [active]\n\n_body_\n"` to single brackets while updating the inline assertion to match.

### [NIT] WikiServer logger name collision risk in Card 7 regression test
**Location:** Batch 1 / Card 7
**Issue:** `logging.getLogger("wiki-server")` is a global logger. If another test in the same runner process previously instantiated `WikiServer` and left a stale handler (e.g. after an aborted test), `handlers[0]` may not be the `RotatingFileHandler` just added.
**Fix:** Before the `isinstance` assertion, call `self._log.handlers` length check; alternatively use `logging.getLogger("wiki-server-%s" % id(wiki_server))` for the test instance to ensure isolation. The `handlers == []` post-`on_stop` check is already robust.

### [NIT] Batch 2 verify comment understates expected reds
**Location:** Batch 2 / "Batch Tests" section
**Issue:** The section says "`run-all.py` will still show 3 reds (test-no-direct-rmtree + 2 in test-spawn-core)" but Batch 3 has `depends-on: []` meaning it runs concurrently; the final `run-all.py` verify fires only after all three batches complete, at which point all reds should be gone. The comment creates a misleading expectation for the implementer.
**Fix:** Clarify that the "3 remaining reds" only applies during Batch 2 execution in isolation; after Batch 3 also lands the suite is fully green.
