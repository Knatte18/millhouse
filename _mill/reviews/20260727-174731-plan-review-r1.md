## Findings

### [NIT] `_is_live_phase` assumes `phase` is always a string
**Location:** Batch 2 (cleanup-live-phase-classification) / Card 2
**Issue:** `any(p.match(phase) for p in _LIVE_PHASE_PATTERNS)` raises `TypeError` when a hand-edited status.md yields a non-str `phase` (e.g. unquoted `phase: 42`); the replaced `phase in _LIVE_PHASES` set check degraded safely to `False` for the same input, so this is a new crash that would abort `build_plan` for every slug in the sweep, not just the malformed one. Low-probability (the canonical writer, `_status.append_phase`, always quotes the scalar), but reachable via manual edits.
**Fix:** Guard with `isinstance(phase, str)` (or catch `TypeError`) before the pattern loop so a malformed status.md still falls through to "unknown phase" reporting for that one slug.
