## Findings

### [BLOCKING] `except Exception` does not catch `SystemExit` from `resolve_git_root`
**Location:** Batch 1 / Card 2 (Shared Decision `psmux-flag-lookup`) + Card 4 test 11
**Issue:** `_get_via_psmux_flag()` is specified to use `except Exception`, but `_paths.resolve_git_root()` raises `SystemExit` (a `BaseException`, not an `Exception`) for "Not in a git repository" and wiki-as-cwd cases. Card 4 test 11 patches `resolve_git_root` to raise `SystemExit("test")` and asserts the function returns `False` — this test will fail as written because `SystemExit` escapes the `except Exception` clause. The Shared Decision text explicitly names "cwd outside a git worktree" as a case that must be silently handled.
**Fix:** Change Card 2 requirement 3's except clause to `except (Exception, SystemExit)` to match the stated intent; Card 4 test 11 is then correct as written.

### [NIT] Card 4 test 11 patching path is unreliable for deferred imports
**Location:** Batch 1 / Card 4, test case 11
**Issue:** The plan says to patch `_llm_claude_mod._paths.resolve_git_root`, but `_paths` is a local import inside `_get_via_psmux_flag()` — it never becomes a module-level attribute on `_llm_claude`, so `_llm_claude_mod._paths` does not exist before the first call.
**Fix:** Specify `mock.patch.object(sys.modules['_paths'], 'resolve_git_root', ...)` (after ensuring `_paths` is in `sys.modules` via a prior call or explicit import) as the canonical patching approach rather than `_llm_claude_mod._paths`.
