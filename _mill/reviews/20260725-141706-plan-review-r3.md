## Findings

### [BLOCKING] Batch 4's rebind breaks all 3 test files' existing tests
**Location:** Batch 4 (project-root-rebinding-implement-side), Cards 8/9/10/11
**Issue:** Cards 8-10 add `container_path = _paths.resolve_container_path(git_root)` + `_paths.resolve_active_hub(...)` unguarded to `millpy-implement.py`/`millpy-fix.py`/`millpy-merge-in-subagent.py`. `test-millpy-implement.py`, `test-millpy-fix.py`, `test-millpy-merge-in-subagent.py` use plain-tempdir fixtures (no `git init`) and mock only `resolve_git_root`/`resolve_hub_path`/`resolve_wiki_path`/`slug_from_branch` — none mock `resolve_container_path`/`resolve_active_hub`. `resolve_container_path` → `resolve_main_worktree_root` → `_pygit2_util.open_repo` will raise `GitOpsError` against the non-git tempdir, which `resolve_main_worktree_root` re-raises as an uncaught `SystemExit` — crashing every pre-existing test (and Card 11's own new regression test, which per its own instructions mocks only `resolve_hub_path`/`resolve_active_hub`, not `resolve_container_path`).
**Fix:** Add a `_paths.resolve_container_path` mock (returning a stable decoy/container path) to each file's shared `setUp`, or give each test fixture a real git repo, before Cards 8-11 land.

### [BLOCKING] resolve_path() (reviews_dir) still hits the daemon on every review finalize
**Location:** `_review_common.resolve_path` (used by `millpy-review-code.py`, `millpy-review-plan.py`, `millpy-review-discussion.py`)
**Issue:** All three review CLIs call `resolve_path(cfg["paths"]["reviews_dir"], slug)` at `--stage finalize` (and discussion's round-discovery) to get `reviews_dir`. `resolve_path` independently resolves its own `hub_dir`/`git_root`/`cfg` and calls `_paths.resolve_active_hub(container_path, slug, cfg=cfg, git_root=git_root)` with no `skip_slug_validation`, so `resolve_active_worktree`'s default path still calls `_marker.slug_from_branch` → the full daemon retry loop this task exists to eliminate. No card touches `resolve_path` or threads `skip_slug_validation=True` into it, so every review-finalize call (a hot, once-per-round path) keeps the ~134s stall batches 2/3 were meant to close.
**Fix:** Add a card updating `resolve_path` (or its callers) to pass `skip_slug_validation=True` through to `resolve_active_hub`.

### [BLOCKING] Card 15 assumes CLI-level test scaffolding that only exists in 1 of 3 files
**Location:** Batch 5 (project-root-rebinding-review-side), Card 15
**Issue:** Card 15 says to add a regression test "matching that file's existing mocking conventions" mocking `_paths.resolve_hub_path`/`resolve_active_hub` and invoking the rebind. `test-review-discussion-flow.py` already has exactly this (a `sys.modules`-injected `main()` harness, e.g. `test_brief_path_nested_layout`). `test-review-code-flow.py` and `test-review-plan-flow.py` have no such convention — they only call the backend `_review_code.run()`/`_review_plan.run()` directly, never `millpy-review-code.py`/`millpy-review-plan.py`'s `main()`, which is where Cards 12/13's rebind actually lives. "Matching existing conventions" is inaccurate for 2 of 3 files and understates the new scaffolding required.
**Fix:** Call out explicitly that code/plan flow files need brand-new `main()`-level harnesses (modelled on discussion's), not an extension of an existing pattern.

### [NIT] Card 13 undercounts which stages benefit from the rebind
**Location:** Batch 5, Card 13 (`millpy-review-plan.py`)
**Issue:** Card 13 says the rebind fixes "every subsequent use of `project_root` in the `prepare`-stage branch," but the insertion point is before the `if args.stage == "prepare"/elif "finalize"/else` dispatch, so `finalize`'s and `full`'s uses of `project_root` (e.g. the `run(...)`/`finalize(...)` calls) are equally corrected. Wording could mislead an implementer into thinking only `prepare` is fixed.
**Fix:** Reword to state the rebind applies uniformly across all three stage branches.

### [NIT] Shared Decision's "two early consumers" list is incomplete
**Location:** `00-overview.md`, "project_root/hub_dir rebind happens AFTER slug resolution" decision; Cards 8/9
**Issue:** The decision names only the `cfg` bootstrap and the slug-resolution call as pre-rebind consumers of the original `project_root`, but `millpy-implement.py`/`millpy-fix.py` also run `git config --global --get user.name/user.email` with `cwd=project_root` before the rebind — a third early consumer, omitted from the enumeration (harmless in practice since `--global` reads are cwd-independent, but the decision's completeness claim is inaccurate).
**Fix:** Add the git-config subprocess calls to the decision's enumerated early consumers, or note explicitly why they're exempt.
