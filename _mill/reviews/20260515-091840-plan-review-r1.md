## Findings

### [BLOCKING] Card 13 uses class-based test API in a standalone-function file
**Location:** Batch 4 / Card 13 (`test-reviewers.py`)
**Issue:** Both new tests use `self.addCleanup`, `self.assertRaises`, and `self.assertIn` — class instance methods. `test-reviewers.py` uses standalone functions throughout; `self` is undefined and will raise `NameError` at runtime. Additionally, neither new test is added to the `tests = [...]` list in the file's `main()` function, so `run-all.py` will never discover or call them — batch 4's verify passes while silently providing zero coverage for the backward-compat fallback and implementer-model validation paths.
**Fix:** Rewrite both new tests as standalone functions using `with tempfile.TemporaryDirectory()`, `try/except`, and `assert`, then append both function references to the `tests` list in `main()`.

### [NIT] `validate_role_refs` called without module prefix in Card 13 code sample
**Location:** Batch 4 / Card 13 (`test_validate_role_refs_catches_bad_implementer_model`)
**Issue:** The sample calls `validate_role_refs(cfg, registry)` directly but this name isn't imported — existing tests use `_reviewers.validate_role_refs(...)`.
**Fix:** Either add `from _reviewers import validate_role_refs` to the import block, or use `_reviewers.validate_role_refs(cfg, registry)` to match the existing file style.
