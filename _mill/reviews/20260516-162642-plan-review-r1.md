## Findings

### [BLOCKING] Existing `test-config.py` tests will fail after Card 10 signature change
**Location:** Batch 2 / Cards 10 and 14
**Issue:** Card 10 changes `load_config(wiki_path, worktree_root)` → `(repo_root, worktree_root)`. The nine existing test functions all pass a `wiki` Path as the first arg. After the change, `load_config(wiki, wt_root)` interprets `wiki` as `repo_root`, then calls `_paths.resolve_wiki_path(wiki)` for the legacy fallback, which raises `SystemExit` because `wiki.name == "wiki"` triggers the wiki-cwd guard. Card 14 only adds new tests — it never updates or removes the now-wrong old tests (including the four machine-layer tests for behaviour that was deleted). The batch 2 `verify:` command includes `test-config.py`, so all tests will fail.
**Fix:** Card 14 must also rewrite the existing load_config tests to use `(git_root, git_root)` as the signature and remove the four machine-layer tests (those features are gone after Card 10).

### [BLOCKING] `write_commit_push` after `git rm` will always fail
**Location:** Batch 3 / Card 19
**Issue:** Card 19 calls `git -C <wiki_path> rm config.yaml` (removes file from WT and stages deletion), then passes `["config.yaml"]` to `_wiki.write_commit_push`. `write_commit_push` begins with `git add -- config.yaml`, which fails with "fatal: pathspec 'config.yaml' did not match any files" (exit 128) because the file no longer exists in the working tree. The script would raise `WikiPushError` and abort before committing or pushing, leaving the wiki in a dirty state.
**Fix:** After `git rm config.yaml` inside the wiki lock, call `_subprocess_util.run(["git", "-C", str(wiki_path), "commit", "-m", "chore(migrate): remove wiki/config.yaml (moved to hub/mill-config.yaml)"])` + a separate push call directly, bypassing the `git add` step. The same fix applies to the `agents.yaml` deletion branch.

### [BLOCKING] CLAUDE.md "wiki-config.yaml mirror" bullet left stale after Batch 4
**Location:** Batch 1 / Card 7; Batch 4 / Card 22
**Issue:** Card 7 explicitly defers the "Template `wiki-config.yaml` mirrors production `wiki/config.yaml`" bullet to Batch 4. But Batch 4 / Card 22 contains only file deletions — no CLAUDE.md edit. After the plan completes, CLAUDE.md still instructs operators to mirror changes to a deleted template (`wiki-config.yaml`) pointing at a non-existent file (`wiki/config.yaml`). The convention needs to be rewritten for the new model (`mill-config.yaml` template → hub's `mill-config.yaml`).
**Fix:** Add a CLAUDE.md edit to Card 22 that replaces the stale bullet with the new mirroring convention for `mill-config.yaml`.

### [NIT] Card 6 entry count is incorrect
**Location:** Batch 1 / Card 6
**Issue:** Requirements say "all 12 entries" from `wiki/agents.yaml`. The actual file has 14 entries (g25flash, g25flash\_tool, g25pro, g25pro\_tool, g3flash\_preview, g3flash\_preview\_tool, haiku, opushigh, opusmax, opusmedium, sonnethigh, sonnetmax, sonnetmax\_tool, sonnetmedium).
**Fix:** Change "12 entries" to "14 entries" in the requirements prose. (Implementer will copy the real file, so runtime impact is nil, but the wrong count could mislead the reviewer audit.)

### [NIT] Card 18 legacy-wiki fallback test needs `resolve_wiki_path` mocking
**Location:** Batch 2 / Card 18
**Issue:** `test_legacy_wiki_fallback_when_no_plugin_template` calls `_reviewers.load(hub_dir)`, which internally calls `_paths.resolve_wiki_path(hub_dir)` for the legacy path. Without a real git repo fixture OR a monkeypatch of `_paths.resolve_wiki_path`, this will raise `SystemExit` (not-a-git-repo). The requirements only specify mocking `_resolve_plugin_template_path`.
**Fix:** Either specify monkeypatching `_paths.resolve_wiki_path` to return a controlled wiki path, or specify creating a real git fixture (matching `test-inspect.py` style) so `resolve_wiki_path` resolves correctly.
