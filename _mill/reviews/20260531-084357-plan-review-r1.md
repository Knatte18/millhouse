## Findings

### [BLOCKING] elif condition too broad — breaks existing Case 4 test
**Location:** Batch 2 / Card 4 (`_implementer_common.py`)
**Issue:** Card 4 specifies `elif start_sha is not None:` for the new no-snapshot branch, but the batch scope states the branch fires "when `start_sha` is given but `snapshot_path` is None". The broader condition also fires when `snapshot_path` is a non-None path to a non-existent file — which is exactly what existing Case 4 in `test-implementer-common.py` exercises (it passes `snapshot_path=nonexistent_path` with HEAD advanced and a clean tree). After the fix, Case 4 would receive `success/inferred=True` instead of `stuck/logic`, causing a regression.
**Fix:** Change the condition to `elif start_sha is not None and snapshot_path is None:`. Card 5 passes no `snapshot_path` (defaults to `None`), so the fix still fires for `millpy-fix.py`; Case 4 (non-None but missing snapshot) continues to fall through to the stuck sentinel unchanged. Card 6's three new tests all pass `start_sha` with no `snapshot_path`, so they remain valid under the narrowed condition.

### [NIT] Wrong function name in call-site instruction
**Location:** Batch 3 / Cards 8 and 10 (`_plan_validate.py`)
**Issue:** Card 8 says "in `validate_plan()`, add `errors.extend(_check_verify_full_suite(batch_files))`" and Card 10 also references `validate_plan(...)`. No `validate_plan` function exists; the public entry point is `run()`.
**Fix:** Replace `validate_plan()` with `run()` in both cards' requirements prose.

### [NIT] Test C dirty-file type is ambiguous — untracked files are invisible
**Location:** Batch 2 / Card 6 (`test-implementer-common.py`, Test C)
**Issue:** The spec says "write another file WITHOUT committing (dirty tree)" without specifying a tracked file. The new branch uses `git status --porcelain --untracked-files=no`, so a newly-written untracked file produces an empty status → the branch returns `success/inferred` instead of falling through to stuck, inverting the assertion.
**Fix:** State explicitly that the dirty write in Test C must modify an already-tracked file (e.g., `(project_root / "README.md").write_text("dirty", encoding="utf-8")`) so the modification appears in `--porcelain --untracked-files=no` output.
