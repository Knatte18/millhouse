## Findings

### [BLOCKING] Card 8 phase-guard tests silently exercise wrong path
**Location:** batch 5 / card 8
**Issue:** `_setup_tempfile_wiki(home_md_content)` only writes Home.md as text; V3 reads tasks from TinyDB via `wiki.list_tasks_brief`. The phase-guard tests (`test_locked_phase_active_refused`, etc.) call `mill_fold.main(...)` against a wiki with empty `tasks.json`, so `list_tasks_brief` returns `[]`, `target_task` becomes None, and SystemExit fires on the "Slug not found" branch — NOT the phase guard. The test still asserts `raised=True` and Home.md unchanged, so the bug is silent: phase guard goes untested. The "open GH issue accepted" test would actually fail loudly (rc != 0) for the same reason but is also not addressed.
**Fix:** Require card 8 to seed each test's wiki via `wiki.upsert_task(wiki_path, slug, title=..., brief=..., status=phase)` before invoking `mill_fold.main`. Add this as an explicit step in the Requirements covering ALL preserved test cases, not just the `append_to_body` rewrites. Alternative: extend `_setup_tempfile_wiki` to accept a `tasks: list[dict]` arg and call upsert_task for each, then have every test pass its tasks explicitly.

### [BLOCKING] Card 12 pytest.skip used on bare-script integration tests
**Location:** batch 6 / card 12
**Issue:** The plan's escape hatch — "Add a `pytest.skip(...)` mark to the affected test method" — does not work for these files. `test-spawn.py`, `test-spawn-units.py`, `test-merge.py`, and `test-wiki-concurrency.py` are bare Python scripts invoked directly (`python test-merge.py`); they use `assert` + `print("PASS:")` patterns, not pytest. Calling `pytest.skip()` outside a pytest collection raises `Skipped` and crashes the script.
**Fix:** Replace the `pytest.skip` instruction with a deletion-or-guard pattern appropriate for these scripts: either delete the affected helper function and its caller wholesale OR add an early `return` with a `print("SKIP: see #NNN")` line, AND remove the function from any test runner list at the bottom of the file. Update the cap-on-skips wording accordingly.

### [BLOCKING] Card 12 `wiki` local variable collision in test-merge.py
**Location:** batch 6 / card 12 (`test-merge.py` specifics)
**Issue:** `test-merge.py` uses `wiki` as the local variable for the wiki path everywhere (e.g. `_wiki.wiki_lock(wiki, ...)`, `_sidebar.regenerate(wiki)`, `_wiki.write_commit_push(wiki, ...)`). Card 12 prescribes `from wiki import _client as wiki` for files calling V3 client functions, AND tells the file to call `wiki.set_phase(wiki_path, slug, phase)` and possibly `wiki._sync.commit_push(...)`. The local would shadow the module — there is no `wiki_path` local in scope to pass instead. Card 6 explicitly handled this collision in the four reader CLIs by renaming the local; card 12 does not.
**Fix:** Add explicit instruction to rename the `wiki` local to `wiki_path` end-to-end in `test-merge.py` before adding the alias-import — same pattern card 6 used. Verify the same is not needed for `test-wiki-concurrency.py` (which uses `wiki` and `clone` locals).

### [NIT] Card 7 leaves V2 `wiki/config.yaml` reference in `_worktree.py` docstring
**Location:** batch 4 / card 7
**Issue:** The `_worktree.remove_safe` docstring includes `junctions_cfg: The ``junctions:`` block from ``wiki/config.yaml``` — V2 path. Card 7 fixes the `_wiki.read_junctions` text but not the `wiki/config.yaml` path text in the same docstring.
**Fix:** Add a sub-bullet to card 7's `_worktree.py` block: replace `wiki/config.yaml` with `mill-config.yaml` in the docstring of `_worktree.remove_safe` (and grep for any other `wiki/config\.yaml` strings in these three files).

### [NIT] Card 4's iteration-var grep regex may miss real callsites
**Location:** batch 2 / card 4 (final verification block)
**Issue:** The regex `\b(t|task|entry|picked|chosen|c|cand)\.(slug|title|...)\b` enumerates a closed set of variable names. `_spawn_core.py` also has `home_task`, `source_task`, `merged_task`, `parsed_task`, etc. While most of these are already dict-typed in current code, post-edit verification could miss any that still slip through.
**Fix:** Broaden the regex to `[a-zA-Z_][a-zA-Z0-9_]*\.(slug|title|phase|has_proposal|heading_line_no|brief|group|status)\b`, accepting a higher false-positive rate in exchange for completeness.
