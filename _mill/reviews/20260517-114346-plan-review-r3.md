### [NIT] Card 7 `captured_argv` closure scope guidance is ambiguous
**Location:** Batch 3, Card 7, step 4
**Issue:** "declare a fresh `captured_argv` list per new test" — if the implementer writes `captured_argv = []` (new variable) but reuses the existing `_fake_run` closure, `_fake_run` still extends the OLD list object because Python closures capture by name binding. Assertions on the new variable would evaluate against an always-empty list and pass vacuously regardless of what argv was built.
**Fix:** Specify "define a new `_fake_run` closure per test that closes over its own local `captured_argv`" (matching the existing `run_implementer` block exactly), OR "use `captured_argv.clear()` between tests when reusing a single `_fake_run`."

### [NIT] `_filter_porcelain` ordered-list equality susceptible to false positives
**Location:** Batch 1, Card 1 — `worktree_snapshot_guard` body (`before_filtered != after_filtered`)
**Issue:** List equality is order-sensitive. If `git status --porcelain` output order differs between two calls — possible after a git upgrade or on a filesystem where inode enumeration order varies — the guard raises `ReviewerOverstepError` even when the set of modified paths is identical.
**Fix:** Compare sets: `set(before_filtered) != set(after_filtered)`. Porcelain lines are unique per path entry; set semantics are correct and resilient to ordering variance.
