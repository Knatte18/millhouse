## Findings

### [BLOCKING] S10 and S11 missing load_buffer/paste_buffer mocks
**Location:** Batch 2, Card 5, items 3 and 4
**Issue:** S10 setup lists `_psmux.new_session`, `_psmux.set_history_limit`, `_psmux.send_keys`, `_psmux.capture_pane`, `_psmux.kill_session` — but omits `_psmux.load_buffer` and `_psmux.paste_buffer`, both called unconditionally in Step 10 before Step 11 is reached. Unmocked, they invoke real tmux and raise `PsmuxError`, which the outer handler catches and logs — putting `PsmuxError:` in stderr instead of `response-poll timeout` / `MarkerNotFoundError`. Both assertions fail. S11 inherits the same gap ("setup identical to S10").
**Fix:** Add `mock.patch("_psmux.load_buffer")` and `mock.patch("_psmux.paste_buffer")` to the `with mock.patch(...)` blocks for both S10 and S11, mirroring S4/S6/S7.

### [NIT] Card 5 time.monotonic call-count note conflicts with Card 2 implementation
**Location:** Batch 2, Card 5, `_wait_for_idle_stable` unit tests — final note
**Issue:** The note says "time.monotonic is called twice per loop iteration" but the verbatim body in Card 2 calls it only once (the timeout check); `start = time.monotonic()` is before the loop. The side_effect lists supply 4+ values for 2-iteration paths, where only 2–3 are consumed. Tests pass because unused side_effect values are harmless, but the note is misleading and could cause an implementer to add a spurious second call.
**Fix:** Change the note to: "time.monotonic is called once before the loop (for `start`) and once per loop iteration (for the timeout check)."
