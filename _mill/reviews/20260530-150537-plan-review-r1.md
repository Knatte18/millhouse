## Findings

### [BLOCKING] Attempt count contradicts sleep sequence
**Location:** Batch 1, Cards 2 and 4
**Issue:** Card 2 says "3 attempts" with backoff `[2, 4, 8]`. The standard retry pattern for 3 total attempts yields only 2 inter-attempt sleeps `[2, 4]`, not 3. Card 4 asserts `time.sleep` call args are exactly `[2, 4, 8]` — an implementer following Card 2 literally produces only 2 sleep calls and Card 4's test fails. The "~23 s worst case" is only consistent with 3 attempts if `sleep(8)` fires after the third failure before raising (non-standard); the plan never makes this explicit.
**Fix:** Either (a) restate as "4 total attempts (initial + 3 retries)" with sleeps `[2, 4, 8]`, or (b) reduce the backoff list to `[2, 4]` and update Card 4's assertion to match 3 total attempts.

### [BLOCKING] Blocking Bash one-liner will timeout for normal workloads
**Location:** Batch 3, Cards 8 and 9
**Issue:** Both cards replace the existing `cat <log-path>` polling pattern with a single blocking `"$MILL_PYTHON" -c "... _bg.wait_for_bg_terminal(log_path) ..."` call in the SKILL.md. `wait_for_bg_terminal` blocks until the worker terminates or dies. Normal implementations and reviews run 10–60+ minutes; the Bash tool's maximum configurable timeout is 600 s (10 min). The blocking call will consistently timeout on ordinary workloads, breaking the primary (non-dead-worker) execution path — not just the logout-recovery path the task targets.
**Fix:** Retain the existing `cat`-based polling loop for the "wait for exit" path; inject a `_bg.is_bg_worker_alive(log_path)` liveness check at each poll iteration and branch to the `infrastructure` stuck path when it returns `(False, pid)` and no EXIT sentinel is present. This preserves the workable incremental-poll approach while adding dead-worker detection without a blocking Bash call.

### [NIT] `_EXIT_RE` has no capture group — misleading phrasing
**Location:** Batch 2, Card 6
**Issue:** "reuse `_EXIT_RE`'s capture" is impossible — `_EXIT_RE = re.compile(r"\[mill-bg\] EXIT \d+")` has no capture group. The implementer must either silently fall back to "a new local regex" or modify `_EXIT_RE` (with attendant risk to existing tests).
**Fix:** Remove "or reuse `_EXIT_RE`'s capture"; replace with "a new local regex with a capture group, e.g. `re.compile(r'\[mill-bg\] EXIT (\d+)')`."

### [NIT] `sys.platform` patch cannot alter a module-level constant
**Location:** Batch 1, Card 4, test case (g)
**Issue:** `SPAWN_TIMEOUT = 20 if sys.platform == "win32" else 10` is evaluated once at import time. Patching `sys.platform` post-import leaves the constant unchanged. On Windows (the target platform) the constant is already 20, so the assertion passes trivially without any patch.
**Fix:** Replace with a direct assertion `assert _client.SPAWN_TIMEOUT == 20` (unconditionally valid on the target platform), or for cross-platform coverage use `importlib.reload(_client)` inside a `sys.platform` patch context.

## Verdict

REQUEST_CHANGES
Two blocking issues: attempt-count/sleep-sequence contradiction in Cards 2/4 will cause the verify test to fail; blocking Bash one-liner in Cards 8/9 will consistently timeout for normal-length operations.
