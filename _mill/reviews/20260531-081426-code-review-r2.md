## Findings

### [NIT] `wait_for_socket_reachable` can overshoot its `timeout` budget
**Location:** `plugins/mill/scripts/wiki/_client.py:100-112`
**Issue:** The inner `socket.create_connection((host, port), timeout=0.5)` blocks up to 0.5 s per iteration regardless of the remaining outer budget. If the outer deadline is nearly expired, `wait_for_socket_reachable` can overshoot it by up to 0.5 s.
**Fix:** Cap the per-attempt connect timeout to `min(0.5, max(0, deadline - time.monotonic()))` before each `create_connection` call.

### [NIT] `_dispatch` returns `None` implicitly after the retry loop
**Location:** `plugins/mill/scripts/wiki/_client.py:153-163`
**Issue:** After the `for attempt in range(4)` loop the function has no explicit `return`; Python silently returns `None`. The code path is unreachable (either a `return` or `raise WikiBusyError` exits the loop), but mypy reports the return type as `dict | None`.
**Fix:** Add `raise WikiBusyError(...)` (or an `assert False`) after the loop as an unreachable-guard so the type is clean.

### [NIT] Misleading docstring in race-guard test side-effect
**Location:** `plugins/mill/unit_tests/test-bg-liveness.py` — `TestCheckBgStatus.test_check_bg_status_race_guard_exit_appears`
**Issue:** The `read_text_side_effect` docstring says "On first call (from is_bg_worker_alive)" but `is_bg_worker_alive` is fully patched and never calls `read_text`; the first call is from `check_bg_status` itself.
**Fix:** Change the docstring to "On first call (from check_bg_status initial read), no EXIT. On re-read (race guard), EXIT present."

### [NIT] Test (q) connects to privileged port 1 for "refused" assertion
**Location:** `plugins/mill/unit_tests/test-wiki-daemon.py:~374`
**Issue:** Port 1 is reserved/privileged; on some Windows configurations or with certain firewall rules the connection may time out (up to 0.1 s budget) rather than immediately refuse, making the test marginally slow and fragile.
**Fix:** Use a high-numbered port known to be unbound (e.g. pick one above 49152 with `socket.bind(("127.0.0.1", 0))` on a second socket, then close it before the test — the OS will not reuse it instantly).
