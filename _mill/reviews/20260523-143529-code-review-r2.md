## Findings

### [BLOCKING] Task deletion not handled — phantom tasks in render output
**Location:** `plugins/mill/scripts/wiki/_store.py:33-40` (`set`) and `plugins/mill/scripts/wiki/_server.py:195-199` (step 6)
**Issue:** `set("Home.md", content)` calls `upsert_task` for each task in the parsed content but never removes tasks absent from the new content. `render(all_tasks())` then includes all TinyDB entries — including stale ones — and step 6 of `_handle_write` overwrites the disk `Home.md` written in step 4 with this phantom-inclusive rendered version. Any client write that removes a task from `Home.md` causes that task to reappear in every subsequent read.
**Fix:** Before upserting in `set("Home.md", ...)`, collect the set of slugs in `parse_home_md(content)` and delete TinyDB documents whose slugs are absent, while preserving `body`/`id` fields for tasks that remain (copy them before deletion, pass into the new insert).

### [NIT] `_last_pull` not updated when repopulation condition is false
**Location:** `plugins/mill/scripts/wiki/_server.py:171-183` (`_handle_write` step 2)
**Issue:** `self._last_pull = time.monotonic()` sits inside the `if "Home.md" in files_payload or self._store.get("Home.md") is None:` block. When that condition is false, the pull from step 1 completes successfully but the timestamp is not recorded, causing the next `_handle_read` to trigger an unnecessary extra pull.
**Fix:** Move `self._last_pull = time.monotonic()` to immediately after `pull(self._wiki_path)` in step 1 (outside the conditional).

### [NIT] Integration test does not send SIGTERM on POSIX
**Location:** `plugins/mill/integration_tests/test-wiki-daemon-tinydb.py:56-68` (`_kill_daemon`)
**Issue:** On non-Windows, `_kill_daemon` only deletes the state file; it never sends SIGTERM. The plan spec says "kill by deleting `.wiki-daemon.json` and sending SIGTERM (or on Windows, use taskkill)." The old daemon keeps running until its 3 s idle timeout elapses, making test 4 sensitive to timing.
**Fix:** Add `os.kill(pid, signal.SIGTERM)` on POSIX before deleting the state file, mirroring the Windows `taskkill /F` branch.

## Verdict

REQUEST_CHANGES
Phantom-task bug (deleted tasks reappear in rendered output) is a correctness break requiring a fix before merge.
