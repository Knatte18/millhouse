## Findings

### [BLOCKING] Wrong `_config.load_config` call in bg launcher validation
**Location:** Batch 4 / Card 8
**Issue:** Card 8 instructs `_config.load_config(wiki_path, Path(git_root))`, passing `wiki_path` as `repo_root`. `_config.load_config(repo_root, worktree_root)` looks for `mill-config.yaml` at `repo_root`; the wiki directory holds no such file, and internally calling `resolve_wiki_path(wiki_path)` raises `SystemExit` (caught and swallowed), leaving `branch_prefix` unset (""). With empty prefix, D1's "strip first `/`-delimited component" fallback fires for any slash-bearing branch name (e.g., operator on `feature/something` where `something` is a live task slug), falsely accepting the wrong terminal — the opposite of what D7 is meant to prevent.
**Fix:** Replace with `_config.load_config(Path(git_root), Path(git_root) / ".millhouse")`, matching the call pattern in `millpy-claim.py` and `millpy-spawn.py`.

### [BLOCKING] Card 9 test fixture layout incompatible with `resolve_wiki_path`
**Location:** Batch 4 / Card 9
**Issue:** `_make_task_worktree` creates `tmp/worktree` + `tmp/wiki`. `resolve_wiki_path(tmp/worktree)` resolves the main root to `tmp/worktree`, finds `tmp` is not named `"wts"`, and falls through to prefix-form: `tmp / "worktree.wiki"` — not `tmp/wiki`. The validation then passes this non-existent path to `slug_from_branch`, which (after D1) immediately calls `(wrong_wiki_path / "Home.md").read_text()` and raises `FileNotFoundError`. `FileNotFoundError` is an `OSError` subclass, caught by neither `except _marker.MarkerError` nor `except (ValueError, SystemExit)`; the launcher crashes with an unhandled traceback. Neither the "cwd appears to be a non-task worktree" string (test 1) nor the "cannot validate cwd" string (test 2) is ever printed; all three tests fail.
**Fix:** Each test fixture must produce a layout where `resolve_wiki_path` actually finds the wiki — either (a) container-form: place the worktree at `tmp/wts/worktree` with `tmp/wiki` as sibling, or (b) write `.millhouse/config.local.yaml` in the worktree with `paths: {wiki: <abs-path-to-wiki>}`. The plan must specify which form each test uses.

### [NIT] `FileNotFoundError` from `slug_from_branch` not caught in launcher
**Location:** Batch 4 / Card 8 — second `except` clause
**Issue:** After D1 moves the Home.md read before the prefix check, any path where `wiki_path` resolves but Home.md is absent (the exact condition BLOCKING 2 exposes) raises `FileNotFoundError` (an `OSError` subclass) instead of `ValueError` or `SystemExit`, propagating past both handler branches and crashing the launcher with a raw traceback in production too (e.g., wiki clone not yet restored after re-setup).
**Fix:** Widen the second catch to `except (ValueError, SystemExit, OSError)`.

## Verdict

REQUEST_CHANGES
Two blocking defects in Batch 4: `_config.load_config` is called with `wiki_path` as `repo_root` (wrong argument order; `branch_prefix` never loads), and Card 9's test fixtures use a layout that `resolve_wiki_path` cannot resolve, causing all three tests to crash with an unhandled `FileNotFoundError` rather than hitting the expected rejection paths.
