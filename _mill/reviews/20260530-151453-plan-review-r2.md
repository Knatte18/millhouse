## Findings

### [NIT] Card 8 omits ERROR-only retry poll sites in mill-go
**Location:** Batch 3 / Card 8
**Issue:** Card 8 lists six polling sites for liveness augmentation but omits the per-batch ERROR-only retry (step 4.5) and holistic ERROR-only retry (step 3.5), both of which contain the same unbounded `cat <log-path>` poll. Card 9 explicitly covers mill-start's ERROR-only retry loop, making the omission inconsistent — a worker killed during either of those mill-go retries would cause an indefinite poll with no dead-worker detection.
**Fix:** Add per-batch step 4.5 and holistic step 3.5 to the enumeration of poll sites receiving per-iteration `check_bg_status` liveness detection.

### [NIT] Card 3 — timeout value for wait_for_socket_reachable unspecified
**Location:** Batch 1 / Card 3
**Issue:** The spawn-wait refactor is told to call `wait_for_socket_reachable(state["host"], state["port"], timeout=...)` but leaves the timeout as a placeholder; the correct value (remaining deadline budget) is inferable but not stated, allowing an implementer to pass an arbitrary constant.
**Fix:** Specify `timeout = deadline - time.monotonic()` (remaining SPAWN_TIMEOUT budget from the outer loop) as the value to pass.

### [NIT] Card 4 test (g) — no platform guard on SPAWN_TIMEOUT assertion
**Location:** Batch 1 / Card 4
**Issue:** `assert _client.SPAWN_TIMEOUT == 20` will fail on non-Windows (Linux CI); the plan notes Windows-only validity but does not require a guard.
**Fix:** Wrap as `if sys.platform == "win32": assert _client.SPAWN_TIMEOUT == 20 else: assert _client.SPAWN_TIMEOUT == 10`.

### [NIT] Card 6 — missing-log early return not explicitly sequenced
**Location:** Batch 2 / Card 6
**Issue:** The flow description lists "(1) read the log; if EXIT present..." then separately notes "if log file missing, return ('dead', None)" without stating it precedes the first `read_text`; a bare `read_text` on a missing file raises `FileNotFoundError`.
**Fix:** Explicitly state the existence guard (`if not log_path.exists(): return ("dead", None)`) as the first step, matching `is_bg_worker_alive`'s own opening pattern.

## Verdict

APPROVE
Four NITs; plan is structurally sound with no blocking issues.
