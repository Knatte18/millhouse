## Findings

### [BLOCKING] prepare() breaks full-path tests via spec["model"]
**Location:** `plugins/mill/scripts/_review_discussion.py:111`, `plugins/mill/scripts/_review_code.py:315`
**Issue:** The new `prepare()` does `"model": spec["model"]` unconditionally; the `test_stub` reviewer spec (`_reviewers.resolve` returns `{"type":"single","provider":"test_stub","tooluse":False}`) has no `model` key, so `run()` -> `prepare()` raises `KeyError: 'model'`. Verified: 4/5 `test-review-discussion-flow.py` and 13/14 `test-review-code-flow.py` cases fail (17 total), violating the plan's "full is byte-for-byte unchanged" guarantee.
**Fix:** Use `spec.get("model")` in both prepare return dicts (the `full` path never consumes it; the CLI prepare stage feeds a real reviewer with a model into `model_to_tier`).

### [NIT] plan prepare() has the same latent spec["model"] hazard
**Location:** `plugins/mill/scripts/_review_plan.py:387,464`
**Issue:** `batch_spec["model"]` / `holistic_spec["model"]` would raise the same `KeyError` for `test_stub`; it is only masked because `_review_plan.run()` kept its inline implementation and does not call `prepare()` on the test path.
**Fix:** Switch to `.get("model")` for consistency and to harden the agent-mode prepare path against model-less specs.

### [NIT] review CLIs skip the via_psmux dispatch shim
**Location:** `plugins/mill/scripts/_review_common.py:1331` (`load_config`)
**Issue:** `_review_common.load_config` does not call `_apply_dispatch_shim`, so a legacy `llm.claude.psmux.via_psmux: true` hub would not migrate to `psmux` when a review CLI resolves dispatch mode (it would default to `subprocess`); only `_config.load_config` applies the shim.
**Fix:** Not exercised by this hub (card 3 replaced `via_psmux` with `dispatch:`); apply the shim in `_review_common.load_config` too if legacy configs must be honored by reviewers.

### [NIT] fix finalize start_sha/snapshot diverges from full
**Location:** `plugins/mill/scripts/millpy-fix.py:188-194`
**Issue:** `full` calls `_forward_output(..., start_sha=<post-commit HEAD>, snapshot_path=None)` but `finalize` passes `start_sha=None` plus a `.cleanliness-snapshot-fixer.txt` snapshot, so the inferred-success fallback (no-JSON output) would behave differently between modes.
**Fix:** Pass `start_sha` reconstructed as `full` does and `snapshot_path=None` for parity (only matters when the agent omits structured JSON).
