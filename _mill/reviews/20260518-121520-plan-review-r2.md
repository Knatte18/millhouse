## Findings

### [NIT] cleanup_session placement contradicts its public status
**Location:** Batch 3, Card 10
**Issue:** Card 10 places `cleanup_session` "immediately above the `# Public API` comment block" — visually in the private section — yet declares it a public API function and adds it to the module docstring's `Public API:` list.
**Fix:** Place it inside the `# Public API` section (after `run_implementer`) to match where `run_bulk` / `run_tool_use` / `run_implementer` live. Intent is clear enough for an implementer to resolve, but the stated location is contradictory.

### [NIT] Holistic session_id capture depends on unverifiable assumption
**Location:** Batch 4, Card 13
**Issue:** Card 13 instructs mill-go to "capture the `session_id` field from the parsed JSON envelope" of `millpy-implement-holistic.py` stdout, claiming the script already emits it there. `_implementer_common._forward_output` (not in the file manifest) is the actual emitter; if it does not include `session_id` in the JSON, `holistic_sid` is always empty and holistic cleanup silently becomes a no-op.
**Fix:** Verify that `_forward_output(output, project_root, session_id=session_id)` propagates `session_id` into the stdout JSON before shipping; document the dependency in Card 13's context or add it to the "All Files Touched" context list.

### [NIT] psmux resume error message references non-existent `--resume` flag
**Location:** Batch 3, Card 9
**Issue:** The error string `f"psmux-claude --resume {session_id} exited {result.returncode}: {error_detail}"` implies the wrapper was invoked with `--resume`, but `millpy-claude-sub.py` has no such flag; session continuity on the psmux path works via TUI keepalive.
**Fix:** Use `f"psmux-claude (session {session_id[:8]}…) exited {result.returncode}: {error_detail}"` to avoid operator confusion when reading stderr.

### [NIT] Batch 1 adds no direct test for the nested config read path
**Location:** Batch 1, Batch Tests section
**Issue:** Batch 1's verify relies on batch 3's tests to cover the nested `llm.claude.psmux.via_psmux` read. The rationale is reasonable, but a config mis-merge that returns the wrong nesting (e.g. config key collision between old `via_psmux: true` overlay and new nested block) would produce silent `False` with no failing unit test until batch 3.
**Fix:** Add a micro-test to batch 1 — or Card 3 — that calls `_get_via_psmux_flag()` with a patched `_config.load_config` returning `{"llm": {"claude": {"psmux": {"via_psmux": True}}}}` and asserts `True`. Two lines in the test file is sufficient.

## Verdict

APPROVE — plan is sound; NITs are non-blocking and do not affect correctness of the core keepalive mechanism.
