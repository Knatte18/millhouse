## Findings

### [NIT:design] CLI error handling misses wiki startup errors
**Location:** Batch 3 / Card 7 **Issue:** `_marker.slug_from_branch` deliberately propagates `wiki.WikiStartupError` unwrapped (`_marker._list_tasks_brief_with_retry`), which is not `SystemExit`/`OSError`/`ValueError`/`MarkerError`, so it escapes the "any other failure -> exit 1" catch and produces a traceback. **Fix:** Name `WikiStartupError` (or a broad `Exception`) in the caught set and add a test for it in Card 8.

### [NIT:design] Shell-metacharacter validation gap in name
**Location:** Batch 1 / Card 2 (`render_tasks`) **Issue:** The name is placed inside double quotes in a shell command, but validation rejects only `"`, backslash and control characters; `$` and backtick would expand. This is low risk because slugs are validated and the hub name is a config short name. **Fix:** Also reject `$` and backtick, or state that they are out of scope.

### [NIT:consistency] mill-setup Step 1 reads only the hub config file
**Location:** Batch 5 / Card 12 **Issue:** The `-c` one-liner does `yaml.safe_load` on `<cwd>/mill-config.yaml` only. It ignores the template defaults and `config.local.yaml` layers that the `millpy-session-tasks` CLI's `_load_config` applies, so setup and the CLI can render different values. **Fix:** Note the difference in the prose, or use `_config.load_config(hub_root, worktree_root)` as the CLI does.

## Verdict

APPROVE
Plan is sound and source-consistent (`load_config`, `slug_from_branch`, `run-all.py --only` all verified); only minor NITs remain.
