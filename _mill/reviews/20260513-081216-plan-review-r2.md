## Findings

### [BLOCKING] Card 3 breaks `test-worktree.py` "path exists + not a working tree" test

**Location:** Batch 2 / Card 3
**Issue:** After migration, `remove_safe`'s rmtree fallback calls `_safe_rmtree.safe_rmtree`, which immediately calls `_paths.resolve_container_path(allowed_root)` → `_subprocess_util.run(["git", "-C", ..., "rev-parse", "--git-common-dir"])`. Because `patch("_worktree._subprocess_util.run", ...)` patches the shared module object, this extra git call consumes `mock_prune` (item 1 of `side_effect=[mock_result, mock_prune]`). The subsequent `git worktree prune` call then exhausts the list and raises `StopIteration`, failing the test. The "path absent" variant is unaffected (`path.exists()` is False → `safe_rmtree` never called). Card 3's Requirements mention updating the `shutil.rmtree` patch targets but do not address this broken test.
**Fix:** In Card 3's Requirements for `test-worktree.py`, add a third mock value to the `side_effect` list in the "remove_safe exits cleanly via rmtree fallback on 'is not a working tree' (path exists)" test (e.g. `side_effect=[mock_result, mock_prune, mock_prune]`, where the new third entry has `returncode=0`/`stderr=""`), to account for the extra subprocess call introduced by `_blacklist_for`'s `_paths.resolve_container_path` call inside `safe_rmtree`.
