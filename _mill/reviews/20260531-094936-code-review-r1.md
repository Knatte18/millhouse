### [NIT] Stale docstring in `_client.list_tasks_brief`

### [NIT] `render_order` silently mutates input task dicts
**Location:** `plugins/mill/scripts/wiki/_render.py:43`
**Issue:** `for task in tasks: task["layer"] = ...` is an undocumented side-effect on the caller's objects; plan says "Returns a new sorted list" without noting mutation.
**Fix:** Either copy tasks before mutating (`task = {**task, "layer": ...}`) or document the side-effect explicitly. The current behavior works for all callers but is surprising.

### [NIT] DFS cycle-path accumulates stale nodes on backtrack
**Location:** `plugins/mill/scripts/wiki/_store.py:56–78`
**Issue:** The `path` list appends slugs during DFS descent but is never popped on backtrack; for graphs with branching before the cycle the error message includes slugs not on the actual cycle path. Tests only assert both slugs appear, so they pass.
**Fix:** Pop `path` before returning False (`path.pop()`), mirroring the `color` cleanup already present.

### [NIT] Test 16 hardcodes `"group": None` in response fixture
**Location:** `plugins/mill/unit_tests/test-wiki-protocol.py:165–175`
**Issue:** The static round-trip test still uses the old schema (`"group": None`); post-migration the server never returns `group`.
**Fix:** Update the hardcoded response to use the new schema fields; the test is data-only and the fix is cosmetic.
