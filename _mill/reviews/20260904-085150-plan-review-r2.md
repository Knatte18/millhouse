## Findings

### [NIT:consistency] Card 6's ctypes.windll mocking strategy cannot work on this Linux host
**Demoted-from:** BLOCKING
**Location:** batch 3 / Card 6 (`test-bg-liveness.py`)
**Issue:** Card 6 says to mock `_bg.ctypes.windll.kernel32.OpenProcess` etc. directly, but Card 5 mandates `import ctypes` *inside* `_win_pid_alive` (function-local, mirroring `_vscode_processes.py`), so `_bg` has no module-level `ctypes` attribute to patch — and the function's own `import ctypes` statement rebinds the local name to the real module at call time regardless of any patch on `_bg.ctypes`. Separately, `ctypes.windll` does not exist as an attribute on non-Windows CPython at all (it's `if sys.platform.startswith("win")`-guarded in `ctypes/__init__.py`), so even patching the real `ctypes.windll.kernel32.OpenProcess` path directly raises `AttributeError` before the mock is ever installed. Confirmed no existing test in `plugins/mill/unit_tests/` mocks `ctypes.windll` anywhere (`_vscode_processes.py`'s own `_probe_windows` — same ctypes-inside-function style — is tested today only by mocking the *outer* `find_open_vscode_paths` function, never by reaching into its `ctypes.windll` internals).
**Fix:** Specify a `unittest.mock.patch.dict(sys.modules, {"ctypes": <fake>, "ctypes.wintypes": <fake>})` swap (or equivalent) installed *before* `_win_pid_alive` runs, so the function's local `import ctypes` binds to the fake module — plain `patch("_bg.ctypes...")`/`patch("ctypes.windll...")` as currently written will not execute.

### [NIT:consistency] Card 9's case 72h contradicts Card 7's unconditional corroboration call
**Demoted-from:** BLOCKING
**Location:** batch 4 / Card 7 vs Card 9 (`_implementer_common.py` / `test-implementer-common.py`)
**Issue:** Card 7's literal code shows the new `else:` clause in `_run_verify_gates` calling `_corroborate_batch_failure(project_root, git_root, start_sha, verify_cmd, cwd_override)` unconditionally whenever the subset-diff mismatches — there is no `if start_sha is not None:` guard at the call site; the "return None fast" fail-safe is described as living *inside* `_corroborate_batch_failure`'s own body. Card 9's case 72h patches `_implementer_common._corroborate_batch_failure` to raise `AssertionError("should not be called")` and asserts it is *never* called when `start_sha` is omitted. As specified, the mismatch path in case 72h's reused 72b scenario would invoke the mocked function (bypassing its internal None-guard entirely, since the whole function is replaced), propagating the `AssertionError` up through `_run_verify_gates` uncaught — failing the test that this same batch's `verify:` gate runs.
**Fix:** Either add an explicit `if start_sha is not None:` guard around the `_corroborate_batch_failure` call at the `_run_verify_gates` call site (Card 7), or change case 72h to assert on the *result* (no corroboration having occurred) rather than on the mock never being invoked — pick one and make both cards agree.

### [NIT:consistency] New orphan-baseline-dir teardown loop catches a narrower exception than remove_safe can raise
**Demoted-from:** BLOCKING
**Location:** batch 2 / Card 3 (`millpy-cleanup.py`)
**Issue:** Card 3's new `apply_plan` loop wraps `_apply_orphan_baseline_dir` in `try: ... except _worktree.WorktreeLockedError as exc:`, explicitly describing this as mirroring `apply_plan`'s existing `except _worktree.WorktreeError as exc:` handling for `_apply_worktree_record`. But that existing handler catches the *broader* `WorktreeError` (of which `WorktreeLockedError` is a subclass), not just the narrower subclass. Since a `.scratch/verify-baseline-*` dir is never a registered git worktree, `remove_safe`'s initial `git worktree remove` call is likely to hit its "unrecognized git failure" branch on an unusual stderr shape, which raises plain `WorktreeError` (not `WorktreeLockedError`) — that would propagate uncaught out of the new loop, aborting the rest of `apply_plan`, exactly the failure mode this catch clause is meant to prevent ("a single stubborn lock must never abort the rest of the cleanup run").
**Fix:** Catch `_worktree.WorktreeError` (matching the sibling handler it claims to mirror), not the narrower `WorktreeLockedError`.

### [NIT:consistency] `import time` placement in Card 1 contradicts its own alphabetical-ordering rationale
**Location:** batch 1 / Card 1 (`_worktree.py`)
**Issue:** Card 1 says to add `import time` "after `import subprocess`, before `import sys`... matching the existing alphabetical stdlib-import ordering." The current block is `shutil, subprocess, sys` (already alphabetical); inserting `time` between `subprocess` and `sys` produces `shutil, subprocess, time, sys`, which is *not* alphabetical (`sys` < `time`). The stated placement contradicts the stated rationale.
**Fix:** Place `import time` after `import sys` (`shutil, subprocess, sys, time`) to actually match alphabetical order.

### [NIT:consistency] Card 2's cited mocking target for the rmtree fallback doesn't match the file's actual convention
**Location:** batch 1 / Card 2 (`test-worktree.py`)
**Issue:** Card 2 says to match the file's mocking style by patching "`_safe_rmtree.safe_rmtree` for the rmtree attempts." The file's existing WinError145 tests actually patch `_safe_rmtree.shutil.rmtree` (plus `_safe_rmtree._blacklist_for`), never `_safe_rmtree.safe_rmtree` as a whole. The card does also say to read the file's existing tests first, which should self-correct this, but the specific named target is factually wrong.
**Fix:** Correct the named patch target to `_safe_rmtree.shutil.rmtree` + `_safe_rmtree._blacklist_for`, matching the actual existing cases.
