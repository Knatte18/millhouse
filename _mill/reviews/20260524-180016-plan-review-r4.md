## Findings

### [BLOCKING] _spawn_core body conversions absent from card 26
**Location:** batch 3, card 26
**Issue:** Card 26 changes `list[_tasks_md.Task]` type hints to `list[dict]` and drops `import _tasks_md`, but does NOT instruct converting attribute access to dict-key access inside `_spawn_core.py`'s own functions. `pick_task_single`, `_prompt_numbered`, `_prompt_numbered_multi`, `pick_task_single_or_multi`, and `prompt_merged_entry` all access `t.phase`, `t.slug`, `t.title`, `t.has_proposal` in their bodies — these will raise `AttributeError` at runtime once tasks become dicts. Cards 22/25 cover consumers in `millpy-claim.py`/`millpy-spawn.py` but not the internal `_spawn_core.py` call sites.
**Fix:** Add an explicit instruction in card 26: "Convert every `t.<attr>` access in `_spawn_core.py` function bodies (pick_task_single, _prompt_numbered, _prompt_numbered_multi, pick_task_single_or_multi, prompt_merged_entry, multi_select_groom_then_claim, etc.) to `t["<attr>"]` dict-key access — grep the file end-to-end."

### [BLOCKING] Migration commit message contradicts daemon handler
**Location:** batch 1 card 5 vs batch 2 cards 13 & 14
**Issue:** Card 5 specifies `_handle_upsert_tasks_batch` calls `_render_and_commit_all(slug_for_msg="batch")` with commit message format `wiki: {slug_for_msg}` → produces `"wiki: batch"`. Card 13 step 5d claims the daemon "renders + commits once with message `wiki: migrate to V3 (TinyDB-backed)`". Card 14 asserts "the second commit message matches verbatim" against `"wiki: migrate to V3 (TinyDB-backed)"`. The card 14 integration test will fail because the daemon emits `"wiki: batch"`, not the migration-specific message. The API signature in card 6 (`upsert_tasks_batch(wiki_path, tasks)`) provides no `message` parameter.
**Fix:** Either (a) add a `message: str | None = None` parameter to `upsert_tasks_batch` in card 6, plumb it through card 5's `_handle_upsert_tasks_batch` (using payload `message` field when provided, falling back to `slug_for_msg="batch"`), and have card 13 pass `message="wiki: migrate to V3 (TinyDB-backed)"`; or (b) change card 13 step 5d wording and card 14 assertion to expect `"wiki: batch"` as the second commit message.

### [NIT] groom_and_claim_merge naming inconsistency
**Location:** batch 1 card 5, batch 3 card 26
**Issue:** Cards reference `_spawn_core.groom_and_claim_merge` (card 5 calls it "the canonical caller for OP_MERGE_TASKS"; card 26 line range `:488-514` cites the same name). The actual function in current `_spawn_core.py` source is `multi_select_groom_then_claim`. No card instructs renaming.
**Fix:** In card 26, either add an explicit rename instruction or replace the citation with the actual function name `multi_select_groom_then_claim` everywhere it appears in cards 5 and 26.

## Verdict

REQUEST_CHANGES
Two blocking defects: missing _spawn_core body conversions and inconsistent migration commit message.
