## Findings

### [BLOCKING] Card 9 test-structure instruction contradicts existing file layout
**Location:** Batch 4 / Card 9
**Issue:** Requirements open with "Append the following five new test functions" then immediately say "each test is an inline call within `main()`, not a separate function, matching the existing file structure." `test-config.py` uses named functions registered in a `tests = [...]` list and called inside a try/except loop; pasting the assertion code inline before `return 0` bypasses that handler entirely — the first failure raises an uncaught `AssertionError`, aborts `main()`, and none of the subsequent tests run. This breaks the "run all, report all failures" contract that the verify command relies on.
**Fix:** Remove the contradictory "inline call … not a separate function" clause. Correct instruction: define each test as a named function matching the existing `test_deep_merge_…` / `test_load_config_…` style, place the definitions before the `if __name__ == "__main__":` block, and append the five new names to the `tests = [...]` list in `main()`.

### [NIT] Card 10 Test A primary patching target won't intercept _review_common calls
**Location:** Batch 4 / Card 10 / Test A
**Issue:** `patch.object(_config, "resolve_plugin_template_path", ...)` patches the attribute on `_config`, but `_review_common` already holds its own bound reference (imported via `from _config import resolve_plugin_template_path`). The patch has no effect on `_review_common.load_config`; the real resolver is called, making the test environment-dependent (passes only when the source-tree template exists at the expected path).
**Fix:** Replace the primary instruction with `patch("_review_common.resolve_plugin_template_path", ...)` or `patch.object(sys.modules["_review_common"], "resolve_plugin_template_path", ...)`; the plan's own parenthetical "or directly via the `_review_common` module's reference" is correct — elevate it and drop the `_config` variant.

### [NIT] Card 8 find-text uses double-hyphen; actual SKILL.md contains em-dash
**Location:** Batch 3 / Card 8
**Issue:** Requirements specify `echo "[mill-go] HALT: wiki appears missing or corrupted -- re-run mill-setup to restore it"` (two hyphens) but both occurrences in the actual SKILL.md file use an em-dash `—`. A literal-string search for `--` won't locate the line.
**Fix:** Update the find-text in Requirements to use `—` matching the actual file content, or instruct the implementer to locate the echo line by surrounding context rather than exact-string match.
