## Findings

### [NIT:consistency] "passed to Popen as-is" contradicts the helper's return shape
**Location:** Batch 1 / Card 2, `run_verify` step 4 **Issue:** `_posix_shell_run_args` (`_implementer_common.py`) returns a `(run_args, run_kwargs)` tuple, and the moved tests unpack it, so passing its result to `Popen` as-is would hand `Popen` a tuple. **Fix:** State that `run_verify` unpacks the tuple and calls `Popen(run_args, **run_kwargs, ...)`.

### [NIT:consistency] Merge-in plain-failure reason skips the shared truncation shape
**Location:** Batch 5 / Card 10, envelope-reason bullet **Issue:** The plain failure reason becomes `run.output.strip() + output_suffix(run)` with no `_truncate_verify_output`, but the Shared Decision "every failure reason uses one shape" lists merge-in and requires truncated output. **Fix:** Apply `_truncate_verify_output` there, or narrow the decision's `Applies to` to exclude the untruncated merge-in plain-failure path.

### [NIT:consistency] Default fake runner does not cover existing real-command cases
**Location:** Batch 3 / Card 6 test bullets and Card 7 last test bullet **Issue:** The default `_fake_run_verify` handles only `exit <N>`, but `test-implementer-common.py` has cases (e.g. the `verify_cmd = "echo '--- FAIL: TestNew (0.00s)' && exit 1"` ones, including cases 78-80) that run real shell commands without patching `subprocess.run`. Those would hit the unexpected-command failure, which contradicts "Existing cases 73-80 ... keep passing". **Fix:** Name these cases as needing a local `run_verify` patch, or extend the fake to cover `echo ... && exit <N>`.

### [NIT:consistency] "Inert until a deploy" omits an unknown-key warning
**Location:** Overview, Decision "hub mill-config.yaml edit is safe mid-flight" **Issue:** `_config.load_config` calls `warn_unknown_keys` against the plugin template, so the deployed copy, whose template lacks the key, prints `[config] unknown key: pipeline.verify_timeout_minutes` to stderr on every load until redeploy. **Fix:** Add that non-fatal warning to the rationale so it is not mistaken for a regression.

### [NIT:scope] Programmer-error and log-failure paths in `run_verify` are untested
**Location:** Batch 1 / Card 2 tests **Issue:** The requirements specify `ValueError` for `cwd is None` and for an invalid `shell_mode`, and specify that a `verify.log` write failure is swallowed. The test list covers none of these. **Fix:** Add one case for each.

## Verdict

APPROVE
No blocking issues; five NITs on wording, test enumeration and one rationale gap.
