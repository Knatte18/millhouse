## Findings

### [BLOCKING] `FIELD_OK` missing from `wiki/__init__.py` constants
**Location:** Batch 1 Card 1 / Batch 6 Card 8
**Issue:** Card 1 enumerates all protocol field constants but omits `FIELD_OK = "ok"`. Card 8 test uses `resp[FIELD_OK]` — NameError at runtime. Server and client use bare `"ok"` strings, so the constant must be added and used consistently.
**Fix:** Add `FIELD_OK = "ok"` to the `FIELD_*` block in Card 1; update Card 8 to import and use it.

### [BLOCKING] `path_guard("")` spec/test contradiction
**Location:** Batch 2 Card 3 / Batch 6 Card 9
**Issue:** Card 3 spec raises only when path is absolute, contains `..`, or escapes base. An empty string passes all three checks (`Path("").parts == ()`, `(base / "")` resolves to `base`). Card 9 test asserts `path_guard("")` raises `WikiPathError` — it will not.
**Fix:** Add an explicit "or empty" guard to Card 3's `path_guard` spec (and add the matching check in requirements).

### [BLOCKING] `CREATE_BREAKAWAY_FROM_JOB` absent from Windows spawn
**Location:** Batch 5 Card 6 — `_spawn_server`
**Issue:** Plan uses `DETACHED_PROCESS | CREATE_NO_WINDOW | CREATE_NEW_PROCESS_GROUP` on Windows. `_subprocess_util.popen_detached` comment explicitly states `CREATE_BREAKAWAY_FROM_JOB` is required to escape the VS Code / CC Bash Job Object so the worker survives launcher exit (fix for #271). Without it the wiki daemon is killed whenever the parent CC session exits, defeating the persistent-daemon design.
**Fix:** Add `CREATE_BREAKAWAY_FROM_JOB = 0x01000000` to the plan and include it in the Windows `creationflags`, consistent with `popen_detached`.

### [BLOCKING] Integration test not covered by `verify:`
**Location:** Batch 7 Card 11
**Issue:** `test-wiki-e2e.py` is added to `plugins/mill/integration_tests/` but Batch 7 has `verify: null`. Per review criteria, adding integration tests without wiring them to `verify:` is BLOCKING.
**Fix:** Either add a `verify:` command that runs `test-wiki-e2e.py`, or move the test to a location explicitly excluded from verify and document the exclusion rationale in the batch scope.

### [NIT] `datetime` not in `_daemon.py` imports list
**Location:** Batch 3 Card 4
**Issue:** The listed stdlib imports (`abc, json, logging, os, pathlib, secrets, signal, socket, time, tempfile`) omit `datetime`, but the state file requires `started_at: <ISO-8601 UTC>`.
**Fix:** Add `datetime` to the stdlib imports list in Card 4.

### [NIT] `WikiPathError` imported but unused in `_store.py`
**Location:** Batch 1 Card 2
**Issue:** Card 2 imports `WikiPathError` from `wiki`, but after the hash-guard was explicitly dropped the import is dead.
**Fix:** Remove the `WikiPathError` import from Card 2's requirements.

### [NIT] `path_guard` "dummy base" unspecified
**Location:** Batch 2 Card 3
**Issue:** "use `(base / rel_path).resolve()` to check for escape" — `base` is called a "dummy base path" with no specification. An implementer could choose `Path.cwd()`, `Path("/")`, or something else, producing inconsistent results.
**Fix:** Specify the dummy base explicitly (e.g., `Path("/guard_root")` or require `wiki_path` as a second parameter).

## Verdict

REQUEST_CHANGES
Four blockers: missing constant, spec/test mismatch, Windows Job Object escape, integration test not in verify.
