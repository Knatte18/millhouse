## Findings

### [BLOCKING] `run()` proceeds after `_claim_state_file()` yields without claiming

**Location:** `plugins/mill/scripts/_daemon.py:69-105` (`run`) and `_claim_state_file:108-122`

**Issue:** When an existing non-stale daemon is found, `_claim_state_file` logs "another daemon is running, exiting" and `return`s — back into `run()`, which then continues: binds a new socket, generates a new token, and calls `_write_state_file`, which atomically replaces the live daemon's state file with new port/token values. Two daemon instances end up running; clients land on the newcomer; the original daemon is unreachable and will idle-exit on its own schedule, potentially racing on git operations with the new one.

**Fix:** Have `_claim_state_file` return a `bool` (or raise a sentinel exception) and add an early `return` in `run()` on the "already running" path, before any socket or state-file work is done.

---

### [NIT] Root-logger StreamHandler propagates wiki-server logs to stderr

**Location:** `plugins/mill/scripts/_daemon.py:17` (`logging.basicConfig`), `plugins/mill/scripts/wiki/_server.py:60-65` (handler setup)

**Issue:** `logging.basicConfig(...)` at module import time installs a `StreamHandler` on the root logger. `WikiServer.__init__` adds a `RotatingFileHandler` to the `"wiki-server"` logger but does not set `propagate = False`, so every log record is emitted twice — once to the log file and once to stderr of the spawned daemon process.

**Fix:** Add `self._log.propagate = False` after the handler is attached in `WikiServer.__init__`.

## Verdict

REQUEST_CHANGES
One BLOCKING bug: `_claim_state_file` does not signal `run()` to exit early, allowing a second daemon to overwrite the live state file.
