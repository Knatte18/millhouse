# Plan fix — round 2

Source: `_mill/reviews/20260904-085150-plan-review-r2.md`

## Fixed

- [NIT:consistency] "Card 6's ctypes.windll mocking strategy cannot work on this Linux host" —
  confirmed: `ctypes.windll` doesn't exist as an attribute on non-Windows CPython at all, and
  `_win_pid_alive`'s function-local `import ctypes` means `_bg` has no stable module-level `ctypes`
  name to patch anyway. Card 6 (batch 3) now specifies installing fake `ctypes`/`ctypes.wintypes`
  modules via `unittest.mock.patch.dict(sys.modules, {...})` before each call to `_win_pid_alive`,
  with a `_make_fake_ctypes(kernel32)` helper and full per-case mock configuration.
- [NIT:consistency] "Card 9's case 72h contradicts Card 7's unconditional corroboration call" —
  confirmed: Card 7's `else:` branch called `_corroborate_batch_failure` unconditionally, so a mock
  replacing that function would bypass its own internal `start_sha is None` guard and be invoked
  anyway. Card 7 (batch 4) now adds an explicit `elif start_sha is None: pass` at the
  `_run_verify_gates` call site itself, so `_corroborate_batch_failure` is never invoked when
  `start_sha` is `None` — Card 9's case 72h assertion (mock never called) is now correct as written.
- [NIT:consistency] "New orphan-baseline-dir teardown loop catches a narrower exception than
  remove_safe can raise" — confirmed `WorktreeLockedError(WorktreeError)` is a subclass, and
  `remove_safe`'s "unrecognized git failure" branch raises the plain base class. Card 3 (batch 2) now
  catches `_worktree.WorktreeError` (matching the sibling `_apply_worktree_record` handler it claims
  to mirror), and Card 4's tests now cover both the subclass and the base-class exception cases
  separately.
- [NIT:consistency] "`import time` placement in Card 1 contradicts its own alphabetical-ordering
  rationale" — confirmed the existing block (`shutil, subprocess, sys`) is already alphabetical and
  `time` sorts after `sys`, not between `subprocess` and `sys`. Card 1 (batch 1) now places
  `import time` after `import sys`.
- [NIT:consistency] "Card 2's cited mocking target for the rmtree fallback doesn't match the file's
  actual convention" — confirmed the existing WinError145 tests patch `_safe_rmtree.shutil.rmtree` +
  `_safe_rmtree._blacklist_for`, never `_safe_rmtree.safe_rmtree` as a whole. Card 2 (batch 1)
  corrected.

## Additional fix (found while verifying the finding above, not in the reviewer's list)

- While re-reading `test-worktree.py` to verify the mocking-target NIT, confirmed Card 1's own
  retry-count change (1→3 total attempts) would break an *existing* test — "raises WorktreeLockedError
  when retry also raises WinError 145" — whose `side_effect=[lock_exc_1, lock_exc_2]` has only 2
  items; a 3rd `_safe_rmtree.shutil.rmtree` call under the new loop would exhaust the side_effect list
  and raise `StopIteration` instead of the expected `WorktreeLockedError`. Card 2 now explicitly
  requires extending that existing test's `side_effect` list to 3 items and updating its
  `mock_rmtree.call_count` assertion to `3`, alongside confirming the sibling "retries once and
  succeeds" test needs no change (its 2-item side_effect already matches the new loop's
  early-exit-on-success behavior).
