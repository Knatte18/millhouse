## Findings

### [BLOCKING] parse_home_md does not produce `has_proposal` / `id` keys
**Location:** Batch 5, Card 9 (also affects Card 10, Card 12)
**Issue:** Card 9 claims `parse_home_md` returns `list[dict]` with V3 keys including `id` and `has_proposal`. The actual implementation at `wiki/_parse.py` only emits `{slug, title, group, brief, status}` — no `id`, no `has_proposal`. After Card 4 converts `_spawn_core._prompt_numbered`/`_prompt_numbered_multi` to direct `t["has_proposal"]` access, any test that feeds `parse_home_md` output into `pick_task_single`/`pick_task_single_or_multi` (e.g. `test_pick_task_single_numbered_path`, `test_pick_task_single_or_multi_*` in test-spawn-core.py) raises `KeyError: 'has_proposal'` in the picker — those surviving tests cannot pass as written.
**Fix:** Choose one and call it out in Card 4 and Card 9: (a) extend `wiki/_parse.py` to set `has_proposal` from the proposal-link form already detected by `proposal_match`; (b) use `.get("has_proposal", False)` in `_spawn_core._prompt_numbered*`; or (c) require test-spawn-core.py to wrap parsed dicts with the missing keys. Option (a) keeps `parse_home_md` and `list_tasks_brief` shape-compatible and is the lowest-friction.

### [BLOCKING] Card 13 prescribes `pytest.skip` for bare-script tests
**Location:** Batch 6, Card 13 (and Batch 5, Card 8 final verification text)
**Issue:** Card 13 says "add a `pytest.skip('see #NNN')` mark with the issue link in the affected test file." All `unit_tests/test-*.py` and `integration_tests/test-*.py` are bare Python scripts with `def main() -> int` runners (no pytest collection — `run-all.py` invokes each as a subprocess and checks exit code). `pytest.skip()` raises `Skipped` outside a pytest context and crashes the script — same hazard Card 12 already forbids for integration tests. This contradicts Card 12 and would not produce a passing `run-all.py`.
**Fix:** Mirror Card 12's pattern in Card 13: for unit tests, drop the failing test function from the per-file `tests = [...]` runner list and add a top-of-file `# SKIP: see #NNN` comment; do not use `pytest.skip`.

### [NIT] millpy-wikipush "post-edit shape" duplicates existing line
**Location:** Batch 4, Card 6
**Issue:** The shown "post-edit shape (lines 109-119 collapse to two lines)" re-prints `changed = _changed_files(wiki)`, but that assignment already exists above the `try:` and is not being moved. An overly literal implementer could duplicate it.
**Fix:** Clarify that `changed = _changed_files(wiki)` is pre-existing and only the `return _push_inner(...)` line moves out (unindented) from the deleted `with` block.

### [NIT] Card 12 dict-literal uses `"brief": None`
**Location:** Batch 6, Card 12
**Issue:** Replacement dict literal for `_tasks_md.Task(...)` specifies `"brief": None`, but both `parse_home_md` and `Store.list_tasks_brief` produce `""` (empty string) for unset brief. Downstream string operations (`brief + "\n" + ...`) on the test dicts will fail differently than on daemon-sourced dicts.
**Fix:** Use `"brief": ""` in the replacement dict-literal template.
