## Findings

### [BLOCKING] Card 11: `resolve_path` not patched for `millpy-review-plan.py` test

**Location:** Batch 3, Card 11 (test-review-cli-error-envelope.py)
**Issue:** The patch list omits `resolve_path`. In `millpy-review-plan.py`, after `find_active_slug` returns (patched to return a slug), the code immediately calls `resolve_path(cfg["paths"]["plan_dir"], slug)` inside the `if not args.skip_validate:` block. `resolve_path` calls `_paths.resolve_git_root()` which fails in a plain tempdir (not a mill container-layout git repo), propagating a `SystemExit` or unhandled exception out of `main()` — not a `ReviewError`. The test never reaches the backend `run()` mock; the plan CLI engine-internal-failure and success paths are untested. Patching `_plan_validate.run` to return `[]` does not help because `resolve_path` is called before `validate_run`.
**Fix:** For plan CLI test cases, pass `argv=["--skip-validate"]` (skips the entire `if not args.skip_validate:` block, including the `resolve_path` call). Remove the `_plan_validate.run` patch instruction — it is both unnecessary and insufficient.

### [NIT] Card 14: `import errno` listed as required import but never used

**Location:** Batch 5, Card 14 (_bg.py)
**Issue:** The "Imports" line in Card 14 lists `errno` as a required stdlib import. The implementation outline contains no `errno.E*` reference; Python 3.3+ promotes `ESRCH → ProcessLookupError` and `EPERM/EACCES → PermissionError`, so typed `except` clauses already handle those without the `errno` module. The plan hedges with "either choice is acceptable" but leaves an unused import that would trigger a linter warning in any `flake8`/`ruff`-equipped environment.
**Fix:** Remove `errno` from the "Imports" line in Card 14. No other change needed.
