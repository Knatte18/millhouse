## Findings

### [BLOCKING] _layer_sort_key references row["id"] which is never added to rows
**Location:** Batch 5 / Card 25
**Issue:** Card 25 adds `"layer"` to rows in `_build_rows` but the `_layer_sort_key` helper uses `(bucket_index, row["id"])` as the sort tuple; `_build_rows` has no `"id"` field in its `rows.append({...})` dict, so every `--sort layer` call raises `KeyError`.
**Fix:** Add `"id": home_tasks[slug].get("id") if slug in home_tasks else None` to each row in `_build_rows`, and use `row.get("id", 0)` in `_layer_sort_key`.

### [NIT] Card 11 does not enumerate which existing tests need updates
**Location:** Batch 3 / Card 11
**Issue:** "Update existing render test cases that reference `group` fields or `# Unspecified`" is unspecific — tests 2, 3, 4, and 13 all use `group`-keyed task dicts or assert on `# Unspecified`/`# Layer X` headers that will change semantics under `compute_layers`.
**Fix:** List each test number and the specific assertion replacement (e.g. test 13: remove `unspecified != -1` assert, add `"# Someday"` check; test 2: replace `"group": "B"` with `"depends_on": []`).

### [NIT] Card 15(e) migration test incompatible with post-Batch-2 upsert_task
**Location:** Batch 4 / Card 15
**Issue:** "insert a task with `group='Z'` via direct store insert" — after Batch 2, `upsert_task` raises `ValueError` for any incoming `group` key via `_validate_write`; the requirement does not say to bypass the public API.
**Fix:** Explicitly state "insert via `wiki_server._store._db.insert({...})` to simulate pre-migration data, bypassing `upsert_task` validation."

### [NIT] render_order(unmarked) vs. server-computed layer field in extended_title
**Location:** Batch 5 / Card 24
**Issue:** `render_order(unmarked)` re-runs `compute_layers` on only the unmarked subset, which may assign different level letters than the server's enriched `layer` field (used by `extended_title`). Active or done tasks that are deps of unmarked tasks are absent from the subset, pulling dependents up to "A"; `extended_title` would still display the server's (higher) letter.
**Fix:** Either call `render_order` on the full task list and filter afterwards, or accept and document that picker order may diverge from Home.md order for tasks with cross-status deps.
