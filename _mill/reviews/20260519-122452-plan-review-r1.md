## Findings

### [BLOCKING] Card 1 describes mill-config.yaml roles block as commented-out, but it is active
**Location:** Batch 1, Card 1
**Issue:** The card states "the file currently has the whole `roles:` block commented out" — the provided `mill-config.yaml` has a fully active `roles:` block (with `discussion-review:`, `plan-review:`, `code-review:`, and `implementer:` subsections). An implementer following "Add a new active (uncommented) top-level `roles:` block" literally would create a duplicate top-level `roles:` YAML key; PyYAML's `safe_load` uses last-wins semantics, silently dropping all four existing role subsections and breaking every `validate_role_refs` test and config-dependent operation.
**Fix:** Replace the erroneous parenthetical with "the file already has an active `roles:` block; add a `fixer:` subsection under it, sibling to `implementer:`". Remove the phrase "Add a new active (uncommented) top-level `roles:` block" and replace with "Add a `fixer:` key under the existing `roles:` block".
