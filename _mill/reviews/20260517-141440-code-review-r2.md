## Findings

### [NIT] `_collect_task_intent` carries a multi-line docstring
**Location:** `millpy-merge-in-subagent.py` (the `_collect_task_intent` helper)
**Issue:** The plan specifies one comment line above the helper; the implementation also adds an 8-line docstring that re-describes what the code already expresses. CLAUDE.md and the session guidelines both say "never write multi-paragraph docstrings — one short line max."
**Fix:** Remove the docstring body; keep only the required `# DU-conflict resolution needs branch intent; the resolver had no signal before #314.` comment above the function.

### [NIT] `_collect_task_intent` output has extra blank lines per plan file
**Location:** `millpy-merge-in-subagent.py:_collect_task_intent`
**Issue:** The heading is appended with a trailing `\n` (`f"### From _mill/plan/{filename}\n"`), and then each subsequent element is separated by the `"\n\n".join` separator, producing triple newlines between the heading and the YAML block.
**Fix:** Append the whole per-file section as a single formatted string (per the plan's `f"### From _mill/plan/{filename}\n\n{yaml_block}\n\n{bullets_text}"` shape) so the join separator produces exactly one blank line between sections.

### [NIT] Malformed batch YAML produces a false `depends-on-batch-mismatch` error
**Location:** `_plan_validate.py:_check_depends_on_batch_mismatch` (the `except Exception: batch_side_deps[name] = []` clause)
**Issue:** When a batch file's YAML block cannot be parsed, the fallback `[]` is compared against the overview's resolved deps. If the overview has a non-empty `depends-on`, the check emits a mismatch error for a file that failed to parse — not a true dependency disagreement.
**Fix:** On parse failure, `continue` (skip the entry entirely) rather than storing `[]`; other checks (`card-missing-field`, `reads-not-backtick-path`) will already surface the malformed file.
