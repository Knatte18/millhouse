## Findings

### [NIT] Card 5's non-finalize dispatch call site lacks a distinguishing status_path test
**Location:** `plugins/mill/scripts/millpy-fix.py:553-564` vs `plugins/mill/unit_tests/test-millpy-fix.py`
**Issue:** The `--stage full` holistic branch (line 556-561) correctly threads `status_path` into `iter_batch_verifies` and calls `_report_skipped_verifies`, matching the `--stage finalize` branch exactly, and code inspection confirms it is wired correctly. However every test exercising this call site (`test_holistic_scope_uniform_cwd_hub_threads_cwd_override`, `test_holistic_scope_mixed_cwd_raises_value_error_naming_batches`, `test_holistic_all_null_verifies`) uses an all-`"approved"` (or all-`verify: null`) fixture, which is behaviorally indistinguishable from omitting `status_path` entirely — none of them prove the filter is actually active at this call site the way `test_holistic_finalize_status_path_filters_pending_batch_and_logs_skip` does for the finalize call site. This falls short of batch 4's own Batch Tests requirement to cover "both call sites" with a pending-batch fixture.
**Fix:** Add one test on the `--stage full` (non-finalize) path with a deliberately `"pending"` batch and assert the corresponding verify is absent from the joined command and/or the `[millpy-fix] skipped ...` stderr line appears, mirroring the existing finalize-stage test.

## Verdict

APPROVE
All four batches correctly realise the plan; cross-batch contracts, Shared Decisions, and test coverage are sound bar one minor gap.
