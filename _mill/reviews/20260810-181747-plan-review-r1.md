## Findings

### [BLOCKING:design] Card 8's code-stage verdict-rewrite sub-case has no excluded class to test
**Location:** Batch 2 (finalize-verdict-rewrite), Card 8, `test_verdict_token_rewritten_for_plan_and_code_types`.
**Issue:** The card says to build the code-type sub-case using `resolve_blocking_classes({}, "code", "holistic")` plus "a finding class excluded from [code]'s ceiling per... `test_ceiling_table_code`" — but `test_ceiling_table_code` (existing, unchanged) itself asserts `blocking_count == 4, nit_count == 0`, i.e. `DEFAULT_BLOCKING_CLASSES["code-review"]` equals all four `RECOGNIZED_CLASSES`. No class is excluded by default for code review, so no ceiling-flip fixture is constructible under the call the card specifies.
**Fix:** For the code sub-case, pass an explicit custom `blocking_classes` frozenset (e.g. one that excludes a class) instead of `resolve_blocking_classes({}, "code", "holistic")`, or state that the code sub-case is dropped in favor of the plan-only variant.

### [BLOCKING:design] Card 7's rewrite guard doesn't actually scope to "ceiling changed the verdict"
**Location:** Batch 2, Card 7 (`finalize_scope` wiring) and Card 8's test coverage.
**Issue:** `resolve_blocking_classes` never returns `None`; every production call site already passes a non-`None` value (per `finalize_scope`'s own docstring: "every production call site passes this explicitly"). So the `blocking_classes is not None` guard does not exclude the case Card 7's own rationale calls out-of-scope — "a reviewer stating the wrong verdict token for its own finding count" unrelated to any ceiling demotion. In production this now also gets silently rewritten, and no Card 8 test exercises it (`test_verdict_token_unchanged_when_no_demotion`'s fixture already starts with `verdict == original_verdict`, so it can't detect this).
**Fix:** Either accept the broader scope explicitly (document it, add a "mismatched-but-no-demotion" test) or gate the rewrite on "an actual demotion occurred" (e.g. `findings != pre-ceiling findings`) rather than merely `blocking_classes is not None`.

### [BLOCKING:design] Demoted-predicate convergence gate ignores plan-review's approved-batch carryforward
**Location:** Batch 3 (review-loop-min-rounds), Card 12 / the Batch Scope's shared convergence-gate design.
**Issue:** `_review_plan.py`'s `_scan_approved_batches` + `run()` concatenate already-approved, carried-forward batches' `findings` (which can carry stale `demoted: true` markers written by a prior round's ceiling) into the same top-level `findings` the convergence gate reads. If `plan-review.batch` is ever enabled — mill-plan's own SKILL text anticipates this ("If per-batch plan review is ever enabled, the SKILL loops the three-step flow once per enabled scope") — a stale demotion from an unrelated, already-approved batch makes `not any(f.get("demoted"))` permanently False, so the holistic convergence gate can never converge before the round cap forces the implicit-approve fallback every single round.
**Fix:** Scope the demoted-predicate check to the current round's own (non-carried-forward) findings, or explicitly document this as a limitation confined to `plan-review.batch`-disabled hubs (both configs in this repo currently disable it, but the SKILL applies generically).

## Verdict

Two Card 8 test fixtures are unbuildable/undertested as specified, and the demoted-predicate gate has an unaddressed carryforward interaction.
