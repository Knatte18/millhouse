## Findings

### [NIT] check_bg_status double-read creates orphaned probe state

**Location:** `plugins/mill/scripts/_bg.py:138-150`
**Issue:** `check_bg_status` reads the log at line 138, then calls `_probe_liveness` which re-reads the file. If `[mill-bg] EXIT` appears between the two reads, `_probe_liveness` returns `("exit", pid)` but `check_bg_status` has no branch for that probe state -- it falls through to `("dead", pid)`. The plan intended to eliminate the two-read race by checking EXIT first, but the double-read preserves a microsecond window where the new code is slightly worse than the old race-guard.
**Fix:** After `state, pid = _probe_liveness(log_path)`, add `if state == "exit": ...` to extract the code via `_EXIT_CODE_RE` on a re-read (or return `("exit", 0)` as a safe fallback), matching the existing step-2 fast path.

### [NIT] check_bg_status docstring omits agent-mode dispatch note

**Location:** `plugins/mill/scripts/_bg.py:116-134`
**Issue:** Card 3 requires the `check_bg_status` docstring to note that agent-mode dispatch is the structural resolution and subprocess/psmux detection is best-effort plus JSON-sentinel backstop. That note is in the module docstring but absent from the function docstring.
**Fix:** Add one line to the `check_bg_status` docstring: "Agent-mode dispatch (no subprocess) is the structural fix; this fallback applies only to subprocess-mode workers."

APPROVE
Core logic correct; two NITs are non-blocking.
