## Findings

### [BLOCKING] Integration test skips the primary end-to-end assertion
**Location:** `plugins/mill/integration_tests/test-hub-relative-path.py` (main function, Step 1 comment)
**Issue:** The dry-run spawn assertion — plan Card 12 requirement #3 — is entirely absent. `_run_spawn` is defined but never called. The comment reads "Skip the mill-spawn dry-run test for now". This was the only assertion that could have caught the spawn status-path bug below.
**Fix:** Remove the "Skip" comment and call `_run_spawn(hub)`; assert exit code 0 and that stdout contains a `[DryRun] Status:` line whose path is under `<wts>/subproj-fixture/projects/sub/_mill/status.md`.

### [BLOCKING] millpy-spawn uses worktree_path instead of dest_hub for status paths
**Location:** `plugins/mill/scripts/millpy-spawn.py` (dry-run print block and `write_initial_status` call)
**Issue:** Both the `[DryRun] Status:` output and the `write_initial_status(worktree_path=worktree_path, ...)` call pass the git checkout root (`<wts>/subproj-fixture`), not the hub subfolder (`<wts>/subproj-fixture/projects/sub`). For any `hub_subpath != "."`, `_mill/status.md` is written to the worktree root instead of the hub subfolder. The skipped integration test assertion was designed to catch exactly this failure.
**Fix:** Replace `worktree_path` with `dest_hub` in both the dry-run `_paths.status_path(…)` call and the `write_initial_status(worktree_path=…)` argument; also update the test fixture to include a stub at `outer_repo/projects/sub/.millhouse/config.local.yaml` so `hub_relative_path` propagates into spawn's config when running from the hub subfolder.

### [NIT] Module docstring in _config.py has stale signature
**Location:** `plugins/mill/scripts/_config.py:1-10`
**Issue:** The module-level docstring still declares `load_config(wiki_path, worktree_root)` and describes loading `wiki/config.yaml`. Both are wrong after the hub_root rename and layering overhaul.
**Fix:** Update the docstring to `load_config(hub_root: Path, worktree_root: Path)` and describe the actual merge order (plugin template → hub overlay → local stub → real config → env overrides).

### [NIT] Dead code: _run_spawn defined but never used
**Location:** `plugins/mill/integration_tests/test-hub-relative-path.py`
**Issue:** The `_run_spawn` function is defined with full implementation but is never invoked, making it dead code that will mislead future readers.
**Fix:** Either call the function (after fixing the two BLOCKING issues above) or remove it.

## Verdict

REQUEST_CHANGES
Two blocking defects: the integration test skips its central assertion, and spawn writes status.md to the wrong directory for sub-project layouts.
