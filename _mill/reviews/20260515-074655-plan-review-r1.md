## Findings

### [NIT] `worktree_root` undefined before step 4.5 in mill-go
**Location:** Batch 2 / Card 2
**Issue:** Step 4.5 uses `worktree_root` in both `_config.load_config(wiki_path, worktree_root)` and `_paths.resolve_task_path(worktree_root, ...)`, but mill-go's entry steps 1–4 never assign that variable; step 2 calls `_paths.resolve_git_root()` inline without storing the result.
**Fix:** Add `worktree_root = _paths.resolve_git_root()` to step 4.5's preamble, or update step 2 to store `worktree_root = _paths.resolve_git_root(_paths.resolve_git_root())`.

### [NIT] Step 4.5 re-loads config already loaded in step 3
**Location:** Batch 2 / Card 2
**Issue:** Mill-go step 3 already loads config via `_review_common.load_config(wiki_path, Path(".millhouse"))`; step 4.5 adds `cfg = _config.load_config(wiki_path, worktree_root)` using a different function and a different second argument. The plan does not reconcile these two loads or explain which one wins.
**Fix:** Explicitly note that step 4.5's assignment supersedes step 3's, or update step 3 to use `cfg = _config.load_config(wiki_path, worktree_root)` directly and drop the redundant step-4.5 reload.

### [NIT] Board Discipline references undefined variables in mill-merge
**Location:** Batch 3 / Card 4 step 7
**Issue:** The updated Board Discipline prose references `discussion_path`, `plan_dir`, and `reviews_dir`, but mill-merge's Path Setup only defines `status_path` and `task_dir`; those three variables are never set in mill-merge.
**Fix:** Reference `task_dir` (the directory removed at cleanup) instead of the individual path variables that mill-merge does not use.

### [NIT] `plan_dir` trailing slash changes value written to `status.md`
**Location:** Batch 4 / Card 6 step 3
**Issue:** `cfg['paths']['plan_dir']` equals `"_mill/plan/"` (trailing slash from wiki-config.yaml template), while the current hardcoded string `"_mill/plan"` has none; calling `_status.update_field(status_path, "plan", cfg['paths']['plan_dir'])` silently changes the on-disk value.
**Fix:** Strip the trailing slash on write (`cfg['paths']['plan_dir'].rstrip('/')`) or document that the change is intentional and no downstream consumer does string-equality checks on this field.

### [NIT] Card 8 `required_keys` omits `junctions`
**Location:** Batch 5 / Card 8
**Issue:** The upsert list `['paths', 'llm', 'pipeline', 'roles', 'notify', 'spawn', 'groom']` omits `junctions`, which `_wiki.read_junctions` consumes; an existing config missing `junctions:` silently falls back to `_JUNCTION_DEFAULTS` (only `.wiki`), leaving `.portals` and `.active` absent until the operator notices.
**Fix:** Add `'junctions'` to `required_keys`, or add a comment noting the fallback is acceptable.

## Verdict

APPROVE
Plan is structurally sound; all five findings are NITs with no functional blockers.
