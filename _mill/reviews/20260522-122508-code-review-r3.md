## Findings

### [BLOCKING] `run()` finally deletes live daemon's state file on early exit

**Location:** `plugins/mill/scripts/_daemon.py:82-92` (the `run` method try/finally)
**Issue:** When `_claim_state_file()` returns `False` (another healthy daemon running), `return` triggers the `finally` block, which calls `self._state_file_path.unlink(missing_ok=True)` — deleting the live daemon's state file. Every subsequent client call will see no state file and spawn a second daemon, creating two competing daemons on the same wiki path.
**Fix:** Track whether this invocation actually claimed the state file; guard cleanup on that flag: `claimed = False` before the try, `claimed = True` immediately after `_claim_state_file()` returns True, and change `finally` to `if claimed: self.on_stop(); self._state_file_path.unlink(...)`.

### [NIT] `import tempfile` unused in `_daemon.py`

**Location:** `plugins/mill/scripts/_daemon.py:9`
**Issue:** `tempfile` is imported but never used; `_write_state_file` uses `path.with_suffix('.tmp')` directly.
**Fix:** Remove the `import tempfile` line.

### [NIT] Module-level `logging.basicConfig` import side effect in `_daemon.py`

**Location:** `plugins/mill/scripts/_daemon.py:14`
**Issue:** `logging.basicConfig(...)` at module level reconfigures the root logger in any process that imports `_daemon`, interfering with the importer's logging setup. Plan lists only imports as module-level; no side effects were specified.
**Fix:** Move into `run()` or guard with `if not logging.root.handlers`.

### [NIT] Dead code in `DaemonBase._is_stale` — `if not pid_alive: return True` unreachable

**Location:** `plugins/mill/scripts/_daemon.py:149-151`
**Issue:** Every code path that doesn't `return True` early sets `pid_alive = True`; the guard `if not pid_alive: return True` is structurally unreachable.
**Fix:** Remove the dead guard; the subsequent socket check already handles the full alive case.

### [NIT] `_connect_send_recv` receives `token` parameter but never uses it

**Location:** `plugins/mill/scripts/wiki/_client.py:216`
**Issue:** `token` is part of `msg` already; the parameter is accepted but unused in the function body, creating a misleading signature.
**Fix:** Remove `token` from the parameter list and all call sites.

### [NIT] `proc.wait()` with open pipes risks deadlock in `_scenario_2_concurrent_cas`

**Location:** `plugins/mill/integration_tests/test-wiki-e2e.py:138-139`
**Issue:** `proc_a.wait(timeout=30)` / `proc_b.wait(timeout=30)` with `stdout=PIPE, stderr=PIPE` open — if subprocess output fills the OS pipe buffer the child blocks writing and `wait()` deadlocks. Script output is small so it's unlikely but latent.
**Fix:** Replace `wait()` + subsequent `communicate()` with `communicate(timeout=30)` and capture `(out, err)` from that call.

## Verdict

REQUEST_CHANGES
The `run()` finally-block bug silently corrupts a live daemon's state file on every contended startup.
