## Findings

### [NIT] Phase 2 capture_pane call not stated explicitly
**Location:** Batch 2 / Card 4
**Issue:** Phase 2 description says `curr_idle = "for shortcuts" in capture` with `(swallow PsmuxError → curr_idle = False)` implying a capture_pane call, but never explicitly names it; the first capture source (last Phase-1 capture vs. fresh call) is left to inference from Scenario (b)'s 4-capture count.
**Fix:** Add one line: "At the top of each Phase 2 iteration, call `capture_pane(session_name, alternate=True)` in a try/except; on `PsmuxError` set `capture = ''`."

### [NIT] No direct unit test for rewritten _wait_for_idle_prompt
**Location:** Batch 2 / Card 3, Batch 4
**Issue:** After Card 3 replaces the `❯`-per-line loop with `"for shortcuts" in capture`, no direct test exercises the new body (S-series mocks the function away; Scenarios a/b/c only cover `_wait_for_idle_stable`).
**Fix:** Add a 2-case direct test in `test-claude-sub.py` alongside Scenarios a/b/c: one where capture contains "for shortcuts" → True, one where timeout fires → False.

### [NIT] Integration test prereq check still hardcodes pwsh
**Location:** Batch 4 / Card 11
**Issue:** `_check_prerequisites()` in `test-claude-psmux.py` checks `shutil.which("pwsh")`, but after Card 2 the shell path is read from config (may be a full absolute path not on PATH), so the prerequisite check would incorrectly skip the test on machines using the configured path.
**Fix:** Either call `_resolve_shell_path()` and check that path exists, or drop the `pwsh` prerequisite check since the test already depends on `millpy-claude-sub.py` which handles shell resolution internally.
