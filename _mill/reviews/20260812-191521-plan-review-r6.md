## Findings

### [NIT:consistency] Batch 4's dead-parent status.md fixtures lack the required ```yaml fence, so resolve_dead_parent can't parse them
**Demoted-from:** BLOCKING
**Location:** 04-integration-tests.md, Cards 11(a), 12, 13, 14
**Issue:** These cards write `_mill/status.md` (and, in Card 14, `task/status.md`) fixture content as bare `"phase: done\ntask: ...\nparent: ...\n"` strings with no `` ```yaml `` / `` ``` `` fence wrapper. `_parse_parent_from_yaml_text` (Card 1, batch 1 — verbatim-extracted from the existing `_read_parent_from_status` loop) only sets `in_block = True` after a line exactly equal to `` ```yaml ``, and only reads `parent:`/`slug:` rows while `in_block`. Content with no fence line never enters `in_block`, so the parser returns `None` for `parent:` regardless of what the text contains — `resolve_dead_parent` step 5 then treats this identically to "no `parent:` row" and returns `{"outcome": "fallback", "reason": "chain-end", ...}` at the very first hop.
**Impact:** Card 11(a) expects `{"outcome": "resolved", "branch": "main", "hops": ["parent-task"]}` but would actually get chain-end fallback. Card 12's two-hop resolution never gets past hop 1 (task-b), so its `resolved`/`release/1.0`/two-hops assertion fails. Card 13's cycle scenario would return chain-end with `hops: ["cycle-x"]` after one hop instead of `outcome: "cycle"` with 10 hops. Card 14's legacy-layout scenario would also incorrectly resolve to chain-end instead of exercising the `task/status.md` fallback it's meant to prove. Only Card 11(b) ("no-tag", no tag exists) and Card 11(c) (no status.md at either path — correctly and deliberately fence-free-irrelevant, since the file is absent entirely) are unaffected, since both return before the parse step is reached.
**Fix:** Wrap every fixture status.md string in these four cards with a leading `` ```yaml `` line and trailing `` ``` `` line (matching `_setup_trio`'s and `_setup_nested_hub_scenario`'s existing status.md fixtures in this same file), e.g. `` "```yaml\nphase: done\ntask: Parent task\nparent: main\n```\n" ``.
