## Findings

### [BLOCKING] `import wiki` does not expose client API functions
**Location:** Batch 2 card 4; Batch 3 card 5; Batch 4 card 6; Batch 5 card 8; Batch 6 card 12
**Issue:** Plan instructs `import wiki` then `wiki.list_tasks_brief()` / `wiki.merge_tasks()` / `wiki.set_phase()` / `wiki.upsert_task()`. But `plugins/mill/scripts/wiki/__init__.py` only re-exports constants and exception classes — the functions live in `_client.py` and are never re-exported. `import wiki; wiki.list_tasks_brief(...)` raises `AttributeError` at runtime; the existing `millpy-fold.py` works only because it does `from wiki import _client as wiki, LOCKED_FOLD_PHASES`.
**Fix:** Either add a card (or extend card 4) that re-exports the public API from `wiki/__init__.py` (e.g. `from ._client import upsert_task, upsert_tasks_batch, set_phase, remove_task, get_task, list_tasks_brief, list_tasks_full, merge_tasks, health_check`), or change every `import wiki` directive to `from wiki import _client as wiki` to mirror the proven millpy-fold.py pattern.

### [BLOCKING] Card 4 body rewrite references undefined `source_tasks`
**Location:** Batch 2 card 4 — "`multi_select_groom_then_claim` body" section
**Issue:** Current signature is `multi_select_groom_then_claim(wiki_path, source_slugs: list[str], ...)` and the caller in `millpy-spawn.py` passes `source_slugs = [t["slug"] for t in picked]`. The plan tells the implementer to write `remove_slugs=[t["slug"] for t in source_tasks]` — `source_tasks` is not a parameter, and indexing strings as dicts would crash. The plan also separately renames "line 545 `source_tasks: list[_tasks_md.Task]`" which is in `prompt_merged_entry`, not in this function.
**Fix:** State explicitly: in `multi_select_groom_then_claim` use `remove_slugs=source_slugs` (parameter already a `list[str]`); the dict-iteration rewrite belongs only in `prompt_merged_entry` where the parameter is genuinely `list[dict]`.

### [BLOCKING] Verify gate for batch 2 references file not in context
**Location:** Batch 2 verify (`00-overview.md` batch index and `02-spawn-core-v2-elimination.md`)

The plan claims it currently fails with `ModuleNotFoundError: No module named '_sidebar'`, but the implementer has no way to read or confirm this without the file. If `test-millpy-color.py` does not exist in the repo, the verify command silently passes vacuously or fails for unrelated reasons.
