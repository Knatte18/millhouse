## Findings

### [BLOCKING] `batch:` field uses frontmatter name instead of file stem
**Location:** `plugins/mill/scripts/_plan_validate.py` — `_check_verify_not_isolated`, error dict construction
**Issue:** The error envelope sets `"batch": batch_name or batch_path.stem` where `batch_name = parsed.get("batch")`. For a file `01-verify-isolation.md` with frontmatter `batch: verify-isolation`, this yields `"verify-isolation"` not `"01-verify-isolation"`. The Shared Decision `validator-error-envelope-5-key` explicitly requires the file's stem, and the SKILL.md fix-dispatcher resolves `_mill/plan/<batch>.md` directly — `_mill/plan/verify-isolation.md` does not exist, so the mechanical fix would fail to find the target file.
**Fix:** Drop `batch_name = parsed.get("batch")` and replace `batch_name or batch_path.stem` with `batch_path.stem` unconditionally. Update the three test assertions that check the wrong batch value: `test_check_verify_not_isolated_dirty_no_prefix` (`"alpha"` → `"01-alpha"`), `test_check_verify_not_isolated_two_batches_dirty` (`{"alpha", "beta"}` → `{"01-alpha", "02-beta"}`), and `test_check_verify_not_isolated_run_integration` (`"alpha"` → `"01-alpha"`).

### [NIT] `run()` docstring still lists only checks through issue #10
**Location:** `plugins/mill/scripts/_plan_validate.py:842` — `run()` docstring: `"Checks 1, 2, 3, 4, 5, 6, 8 from issue #10, plus wiki-config-mutation."`
**Issue:** `verify-not-isolated` was added to the module-level "Checks performed" list (correctly) but the `run()` function's own docstring wasn't updated.
**Fix:** Append `verify-not-isolated` to the enumeration, e.g. `"… plus wiki-config-mutation and verify-not-isolated."`.
