## Findings

### [BLOCKING] Lazy-refresh pull failure aborts read instead of serving cache
**Location:** `plugins/mill/scripts/wiki/_server.py:108-114`
**Issue:** When `pull()` raises `WikiPushError` during lazy refresh in `_handle_read`, the implementation returns `{FIELD_OK: False, FIELD_ERROR_TYPE: ERR_PUSH_FAILED}`, making every read fail during a remote outage. The plan explicitly states "Setting `_last_pull` before the call ensures the refresh interval is honored **even if `pull()` raises**" — the intent is to continue serving from cache, not abort.
**Fix:** Catch `WikiPushError` inside the refresh block, log a warning, and fall through to the cache-hit / disk-read path so stale-but-valid cache is served.

### [NIT] `_ensure_gitignore` uses substring check instead of line check
**Location:** `plugins/mill/scripts/wiki/_server.py:195-196`
**Issue:** `".wiki-daemon.json" in content` is a substring check; the plan specifies checking whether entries are "present as lines". A comment containing the filename would produce a false positive.
**Fix:** Split on newlines and check `any(line.strip() == ".wiki-daemon.json" for line in content.splitlines())`.

### [NIT] `health_check` only verifies TCP reachability, not daemon liveness
**Location:** `plugins/mill/scripts/wiki/_client.py:107-120`
**Issue:** The implementation opens and closes a TCP connection. The plan says "Return True if daemon responds to a read request for a non-existent path (any response means alive)." A daemon that has bound the port but crashed mid-accept would pass this check.
**Fix:** Send a minimal read request and verify any JSON response is received, matching plan spec.

### [NIT] `CAS_RETRIES` constant defined but unused
**Location:** `plugins/mill/scripts/wiki/_client.py:38`
**Issue:** `CAS_RETRIES: int = 3` is never referenced inside `_client.py`; the integration test hardcodes its own `max_retries = 5`. The plan section header says "implements CAS retry" implying the constant is meant for internal use.
**Fix:** Either use it in the integration test subprocess script, or document that it is exported for callers.

### [NIT] PYTHONPATH join in `_spawn_server` omits trailing-separator strip
**Location:** `plugins/mill/scripts/wiki/_client.py:165-170`
**Issue:** The plan specifies the joined PYTHONPATH should be stripped of trailing `os.pathsep`. If the existing `PYTHONPATH` ends with a separator, the resulting value contains a trailing empty entry.
**Fix:** Apply `.strip(os.pathsep)` after joining: `env["PYTHONPATH"] = (scripts_dir + os.pathsep + pythonpath).strip(os.pathsep)`.
