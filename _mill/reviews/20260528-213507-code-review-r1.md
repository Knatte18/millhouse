## Findings

### [BLOCKING] Defective junction-removal assertion in test-junction.py case (c)
**Location:** `plugins/mill/unit_tests/test-junction.py:101`
**Issue:** `assert wiki_link not in [p for p in stripped if p.name == ".wiki"] or not wiki_link.exists()` is a tautology when stripping fails — if `wiki_link` is absent from `stripped` (i.e., the function is broken), `wiki_link not in [...]` is `True` and the OR short-circuits to `True`. The assertion always passes regardless of whether the junction was stripped.
**Fix:** Replace with `assert wiki_link in stripped` + `assert not wiki_link.exists()`.

### [NIT] Temp dirs leaked in test-wiki-protocol.py cases 18-20
**Location:** `plugins/mill/unit_tests/test-wiki-protocol.py:325,356,385`
**Issue:** Cases (18), (19), (20) each call `tempfile.mkdtemp()` with no `try/finally` cleanup. Plan explicitly required `_test_helpers.safe_temp_dir`.
**Fix:** Wrap each case body in `with safe_temp_dir() as tmp:` (already imported at top of file).

### [NIT] test-junction.py summary uses wrong stream and format
**Location:** `plugins/mill/unit_tests/test-junction.py:130`
**Issue:** `print(f"\n{passed} passed, {failed} failed")` writes to stdout; all sibling test files write `PASS/FAIL -- ...` summaries to `sys.stderr`. Also breaks `run-all.py`'s stderr-parsing convention.
**Fix:** Follow the pattern in `test-wiki-daemon.py`: `print("", file=sys.stderr)` + conditional FAIL/PASS lines to stderr.

## Verdict

REQUEST_CHANGES — one blocking test logic defect (false-positive assertion in `test-junction.py` case c) plus two NITs.
