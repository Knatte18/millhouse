## Findings

### [BLOCKING] V3 client API signatures omit wiki_path
**Location:** Batch 1 card 6; consumed in batch 2 card 13 and batch 3 cards 21-28
**Issue:** Existing `wiki._client.read/write_commit_push` take `wiki_path` as first positional arg; the new signatures (`upsert_task(slug, *, ...)`, `set_phase(id_or_slug, phase)`, `list_tasks_brief()`, `health_check()`) drop it entirely. `_ensure_daemon` and `_connect_send_recv` require wiki_path. No mechanism described — implicit cwd resolution? module-level state? — leaves the implementer guessing how to wire `_ensure_daemon(...)`.
**Fix:** Either add `wiki_path` as required first arg to every new public function (and update every call site in batches 2/3 to pass it), or specify in card 6 that the client resolves wiki_path internally via `_paths.resolve_wiki_path(_paths.resolve_git_root())` on each call. State this explicitly.

### [BLOCKING] Integration tests still import _wiki after card 30 deletes it
**Location:** Card 30 (deletes `_wiki.py`); gap not covered by cards 34-35
**Issue:** `integration_tests/test-merge.py` imports `_wiki` directly and uses `_wiki.wiki_lock` / `_wiki.write_commit_push`. `integration_tests/test-wiki-noop-commit.py` imports `_wiki`. `integration_tests/test-wiki-concurrency.py` references `_wiki.sync_pull`. Card 30 grep guard catches these but plan provides no fix card — only halt instruction. Card 34 only addresses `wiki/config.yaml`; card 35 only ports per-CLI tests and deletes the `_wiki.py`-targeted `test-wiki.py` unit test.
**Fix:** Add a card (or expand card 35) explicitly porting/deleting `test-wiki-noop-commit.py`, `test-wiki-concurrency.py`, and the `_wiki` usage in `test-merge.py`. List exact disposition (delete vs. port) for each.

### [BLOCKING] unit_tests/test-cleanup.py patches break after card 23
**Location:** Card 23 (drops `_wiki` import from `millpy-cleanup.py`); gap in batch 3
**Issue:** `unit_tests/test-cleanup.py` uses `patch("mill_cleanup._wiki.write_commit_push")`, `patch("mill_cleanup._sidebar.regenerate")`, `patch("mill_cleanup._tasks_md.set_phase")` extensively (15+ occurrences). After card 23 removes `_wiki` import and `_tasks_md` import from `millpy-cleanup.py`, these attribute patches raise `AttributeError`. Test file is not in card 34's or card 35's Edits.
**Fix:** Add `unit_tests/test-cleanup.py` (and integration_tests counterpart if affected) to card 34 or 35, specifying replacement of all `mill_cleanup._wiki.*` / `mill_cleanup._tasks_md.*` / `mill_cleanup._sidebar.*` patches with `mill_cleanup.wiki.*` patches matching the new import shape.

### [BLOCKING] _spawn_core return-type change not propagated to callers
**Location:** Card 26 (`_spawn_core.groom_and_claim_merge` returns `dict` not `Task`); cards 22, 25 don't update callers
**Issue:** Card 26 changes `groom_and_claim_merge` return signature from `_tasks_md.Task` to `dict`. The function is called by `millpy-spawn.py` and `millpy-claim.py` (via `multi_select_groom_then_claim`); both files then access `.slug`, `.title` attributes on the result. Cards 22 (claim) and 25 (spawn) only address `_tasks_md.parse` replacements, not the spawn-core return-shape change.
**Fix:** Expand cards 22 and 25 to enumerate every site that consumes `_spawn_core.multi_select_groom_then_claim` / `groom_and_claim_merge` return values and convert attribute access to dict-key access (`picked.slug` -> `picked["slug"]`, etc.).

### [BLOCKING] Migration script does not handle missing/legacy wiki/config.yaml
**Location:** Batch 2 card 13
**Issue:** The script resolves `wiki_path` via `_paths.resolve_wiki_path`, but `resolve_wiki_path` reads `paths.wiki:` from `.millhouse/config.local.yaml`. After batch 3 strips `wiki/config.yaml` fallback (cards 19-20), a hub without `mill-config.yaml` cannot resolve. Card 13 also doesn't address operator scenario where migration runs on a wiki that already has a partial `tasks.json` (from a prior aborted run) — second run produces no new commit but the assertion is only that `commit_push` short-circuits; a partial tasks.json from an aborted batch could cause silent drift.
**Fix:** State in card 13 the precondition: `mill-config.yaml` must exist at hub-root before invoking migration. Add explicit precondition check or document it as operator responsibility. Address aborted-prior-run scenario explicitly.

### [NIT] Card 12 commit-message-only deletion comment is confusing
**Location:** Batch 1 card 12
**Issue:** "leave a one-line `# removed: covered by test-wiki-protocol.py::test_unknown_op_rejection` referenced commit-message-only; do not write the comment into the file" — phrasing is ambiguous; reads as "write the comment in commit message body" but unclear what that achieves vs. just naming the deleted test in the commit msg.
**Fix:** Reword to: "Mention the deleted test name in the commit message body; do not leave any `# removed:` comment inside the file."

### [NIT] Card 13 missing-tasks.json error semantics undefined
**Location:** Batch 2 card 13, step 4 (dry-run)
**Issue:** Dry-run prints parsed tasks but doesn't validate that the daemon's idle-exit/respawn cycle won't write a stray `tasks.json`. If daemon spins up during dry-run for any reason (e.g., parse helper triggers _client init), atomic-write-then-no-commit could leave artifacts.
**Fix:** Confirm in card 13 that `parse_home_md` is purely string-in/list-out and does not start the daemon; dry-run must not touch `tasks.json`.

### [NIT] Card 9 brief-paragraph-collapse rule loses paragraph breaks
**Location:** Batch 1 card 3 + card 9
**Issue:** Multi-paragraph briefs collapse to one space-joined paragraph — silently destroys author-intended structure. No mention of whether this is acceptable for round-trip via card 2 renderer (renderer outputs `brief` as a single line block).
**Fix:** State explicitly that paragraph-collapse is one-way (migration only; new entries via `wiki.upsert_task` accept any brief string preserved verbatim) and that the renderer never re-splits.

API signatures lack wiki_path; cards 23/30/34/35 leave broken test imports requiring cleanup before batch 3 can land green.
