## Findings

### [BLOCKING] Reuse path does not skip Steps 8–9 (claude re-launch)

**Location:** `plugins/mill/scripts/millpy-claude-sub.py` — the `if args.psmux_session in existing:` branch inside `main()`

**Issue:** The comment `# Skip to step 10 (paste prompt)` is documentation only; no control-flow skip is implemented. After `_wait_for_idle_prompt` returns `True` on the reuse path, the code falls straight through to Steps 8 (`claude_cmd_parts = [...]`) and 9 (`_psmux.send_keys(session_name, claude_cmd_str, enter=True)` + second `_wait_for_idle_prompt`). This sends `claude --model …` to a pane that already has the claude TUI running, double-calls `_wait_for_idle_prompt`, and corrupts the session state. The plan is explicit: "on success skip **directly** to Step 10"; the batch-scope decision also states `_wait_for_marker_in_pane` and, by extension, the entire launch sequence are skipped on the reuse path.

**Fix:** Introduce a `session_reused: bool` flag (set to `True` when the reuse branch succeeds) and gate Steps 8–9 behind `if not session_reused:`. Step 10 (load/paste/Enter) runs unconditionally for both paths.

---

### [BLOCKING] S1 does not detect the Steps 8–9 regression

**Location:** `plugins/mill/unit_tests/test-claude-sub.py` — S1 test body

**Issue:** S1 only asserts `new_session.call_count == 0` and `ret == 0`. It does not assert that `send_keys` is NOT called with the claude-launch command on the reuse path, and it does not assert that `_wait_for_idle_prompt` is called exactly once (for the idle check) rather than twice (idle check + Step 9 boot wait). Because both `send_keys` and `_wait_for_idle_prompt` are mocked to always succeed, the test passes silently while the re-launch code executes. The plan specifies S1 must assert `_wait_for_marker_in_pane` is NOT called and `load_buffer`/`paste_buffer`/Enter-`send_keys` ARE called — the absence-of-launch check for the claude `send_keys` call is the analogous guard for Step 9.

**Fix:** Add `mock.patch("_psmux.send_keys")` with a `MagicMock` (call recording), then assert after `main()` that no call was made with the claude-launch string (i.e., no call whose first positional arg matches the claude command pattern), and assert `_wait_for_idle_prompt` call count equals 1.

### [NIT] `# noqa: F841` is wrong on the auto-generated branch's `session_owned_by_us = True`

**Location:** `plugins/mill/scripts/millpy-claude-sub.py` — `else:` branch (auto-generated session), line with `session_owned_by_us = True  # noqa: F841`

**Issue:** The variable is consumed in the outer `except Exception` block (`if session_owned_by_us: _psmux.kill_session(session_name)`). The `F841` suppression is incorrect and misleads future readers into thinking the assignment is dead code.

**Fix:** Remove the `# noqa: F841` comment.

---

### [NIT] S7 does not verify the exact session name passed to `new_session`

**Location:** `plugins/mill/unit_tests/test-claude-sub.py` — S7 test body

**Issue:** The plan requires asserting `_psmux.new_session(session_name="new-name", …)` is called with the chosen name. The test only asserts `m_new_session.assert_called_once()` and that `call_args[1].get("shell_argv") is not None`. Because `name` is a positional argument to `new_session`, it lives in `call_args[0][0]`, which is not checked.

**Fix:** Add `assert m_new_session.call_args[0][0] == "new-name"` (or `call_args.args[0]` in newer Python) to verify the positional name argument.

---

## Verdict

REQUEST_CHANGES — the reuse path unconditionally re-launches claude inside an already-running session, and the S1 test does not guard against it.
