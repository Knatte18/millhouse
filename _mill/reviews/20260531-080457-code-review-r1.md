## Findings

### [BLOCKING] Holistic crash-recovery step 1c alive-branch poll missing liveness check
**Location:** `plugins/mill/skills/mill-go/SKILL.md` — Holistic code review, step 1, branch (c) Alive sub-bullet
**Issue:** Card 8 requires adding the `_bg.check_bg_status` per-iteration liveness check to "every place that currently instructs 'Poll the log file with `cat <log-path>` until `[mill-bg] EXIT` appears'." The step 1c Alive branch says "poll `cat <log-path>` until `[mill-bg] EXIT` appears, then resume at step 4" but adds no liveness one-liner. This branch skips step 3 (which does have the check), so a worker that dies while the alive-branch poll is running goes undetected and the poll spins indefinitely.
**Fix:** Insert the same `PYTHONPATH=... python -c "import _bg, json; from pathlib import Path; print(json.dumps(_bg.check_bg_status(Path('<log-path>'))))"` per-iteration one-liner and the `"running"` / `"exit"` / `"dead"` branch instructions immediately inside the alive-branch poll loop, before "resume at step 4."

### [NIT] Test (n) spawns real daemon process; SPAWN_TIMEOUT not patched
**Location:** `plugins/mill/unit_tests/test-wiki-daemon.py` — test (n), `_ensure_daemon` health-probe single-shot
**Issue:** Unlike tests (h) and (i), test (n) does not patch `_spawn_server` or `SPAWN_TIMEOUT`. After the health probe fails with `TimeoutError`, `_is_stale` (patched as a truthy MagicMock) causes `state_file.unlink` to run, then the unpatched `_spawn_server` is called, spawning a real daemon subprocess. The spawn-wait loop then runs for the full `SPAWN_TIMEOUT` (20 s on Windows) until `WikiStartupError` is raised. The assertion itself (exactly 1 call with `timeout=1.0`) is correct and will pass, but the test violates the plan's "spawn no real processes" rule and adds up to 20 s of wall-clock latency.
**Fix:** Add `patch("wiki._client._spawn_server")` and `patch("wiki._client.SPAWN_TIMEOUT", 0.01)` to the `with patch(...)` context in test (n), matching the pattern used in tests (h) and (i).
