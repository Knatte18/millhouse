## Findings

### [BLOCKING] `build_plan` internal config load breaks test-cleanup.py verify
**Location:** Batch 2, Card 8
**Issue:** Card 8 adds `cfg = _load_config(wiki_path, hub_root)` inside `build_plan` to feed `_paths.status_path(wt_path, cfg)`, but `test-cleanup.py` (a unit test) calls `build_plan` directly with tempdir fixtures. Those fixtures almost certainly do not contain a `wiki/config.yaml` with `paths.status_md`. When `_config.load_config` returns `{}` or a config without the new key, `_paths.status_path` raises `KeyError` before `_read_phase` can catch it, crashing `build_plan` and failing the batch 2 verify.
**Fix:** Either (a) keep `_read_phase(_paths.resolve_task_path(wt_path, "_mill/status.md"))` unchanged in `build_plan` — it is already correct and test-safe, sacrificing only cosmetic uniformity for that one call — or (b) thread `cfg` through `build_plan`'s signature and update `test-cleanup.py`'s call site. Option (a) is zero-risk; option (b) is the principled full refactor. The plan's stated rationale for the internal-load approach ("avoid touching test-cleanup.py") is self-defeating: the internal load introduces a new fixture dependency that requires touching the test anyway.

### [NIT] Card 8 misidentifies `_load_config` as locally defined
**Location:** Batch 2, Card 8
**Issue:** Card 8 instructs the implementer to "search for `def _load_config` near the top of the file" — but `millpy-cleanup.py` contains `from _config import load_config as _load_config`; there is no local `def`. An implementer following the literal instruction will search, find nothing, and lose confidence in the requirements.
**Fix:** Replace the description with: "`_load_config` is available via the existing import `from _config import load_config as _load_config`; no new import is needed."
