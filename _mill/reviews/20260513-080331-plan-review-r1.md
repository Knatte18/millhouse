## Findings

### [BLOCKING] Junction/symlink detection uses resolved path, not original

**Location:** Batch 1, Card 1 (`_safe_rmtree.py`, requirements step 5)
**Issue:** Step 5 checks `_is_reparse_point(resolved_path)` and `resolved_path.is_symlink()` after `Path(path).resolve()`. On Windows, `Path.resolve()` calls `GetFinalPathNameByHandle` without `FILE_FLAG_OPEN_REPARSE_POINT`, which follows NTFS junctions to their target. If `path` is a junction, `resolved_path` is the junction target — neither `_is_reparse_point` nor `is_symlink` fires, no `SystemExit` is raised, and `_walk_strip_reparse_points` then `shutil.rmtree` run against the target directory. This is the exact failure mode the task exists to prevent. The Discussion spec ("path itself is a junction") contradicts the Plan ("resolved_path") on this point; the `refuses when path is itself a junction` test would fail outright.
**Fix:** Check the original, un-resolved path before resolving: `if Path(path).is_symlink() or (os.name == "nt" and _is_reparse_point(Path(path))): raise SystemExit(...)`. Only then call `resolved_path = Path(path).resolve()` for the remaining checks.

### [NIT] Card 4 misstates the cleanup call form for test-millpy-spawn.py

**Location:** Batch 2, Card 4
**Issue:** Card 4 says "replace the `addCleanup(shutil.rmtree, self.tmp_path, ...)` calls" at lines 825, 887, 1002, but those locations contain `shutil.rmtree(str(tmpdir), ignore_errors=True)` in `finally` blocks, not `addCleanup`. An implementer searching for the `addCleanup` pattern at those lines won't find it, risks skipping the three callsites, and the gate (Card 6) would fail.
**Fix:** Describe the actual form: "replace `shutil.rmtree(str(tmpdir), ignore_errors=True)` in the `finally` block at each location with `_safe_rmtree.safe_rmtree(tmpdir, allowed_root=tmpdir, ignore_errors=True)`."
