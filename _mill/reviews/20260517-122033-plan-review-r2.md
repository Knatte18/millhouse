## Findings

### [BLOCKING] Card 3 omits updating existing read_branch test Case B

**Location:** Batch 1 / Card 3 (`_status.py` + `test-status.py`)

**Issue:** The existing test Case B in `test-status.py` calls `read_branch` with `cfg={"spawn": {"branch_prefix": "hanf"}}` (no trailing slash) and asserts `result == "hanf/foo"`. That assertion passes today only because the bug adds the separator (`f"{prefix}/{slug}"`). After Card 3 changes `derived = f"{prefix}/{slug}"` to `f"{prefix}{slug}"`, the same call returns `"hanffoo"`, causing Case B to fail. The plan does not mention updating this test, so `verify: python plugins/mill/unit_tests/run-all.py` will fail on Batch 1.

**Fix:** In Card 3's requirements, add an explicit instruction: update the existing Case B assertion in `test-status.py` to use `cfg={"spawn": {"branch_prefix": "hanf/"}}` (with the separator included per the canonical schema) and update the expected value to `"hanf/foo"`. The new test `test_read_branch_fallback_no_extra_slash()` already uses `"hanf/"` correctly; the existing Case B just needs to be brought into alignment.

### [NIT] Card 9 container-form fixture doesn't specify config seeding

**Location:** Batch 4 / Card 9 (`test-bg-launcher.py`)

**Issue:** The description of `_make_container_form_worktree` (or equivalent fixture) doesn't mention writing `wiki/config.yaml` with `spawn.branch_prefix`. The accept test (`test_launcher_accepts_valid_task_worktree`) may pass incidentally: with an empty-prefix config, `_marker.slug_from_branch` falls into the existing `"/" in branch and not prefix` path and still resolves the slug. This works, but it exercises a different code path than production (where a real `branch_prefix` is configured) and would not catch a regression in the D1 prefix-matching path itself.

**Fix:** Add `wiki/config.yaml` seeding with `spawn: {branch_prefix: "hanf/"}` to the fixture helper. The branch in the accept-fixture can then be `hanf/<slug>` and the validation exercises the post-D1 normal path, not the fallback.
