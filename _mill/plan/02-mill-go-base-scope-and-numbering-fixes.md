- **Requirements:** Add a new function `compute_next_card_number(plan_dir: Path, target_batch_file: str) -> int` to `plugins/mill/scripts/_plan_validate.py`, placed immediately after the existing `_check_card_numbering` function. Behavior: (1) glob `plan_dir.glob("??-*.md")` excluding `00-overview.md` (mirroring the existing call-site convention e.g. `sorted(p.name for p in plan_dir.glob("??-*.md") if p.name != "00-overview.md")`), read each file's text, and call the existing `_parse_cards(text)` to build `used_numbers: dict[str, set[int]]` keyed by `batch_path.stem` — the identical `stem` keying convention `_check_card_numbering` itself already uses internally; (2) if `target_batch_file` is not among the resulting keys, raise `PlanDAGError(f"batch file stem {target_batch_file!r} not found under {plan_dir}")`; (3) compute `candidate = max(used_numbers[target_batch_file], default=0) + 1`; (4) if `candidate` is present in any OTHER batch's set (`stem != target_batch_file`), raise `PlanDAGError(f"card {candidate} already used by batch {stem!r}; {target_batch_file!r} and {stem!r} occupy overlapping numeric ranges")` naming the actual colliding `stem`; (5) otherwise return `candidate`. The function performs no write of any kind — pure read-only computation over already-on-disk batch files, callable before any card is written (unlike `_check_card_numbering`, which can only ever detect a duplicate that already exists on disk, since it never accepts a candidate number as input).

  Create `plugins/mill/unit_tests/test-plan-validate-card-numbering.py` as a new, fully self-contained test file (do NOT edit or import from the existing `plugins/mill/unit_tests/test-plan-validate.py` — see the overview's "new standalone test file" Shared Decision). Follow the same top-of-file boilerplate every file in this directory uses: `from __future__ import annotations`, `HUB = Path(__file__).resolve().parent.parent.parent.parent`, `sys.path.insert(0, str(HUB / "plugins" / "mill" / "scripts"))`, then `from _plan_validate import compute_next_card_number, PlanDAGError  # noqa: E402`. Define one small local fixture helper, `_write_batch_file(plan_dir: Path, filename: str, card_nums: list[int]) -> None`, that creates `plan_dir` if absent and writes `filename` with one `### Card {n}: t\n` line per number in `card_nums` (this minimal shape is sufficient — `_parse_cards` only requires the `### Card N:` heading line per card, confirmed by reading its regex `^###\s+Card\s+(\d+)\s*:`; no other card fields are needed for this function's own logic). Using this fixture, write four test functions following the `def test_xxx() -> None:` + `assert`/`raise AssertionError` convention used in `plugins/mill/unit_tests/test-plan-dag.py` (each wrapping its body in `tempfile.TemporaryDirectory()`): (a) `test_compute_next_card_number_simple` — one batch file `01-alpha.md` with cards `[1, 2, 3]` returns `4` for `compute_next_card_number(plan_dir, "01-alpha")`; (b) `test_compute_next_card_number_empty_batch` — a batch file with zero cards (`_write_batch_file(plan_dir, "01-alpha.md", [])`) returns `1`; (c) `test_compute_next_card_number_collision_raises` — two batch files, `01-alpha.md` with cards `[1, 2, 3]` and `02-beta.md` with cards `[4, 5]`, where `compute_next_card_number(plan_dir, "01-alpha")` raises `PlanDAGError` whose message contains both `"01-alpha"` and `"02-beta"`; (d) `test_compute_next_card_number_unknown_batch_raises` — calling with a `target_batch_file` matching no file on disk raises `PlanDAGError`. Add a `def main() -> int:` at the bottom, mirroring `test-plan-dag.py`'s exact structure (call every test function inside a `try:` block, print `"All test-plan-validate-card-numbering unit tests passed."` and `return 0` on success, catch `AssertionError` and print `f"FAIL: {exc}"` to `sys.stderr` then `return 1`), plus the standard `if __name__ == "__main__": sys.exit(main())` trailer.
