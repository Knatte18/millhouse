## Batch Scope

This batch extends `_plan_validate.py`'s `context-completeness` check so it also flags a `Requirements:` backtick token naming a bare **symbol** (function, type, constant — not a file path) whose sole resolvable declaring file is absent from a card's own `Context:`/`Edits:`/`Creates:`/`Deletes:`/`Moves:`-source set. Today the check only fires for path-shaped tokens (containing `/` or ending in a recognized source extension); a bare symbol like `` `SaveState` `` never enters the check at all. Full design rationale, rejected alternatives, and the exact algorithm for every piece below live in `_mill/discussion.md` — this batch implements that design as decided, with no open decisions left to make.

External interface the next batch consumes: the exact `message` string format for a symbol-branch finding, decided in `_mill/discussion.md`'s "Fixer-remediation message format for symbol findings" Decision — `f"card {card_num}'s Requirements: references symbol '{token}', which resolves to '{resolved_relative_path}' -- not in this card's Context:/Edits:/Creates:/Deletes:/Moves:-source"`. Batch 2 (`mill-plan-fixer-doc-update`) parses this exact substring shape (`"which resolves to '"`) to distinguish the symbol case from the pre-existing path case in `mill-plan/SKILL.md`'s fixer-remediation table, so this exact wording must not drift.

Card 1 adds new plumbing (shape detection, filesystem-walk resolution, a shared own-refs membership helper) without wiring it into the check yet, so it produces no new externally-observable behavior — the existing test suite (this batch's own `verify:`) is its regression guard. Card 2 wires the plumbing into `_check_context_completeness`'s per-token loop and adds the core happy-path tests. Card 3 adds the remaining edge-case/regression tests only (no further production-code changes) — this three-way split keeps each commit reviewable: new-plumbing-only, wiring-plus-core-tests, and edge-case-coverage-only.

### Card 1: Add symbol-candidate shape/resolution helpers and extract a shared own-refs check

- **Context:** none
- **Edits:**
  - `plugins/mill/scripts/_plan_validate.py`
- **Creates:** none
- **Deletes:** none
- **Moves:** none
- **Requirements:**
  Add three new module-level pieces to `plugins/mill/scripts/_plan_validate.py`, placed near the existing `_PATH_CANDIDATE_EXTENSIONS` constant (currently line 1575) and `_check_context_completeness` (currently line 1654), and refactor one existing inline check into a shared helper. Do not wire any of this into `_check_context_completeness`'s per-token loop yet — Card 2 does that.

  1. New constants: `_SYMBOL_SEARCH_EXTENSIONS = (".py", ".go", ".cs", ".ts")` (the code subset of `_PATH_CANDIDATE_EXTENSIONS`, defined as its own standalone tuple rather than a slice, to avoid fragile ordering coupling to `_PATH_CANDIDATE_EXTENSIONS`) and `_SYMBOL_SEARCH_DENYLIST_DIRS = frozenset({".git", "node_modules", "vendor", "__pycache__", "dist", "build", ".venv"})`.

  2. New function `_symbol_candidate_shape(token: str) -> str | None`. `token` is an original backtick-quoted Requirements: token already known by the caller to be NOT path-shaped (no `/`, doesn't end in `_PATH_CANDIDATE_EXTENSIONS`) — this function does not re-check that. Steps: (a) strip a trailing `_RE_LINE_RANGE` match; (b) strip a trailing call/generic suffix — one or more trailing balanced-bracket groups of the form `()`, `(...)`, `[...]`, or `<...>` (best-effort: repeatedly strip a trailing `(...)`, `[...]`, or `<...>` group with matched brackets, stopping when no such trailing group remains — the `<...>` form covers C# generic-method call sites like `` `GetItems<T>()` ``, which strips to `GetItems` after removing both the `()` and `<T>` groups) — call the result `base`; (c) match `base` against `^[A-Za-z_]\w*(\.[A-Za-z_]\w*)?$`; return `None` if it does not match; (d) split `base` on `.` into either 1 segment (no dot) or 2 segments (one dot); define `qualifies(segment)` as: not entirely lowercase (contains an uppercase letter anywhere in the segment, including its first character) OR contains `_`; (e) if there is 1 segment: return `base` when `qualifies(base)` is `True` (e.g. `SaveState` -> `"SaveState"`, `New` -> `"New"`), else return `None` (e.g. `config` -> `None`). If there are 2 segments: return the trailing (second) segment when `qualifies(trailing_segment)` is `True` (e.g. `reedengine.New` -> `"New"`, `zone.SourceCellsWithCoverage` -> `"SourceCellsWithCoverage"`), else return `None` — the qualifier (first) segment's own qualification is irrelevant to this decision, since the trailing segment is the only part ever used as the search key and a non-qualifying search key (e.g. `Foo.bar` -> `bar`, plain lowercase) would carry none of the "looks like code" signal the whole gate exists to enforce (e.g. `Foo.bar` -> `None`, even though `Foo` alone would qualify, because `bar` does not).

  3. New function `_resolve_symbol_files(search_key: str, project_root: Path, root: str | None, git_root: Path | None, cache: dict[str, tuple[list[Path], Path | None]]) -> tuple[list[Path], Path | None]`. Memoized (via `cache`, keyed by `search_key` — if `search_key in cache`, return `cache[search_key]` immediately without walking) first-match-wins filesystem search. Build the candidate root list in this exact order — this order is restated here in full below, so no other file needs to be read to implement it, though it is the same precedence `resolve_existing_paths` (`_review_common.py:1023`) itself uses (its docstring: "Resolution order (first match wins)"): (i) `git_root / root` when both `root` and `git_root` are not `None`; (ii) `project_root / root` when `root` is not `None`, else bare `project_root`; (iii) bare `git_root` when `git_root` is not `None` (added unconditionally on whether `root` is set, mirroring that same precedence's own unconditional trailing `git_root/raw` candidate). For each candidate root in order: skip it if it does not exist on disk; otherwise recursively walk it (pruning any directory whose basename is in `_SYMBOL_SEARCH_DENYLIST_DIRS` — do not descend into it), and for every file whose suffix is in `_SYMBOL_SEARCH_EXTENSIONS`: attempt to read its content via `path.read_text(encoding="utf-8", errors="replace")` inside a `try`/`except OSError` block; on `OSError` (e.g. a broken symlink, a permission-denied file, or any other unreadable-file condition under an arbitrary real-world project tree — unlike this file's other `read_text` calls, which only ever read controlled plan/batch markdown), skip that one file (treat it as contributing no match) and continue the walk rather than letting the exception propagate and crash the whole `_plan_validate.run()` call; `errors="replace"` means a non-UTF-8 file is still readable (with replacement characters for invalid bytes) rather than raising `UnicodeDecodeError`, so only genuine OS-level read failures are caught by the `except`. For each successfully-read file, test for a case-sensitive whole-word match of `search_key` via `re.search(r"\b" + re.escape(search_key) + r"\b", content)`; collect every matching file's `Path`. Stop at the first candidate root that yields one or more matching files — do not walk any later root in the precedence order, even if this root yielded more than one match. Store `(matches, that_root)` in `cache[search_key]` and return it. If every candidate root yields zero matches (or no candidate root exists on disk), store and return `([], None)`.

  4. New function `_covered_by_own_refs(candidate: str, own_refs: set[str], moves_sources: set[str]) -> bool`. Returns `True` when `candidate in own_refs`, OR `candidate in moves_sources`, OR (`"/" not in candidate` AND `any(Path(candidate).name == Path(entry).name for entry in own_refs)`); returns `False` otherwise. This is a pure extraction of the three conditions already inline in `_check_context_completeness`'s path branch — no behavior change.

  5. Refactor the existing path-branch membership check: the three currently-inline conditions (`if stripped_token in own_refs: continue`, `if stripped_token in moves_sources: continue`, and the basename-fallback `if "/" not in stripped_token and any(Path(stripped_token).name == Path(entry).name for entry in own_refs): continue`) become a single `if _covered_by_own_refs(stripped_token, own_refs, moves_sources): continue`. Behavior for the path branch must be byte-for-byte identical after this refactor — the existing context-completeness tests (already in `test-plan-validate.py`) are the regression guard, exercised by this card's own `verify:`.

  6. Update the module docstring's `context-completeness` one-line summary (currently line 47) to: `context-completeness — a card's Requirements: references a resolvable file-path-shaped or symbol-shaped backtick token absent from that card's own Context:/Edits:/Creates:/Deletes:/Moves:-source`.

  No test file changes in this card: none of the four new pieces are wired into `_check_context_completeness` yet, so there is no new externally-observable behavior for a new test to exercise. This card's `verify:` (the full existing test suite) is the correctness guard for step 5's refactor.
