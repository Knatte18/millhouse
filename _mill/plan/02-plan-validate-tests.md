## Batch Scope

Adds every new/changed test case for the three `_plan_validate.py`-only fixes from batch `plan-validate-fixes` that were not already covered by that batch's own `test-subprocess-util.py` card (the fence-delimiter tolerance, the naming-convention exemption, and the per-card batch-oversized restructure), plus the `_plan_validate.py`-side half of the subprocess-breadcrumb-suppression test. Every card below edits `plugins/mill/unit_tests/test-plan-validate.py` only — no card in this batch names `plugins/mill/scripts/_plan_validate.py` (or any other file `_plan_validate.py`-sized or larger) in its own `Context:`/`Edits:`/`Creates:`, per the overview's `no backtick citation of _plan_validate.py symbols from batch 2's Requirements:` Shared Decision: `test-plan-validate.py` alone is already within a few thousand tokens of `pipeline.max_batch_context_tokens`, so adding `_plan_validate.py` (or any file defining a symbol these cards' Requirements would otherwise cite) to any one card's `Context:` would push the whole batch over the cap. Every card instead points at sibling test functions already in this same file (visible via this batch's own `Edits:`) as structural templates, by name and by their approximate current line number, and describes the source behavior under test in plain prose without backtick-wrapping any `_plan_validate.py`-internal function/symbol name.

By the time this batch runs, batch `plan-validate-fixes` has already landed and pushed all four source fixes, so every test added here exercises real, already-implemented behavior — this batch's own `verify:` (the full `test-plan-validate.py` file) is the first point in this plan where all four fixes are validated end-to-end together.
