## Findings

### [NIT] "Equivalent" exception-handler claim is technically inaccurate
**Location:** Batch 1, Card 2
**Issue:** Card 2 states `except BaseException:` is "equivalently" `except (Exception, SystemExit):`. They differ: `BaseException` also catches `KeyboardInterrupt` and `GeneratorExit`, silently swallowing a Ctrl-C issued during the brief `resolve_wiki_path` call.
**Fix:** Prefer `except (Exception, SystemExit):` (the correct, narrower form) and drop the "equivalently" wording.

### [NIT] Test case 4 phrasing misdirects the implementer
**Location:** Batch 1, Card 5
**Issue:** The case is titled "falls through to the name check when `resolve_wiki_path` raises internally" — but the name check is the *primary* guard that fires before `resolve_wiki_path` is ever called. The description implies a fallback order that is the reverse of the actual implementation, which could confuse the implementer into writing the wrong assertion flow. The test logic itself is correct but the spec never states what `_subprocess_util.run` should return for each of the two sub-cases (wiki-named vs non-wiki-named cwd), leaving the implementer to infer.
**Fix:** Retitle to "name check fires before nested-halt from `resolve_wiki_path` can propagate" and add explicit mock values for `_subprocess_util.run` for both sub-cases (e.g. `stdout="C:/Code/millhouse/wiki\n"` for the wiki-cwd branch, and a tmp path for the non-wiki-cwd branch).
