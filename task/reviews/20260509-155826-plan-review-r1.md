## Findings

### [BLOCKING] `path_match_helper_*` tests fail cross-platform
**Location:** Batch 1, Card 2 (`test-vscode-processes.py` requirements)
**Issue:** All `path_match_helper_*` tests use POSIX-style `Path("/wts/foo")` with `os.name="posix"` patches, but `Path.resolve()` is not affected by patching `os.name` — on Windows it returns `C:\wts\foo`, not `/wts/foo`, so `_path_matches_cmdline` never finds the needle and returns False. Symmetrically, `path_match_helper_windows_case_insensitive` passes `Path("C:\\wts\\foo")` which on Linux resolves into a path whose string contains literal backslashes, nothing like the test haystack.
**Fix:** Replace all `path_match_helper_*` tests with `tempfile.TemporaryDirectory()`-based real paths; build the haystack from `str(real_path.resolve())` so both sides of `_path_matches_cmdline` use the same resolved string regardless of platform.

### [BLOCKING] `--slug` + empty active list breaks existing test
**Location:** Batch 2, Cards 3 and 4
**Issue:** Current code short-circuits `--slug` to `return 0` when `active == []`. New Card 3 requirements drop this guard: the `--slug` branch calls `next((e for e in active if e[1] == args.slug), None)` → `None` → prints error and returns 1. The existing test "–-slug with no active worktrees → spawn NOT called, exit 0" expects `rc == 0`. Card 4 explicitly says "Preserve every existing test exactly as-is."
**Fix:** Add before the `--slug` branch: `if not active and args.slug is not None: print("No active worktrees found.", file=sys.stderr); return 0`.

### [BLOCKING] Mock target for `find_open_vscode_paths` is semantically ineffective
**Location:** Batch 2, Cards 3 and 4 (shared decision `tests-mock-find_open_vscode_paths-not-subprocess`)
**Issue:** Card 3 instructs `from _vscode_processes import find_open_vscode_paths` and `_filter_open_worktrees` calls the resulting direct binding `find_open_vscode_paths()`. Card 4 patches `mill_vscode._vscode_processes.find_open_vscode_paths` — the module-object attribute — which is a different Python name from the direct-import binding. `unittest.mock.patch` on the module attribute does not update the already-bound name in `mill_vscode`'s namespace, so all tests that exercise the default flow (new and existing) invoke real PowerShell or `ps`.
**Fix:** Either (a) remove `from _vscode_processes import find_open_vscode_paths` and have `_filter_open_worktrees` call `_vscode_processes.find_open_vscode_paths()` through the module reference (matching the current patch target), or (b) keep the direct import and change every Card 4 patch target to `mill_vscode.find_open_vscode_paths`.

## Verdict

REQUEST_CHANGES
Three blocking issues: cross-platform test breakage in `path_match_helper_*`, an existing-test regression in the `--slug` + empty-active path, and an ineffective mock target for `find_open_vscode_paths`.
