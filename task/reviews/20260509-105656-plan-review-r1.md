## Findings

### [BLOCKING] `test-subprocess-util.py` has no `tests = [...]` list
**Location:** Batch 3, Card 8
**Issue:** Card 8 instructs the implementer to "Append each new test function to the existing `tests = [...]` list in `main()`", but `test-subprocess-util.py` uses inline `try/except` blocks with no such list — unlike `test-inplace.py` which it appears to have been confused with. The instructions are unimplementable as written.
**Fix:** Rewrite the card 8 requirement to add new tests as inline `try/except` blocks in `main()` consistent with the existing `(c)`, `(d)`, `(e)` pattern; remove the `tests = [...]` reference entirely.

### [BLOCKING] Test (d) `creationflags` assertion breaks after patch-target switch
**Location:** Batch 3, Card 9
**Issue:** Test (d) in `test-millpy-bg.py` patches `_launcher_mod.subprocess.Popen` and asserts `call_kwargs["creationflags"] == expected_flags`. After card 9 switches the patch target to `_launcher_mod._subprocess_util.popen_detached`, the captured kwargs are `{stdin, stdout, stderr}` — `creationflags` is set internally inside `popen_detached`, not passed in by the launcher. The assertion fails and `run-all.py` exits non-zero.
**Fix:** In card 9's test-update instructions, add: remove the `creationflags`/`start_new_session` assertions from test (d) and (e) — that coverage now lives in `_test_popen_detached_creationflags_on_windows` and `_test_popen_detached_start_new_session_on_posix` in `test-subprocess-util.py`. Retain the structural `patch.object` switch and the `pid` assertion.

### [BLOCKING] `millpy-merge-in-subagent.py` line 133 uses `shell=True` — incompatible with `_subprocess_util.run`
**Location:** Batch 3, Card 10
**Issue:** The plan says lines 133, 142, 154 in `millpy-merge-in-subagent.py` get "same treatment" (route through `_subprocess_util.run`). Line 133 is `subprocess.run(args.cmd, shell=True, ...)` where `args.cmd` is a plain string (the user-supplied verify command). `_subprocess_util.run` accepts `argv: list[str]` and has no `shell` parameter; routing this call through it would fail at runtime with a type mismatch and a missing flag.
**Fix:** Exempt line 133 from routing — it is a shell-escaped user command and cannot use `_subprocess_util.run`. Only lines 142 and 154 (both list-form git calls) receive the standard refactor. Add an explicit note in card 10 that line 133 is left as bare `subprocess.run`.

### [BLOCKING] `TestForwardOutput` mock targets unaddressed after `_implementer_common.py` refactor
**Location:** Batch 3, Card 10
**Issue:** Card 10 refactors `_implementer_common.py` to call `_subprocess_util.run` instead of `subprocess.run`. The `TestForwardOutput` class in `test-millpy-implement.py` (`_call()`, `test_fo_7`, `test_fo_8`) patches `_implementer_common.subprocess.run`. After the refactor that attribute is no longer called; the patch goes inert and the tests make a real `git rev-parse HEAD` call in a temp directory without a git repo — causing failures. The plan only mentions `test-millpy-implement.py:132`.
**Fix:** Add to card 10's test-update instructions: in `TestForwardOutput._call()` and in `test_fo_7`/`test_fo_8`, change `patch.object(_implementer_common.subprocess, "run", ...)` to `patch.object(_implementer_common._subprocess_util, "run", ...)`.

### [NIT] `popen_detached` import omitted from card 8 requirements
**Location:** Batch 3, Card 8
**Issue:** The new tests call `popen_detached(...)` directly, but the existing import line in `test-subprocess-util.py` is `from _subprocess_util import _GRACE_SECONDS, run`. The plan never instructs the implementer to add `popen_detached` to the import.
**Fix:** Add to card 8: "Update the import line to `from _subprocess_util import _GRACE_SECONDS, run, popen_detached`."

### [NIT] Worker-path `import _subprocess_util` placement unspecified
**Location:** Batch 3, Card 9
**Issue:** `millpy-bg.py` has two `import subprocess` statements — one inside the `if "--_worker"` fast-path block (deliberately "stdlib only, no mill imports") and one in the launcher section. The plan says "Add `import _subprocess_util` near the existing `import subprocess`" but doesn't specify which one, leaving the worker-path import placement ambiguous.
**Fix:** Clarify: add `import _subprocess_util` inside the `if "--_worker" in sys.argv:` block (alongside its existing `import subprocess`), and separately in the launcher section.

## Verdict

REQUEST_CHANGES — four blocking issues in batch 3 (test structure mismatch, test assertion breakage, shell=True incompatibility, missing mock-target update) must be resolved before implementation.
