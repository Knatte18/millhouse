## Findings

### [BLOCKING] Card 2 swallow clause must catch BaseException, not Exception
**Location:** Batch 1, Card 2
**Issue:** `resolve_wiki_path` raises `SystemExit` (a `BaseException`, not `Exception`). Card 2's wording "silently swallow the exception" does not specify `BaseException`, so an implementer writes `except Exception:` which does not catch `SystemExit`. Card 5 test case 4 explicitly patches `resolve_wiki_path` to raise `SystemExit("nested-halt")` and asserts the outer call returns normally — that test will fail if the swallow uses `except Exception:`.
**Fix:** In Card 2 Requirements, change "on any exception from `resolve_wiki_path`…silently swallow" to "on any `BaseException` from `resolve_wiki_path`…silently swallow (use `except BaseException:` or `except (Exception, SystemExit):`)".

### [NIT] Card 5 test case 6 missing mock for `resolve_main_worktree_root`
**Location:** Batch 1, Card 5, test case 6
**Issue:** `resolve_wiki_path(main_root)` with `main_root.name != "wiki"` bypasses the new guard and falls through to `resolve_main_worktree_root(git_toplevel)`, which invokes a real subprocess. Without patching, the test hits a live git call and fails in a temp directory. Every existing `resolve_wiki_path` test in the same file patches this function.
**Fix:** Add `with patch("_paths.resolve_main_worktree_root", return_value=main_root):` to test case 6.

### [NIT] Dead `CLAUDE.md` entry in walker allowlist
**Location:** Batch 2, Card 7
**Issue:** `CLAUDE.md` is listed in the allowlist but the walker visits only `plugins/mill/scripts/`, `plugins/mill/skills/`, `plugins/codeguide/scripts/`, and `plugins/codeguide/skills/`. `CLAUDE.md` lives at the repo root and is never reached, making the entry unreachable dead code.
**Fix:** Remove `CLAUDE.md` from the allowlist (it cannot match), or add a comment explaining the entry is pre-emptive if the walk scope may later expand.

### [NIT] Batch 3 smoke-check grep count is 8, not 9
**Location:** Batch 3, Batch Tests
**Issue:** "`grep -rn "Wiki access:" plugins/mill/skills/` returns nine lines (one per SKILL plus the CLAUDE.md section header)" is wrong — `CLAUDE.md` lives outside `plugins/mill/skills/`, so the grep returns 8 lines.
**Fix:** Drop the expected count to 8, or widen the command: `grep -rn "Wiki access:" plugins/mill/skills/ CLAUDE.md` → 9 lines.

### [NIT] Card 10 uses source-tree path instead of `${CLAUDE_PLUGIN_ROOT}`
**Location:** Batch 4, Card 10
**Issue:** The inline python -c guidance specifies `PYTHONPATH="plugins/mill/scripts"` and `uv run --project plugins/mill` — source-tree references that CLAUDE.md prohibits for operational commands (tests being the sole exception).
**Fix:** Lead with `PYTHONPATH="${CLAUDE_PLUGIN_ROOT}/scripts" uv run --project "${CLAUDE_PLUGIN_ROOT}"` and note the `plugins/mill/` fallback only when `${CLAUDE_PLUGIN_ROOT}` is unset in the current shell.
