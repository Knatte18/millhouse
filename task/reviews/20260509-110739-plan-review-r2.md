## Findings

### [NIT] Vestigial `os.name` patches in test-millpy-bg tests (d)/(e)
**Location:** Batch 3 / Card 9
**Issue:** After the launcher replaces its `if os.name == "nt":` Popen block with `popen_detached(...)`, the `patch.object(_launcher_mod.os, "name", "nt"/"posix")` in the updated tests no longer reaches any launcher code path. The plan states they "still gate the launcher's behaviour through helper paths the test exercises," which is incorrect post-refactor — `popen_detached` reads `_subprocess_util`'s own `os.name`, not the launcher module's. Tests still pass (assertions are simplified to `call_count == 1` and pid forwarding), but the platform-differentiating premise of (d) vs (e) is vacated.
**Fix:** Acknowledge in comments that (d)/(e) are now integration smoke-tests only; the creationflags/start_new_session differentiation has moved to `test-subprocess-util.py` blocks (k)/(l).

### [NIT] `popen_detached` env pattern diverges from `run`
**Location:** Batch 3 / Card 7
**Issue:** Plan prescribes `child_env = (env or os.environ).copy()`, which silently uses `os.environ` when `env={}` (falsy empty dict). `run` uses `env.copy() if env is not None else os.environ.copy()`, which would honour an empty dict as an intentional empty environment.
**Fix:** Use the same `env.copy() if env is not None else os.environ.copy()` guard as `run` for consistency; the plan already says "mirroring `run`."
