## Findings

### [BLOCKING] resolve_active_hub M2+sub design gap: stub not at git_root/.millhouse/
**Location:** Batch 1 Card 2 (implementation) + Batch 2 Card 3 (test)
**Issue:** `resolve_active_hub` reads `wt/.millhouse/config.local.yaml` for `hub_relative_path`, where `wt = git_root` for in-place mode. But mill-claim writes the config stub only at `hub/.millhouse/config.local.yaml` (e.g. `git_root/src/Models/.millhouse/`), not at `git_root/.millhouse/`. For M2+sub the stub is absent at the worktree root, so the helper falls back to `hub_subpath = "."` and returns `git_root` instead of `git_root/src/Models`.
**Evidence of inconsistency:** Card 1's `resolve_active_hub` M2+sub test explicitly writes the stub at `<git_root>/.millhouse/config.local.yaml` (artificial fixture), but Card 3's `resolve_path` M2+sub test correctly writes the stub only at `<hub>/.millhouse/config.local.yaml` and explicitly notes "NOT at `<git_root>/.millhouse/`". After implementing Card 2 then Card 4, the Card 3 M2+sub assertion (`== git_root / "src" / "Models" / "task" / "discussion.md"`) will fail because `resolve_active_hub` returns `git_root`.
**Fix:** In the `resolve_active_hub` implementation, initialize `hub_subpath = cfg.get("hub_relative_path", ".")` (caller's cfg as default) instead of `hub_subpath = "."`, then allow the worktree-root stub to override when present. This makes the worktree stub an override rather than the sole source of truth: cross-worktree resolution still reads the target's stub when it exists; in-place M2+sub falls back to the caller's cfg which already carries `"src/Models"`. Update the Design Decision in 00-overview.md accordingly. Update Card 1's `resolve_active_hub` M2+sub test to remove the artificial `git_root/.millhouse/config.local.yaml` stub and verify that the caller's cfg provides the hub path instead.
