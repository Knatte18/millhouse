## Findings

### [BLOCKING] M2+sub in-place + sub-dir hub remains broken post-implementation
**Location:** Batch 1 Card 2, Batch 2 Card 4
**Issue:** `resolve_path` loads cfg via `load_config(wiki_root, git_root / ".millhouse")`. For mill-claim M2+sub, `git_root/.millhouse/config.local.yaml` does not exist — mill-claim writes only to `<hub_dir>/.millhouse/config.local.yaml`. Without `hub_relative_path` in cfg, `resolve_active_worktree` looks for the active marker at `git_root/.millhouse` (wrong), fails, falls through to the worktree-dir lookup (absent for in-place), and raises `ActiveWorktreeNotFound`. The Batch 2 Card 3 tests pass only because they manually scaffold the bootstrap stub at `git_root/.millhouse/config.local.yaml` — a file mill-claim never creates. Mill-spawn does create it (see `millpy-spawn.py` sub-dir bootstrap block), so M1+sub works correctly; M2+sub does not.
**Fix:** Either (a) add a bootstrap stub write to `millpy-claim.py` at `git_root/.millhouse/config.local.yaml` matching mill-spawn's pattern, or (b) have `resolve_path` use hub-aware cfg resolution (like `resolve_wiki_path` does via its stub-indirection) rather than `load_config(wiki_root, git_root / ".millhouse")` directly. Correct the Card 3 test scaffolding to use only state that mill-claim actually creates.

### [BLOCKING] Git relative path hardcoded wrong for sub-dir hub in millpy-abandon
**Location:** Batch 3 Card 6
**Issue:** The plan emits `git -C str(active_worktree) add "task/status.md"`. For M1+sub or M2+sub, `status_path` is `<active_worktree>/<hub_relative_path>/task/status.md`, making the correct worktree-relative path `<hub_relative_path>/task/status.md`. The hardcoded `"task/status.md"` causes git to return non-zero ("did not match any files") for sub-dir hub configurations. Card 5's test assertions also embed `"task/status.md"` and only cover flat-hub layouts, so the bug is not caught.
**Fix:** Replace the hardcoded string with `str(status_path.relative_to(active_worktree).as_posix())`. Update the Card 5 assertion to match.

### [NIT] M2 test mock covers branch call but not worktrees-dir subprocess call
**Location:** Batch 1 Card 1 — M2 and M2+sub test cases
**Issue:** The tests patch `_subprocess_util.run` to return the branch name for `git rev-parse --abbrev-ref HEAD`, but `_inplace.is_inplace` also triggers `resolve_worktrees_dir → resolve_main_worktree_root → git rev-parse --git-common-dir`, which receives the same mock value. This works by coincidence (relative path resolves to git_root → parent → no slug dir) but is brittle.
**Fix:** Add `patch("_inplace.resolve_worktrees_dir", return_value=<tmp-dir-without-slug>)` alongside the subprocess mock, matching the pattern used in `test-inplace.py`.

### [NIT] test-cleanup.py not visible in review materials
**Location:** Batch 4 verify step
**Issue:** The verify command references `test-cleanup.py`; it is neither provided nor created by this batch. The claim that it "exercises both branches" of hub-mill-dir resolution cannot be confirmed.
**Fix:** Confirm the file exists and covers `hub_relative_path == "."` and the sub-dir case; if absent, Batch 4 needs a Creates card for it.
