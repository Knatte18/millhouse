## Findings

### [BLOCKING] `## Resolution` callout breaks `codeguide-setup` first-time flow
**Location:** Batch 2 / Card 3 — `codeguide-setup/SKILL.md`
**Issue:** The verbatim `## Resolution` block says "If `found == false`, halt and tell the user to run `/codeguide-setup` first." Inserted into `codeguide-setup`, this aborts the skill on its primary use case — first-time setup, where `found == false` is the normal, expected result. The "Before doing anything else..." preamble also conflicts with Steps 1–2 (flag parsing and git-toplevel detection), which must run before `resolve.py` can be called meaningfully.
**Fix:** The `## Resolution` block in `codeguide-setup/SKILL.md` must use different prose — drop the halt clause and replace with: "Use the `found` flag (along with `mode`, `cg_root`, `sibling_anchor`) to drive the first-time/refresh/subfolder dispatch in Step 5."

### [NIT] `resolve_scope.py` exit-code spec references a `--json` flag that doesn't exist
**Location:** Batch 1 / Card 1 — Requirements, "Exit code" bullet
**Issue:** "Non-zero only on hard errors (not in a git repo at all, malformed `--json` flag)" — but the argparse setup says "no flags." The `--json` mention is a copy-paste from `resolve.py` and directly contradicts the no-flags spec; an implementer following both requirements can't satisfy both.
**Fix:** Remove "malformed `--json` flag" from the exit-code conditions.

### [NIT] `_make_repo` fixture: `set-head` call placement is ambiguous
**Location:** Batch 1 / Card 2 — shared fixture helper, scenarios 5–6
**Issue:** The helper description says `_make_repo(with_origin=True)` includes `git remote set-head origin <branch>`, but scenarios 5–6 need `with_origin=True` without that call. "Skip the `set-head` call" leaves the implementer to guess whether `set-head` is internal to `_make_repo` (requiring a new parameter) or called externally (requiring scenarios 1–4 to call it explicitly after `_make_repo`).
**Fix:** Add `set_remote_head: bool = True` to the `_make_repo` signature; scenarios 1–4 use the default, scenarios 5–6 pass `set_remote_head=False`.
