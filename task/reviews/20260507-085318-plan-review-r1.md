## Findings

### [BLOCKING] Card 10 test fixtures omit wiki/config.yaml, causing spurious non-existent-path failures

**Location:** batch 3 / card 10 (`test-millpy-validate-plan.py`)
**Issue:** Both new CLI tests use a batch with `wiki/config.yaml` in `Edits:`. After Card 9, `millpy-validate-plan.py` passes the mocked `wiki_root` to `_plan_validate.run`. `_check_non_existent_path` resolves `wiki/config.yaml` against `wiki_dir` — which the existing fixture creates but leaves empty — emitting a `non-existent-path` error that `--skip-check wiki-config-mutation` does not suppress. Both tests assert RC=0 and an empty `errors` list; both will fail.
**Fix:** Add `(wiki_dir / "config.yaml").write_text("# placeholder", encoding="utf-8")` to both new test fixtures, matching the pattern used by the existing wiki-mutation tests in `test-plan-validate.py`.

### [NIT] Card 7 skip_checks tests don't specify wiki directory or config file setup

**Location:** batch 2 / card 7 (`test-plan-validate.py`)
**Issue:** The three new tests call `_plan_validate.run(..., wiki_root=wiki_dir, ...)` with `wiki/config.yaml` in `Edits:`, but `wiki_dir` is never defined in the test spec. Existing wiki-mutation tests in the same file pass no `wiki_root` to `run()` at all, so an implementer following that pattern won't create the file. `_check_non_existent_path` would then emit a spurious error, failing the `assert result == []` assertion in tests 1 and 3 and the "exactly one card-missing-field" assertion in test 2.
**Fix:** Specify that the fixture should create `wiki_dir = tmp / "wiki"; wiki_dir.mkdir(); (wiki_dir / "config.yaml").write_text("# placeholder", encoding="utf-8")` before calling `run()`.

### [NIT] Card 11 Location 1 is prose-only; Locations 2 and 3 provide bash blocks

**Location:** batch 4 / card 11 (`SKILL.md`, step 1.5)
**Issue:** Location 1 instructs to "adapt the sentence to read: 're-runs the review CLI via millpy-bg (slug `plan-validator-fix`) …'" — prose only. Locations 2 and 3 each provide an explicit ```` ```bash ```` block with the full `millpy-bg.py` invocation. This inconsistency leaves step 1.5 without a runnable command example while the two retry steps have one.
**Fix:** Add a ```` ```bash ```` block for Location 1 showing the `millpy-bg.py` invocation with `--slug plan-validator-fix`, analogous to the Location 2 block.
