### [NIT] `import re` unused given instruction to reuse `_tasks_md._SLUG_RE`
**Location:** Batch 2 / Card 4
**Issue:** Imports list includes `re`, but the requirement says "validate against `_tasks_md._SLUG_RE` — reuse the existing private regex", which needs no `re` import. `millpy-add.py` defines its own local `_SLUG_RE` (consistent pattern); reusing the private attribute of another module is also valid, but both the import and the "reuse" instruction can't both be right.
**Fix:** Either drop `re` from the import list (and accept accessing `_tasks_md._SLUG_RE`), or drop "reuse existing private regex" and define a local `_SLUG_RE = re.compile(r"^[a-z][a-z0-9-]*$")` matching `millpy-add.py`'s pattern.

### [NIT] `close_with_comment` failure: "surfaced but exits 0" — try/except not shown
**Location:** Batch 2 / Card 4, step 6
**Issue:** "Any `GhError` from this call is surfaced to the user but exits 0" implies a `try/except _gh_issues.GhError` that prints the error and falls through to `return 0`. The code skeleton doesn't show this explicitly; an implementer who misses it would surface the error as an unhandled exception (exit non-zero).
**Fix:** Add one sentence: "Wrap the `close_with_comment_fn` call in `try: … except _gh_issues.GhError as e: print(f"Warning: …", file=sys.stderr)` and continue."

### [NIT] `_patch_resolve_paths` closure arity not specified
**Location:** Batch 2 / Card 5
**Issue:** "`swaps … for closures that return wiki_path`" doesn't specify argument signatures. `resolve_git_root` takes no args; `resolve_wiki_path` takes `git_toplevel: Path`. An implementer who writes `lambda: wiki_path` for both would get a `TypeError` when `millpy-fold.py` calls `resolve_wiki_path(git_root)`.
**Fix:** Add: "The `resolve_wiki_path` replacement closure must accept (and ignore) its `git_toplevel` argument: `lambda _: wiki_path`."
