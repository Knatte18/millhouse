## Findings

### [NIT] Decision text misrepresents LLMError exit-code contract
**Location:** 00-overview.md — Shared Decision `_forward_output-convention`
**Issue:** The decision states "Exit code 1 from the CLI means a pre-launch error with no JSON emitted." But the requirements for `_run_conflicts` and the pattern in `millpy-implement.py` both emit a stuck/transient JSON blob on stdout before `return 1` for `LLMError`. Test `test_4_conflicts_llm_error` correctly asserts `rc == 1` AND JSON on stdout — contradicting the decision text.
**Fix:** Amend the decision: "Exit code 1 means either a pre-launch validation error (no JSON) or an LLMError (stuck JSON on stdout); exit code 0 always has JSON."
