## Findings

### [BLOCKING] Existing single-worktree tests break after auto-select removal
**Location:** Batch 2, Card 4
**Issue:** Three existing tests (`hub_relative_path set in per-worktree config`, `hub_relative_path = "."`, `Regression: hub config vs worktree config`) each set up exactly ONE active worktree and call `main([])` without mocking `input` or `find_open_vscode_paths`. The old code auto-selected when `len(active) == 1`. Card 3 removes that path unconditionally; the new default flow calls `_filter_open_worktrees` (which invokes the real PowerShell/ps subprocess) and then `input(...)`. In a CI context, `input()` raises `EOFError` and returns 1; in an interactive terminal it hangs. All three tests will fail assertion `if rc != 0`. Card 4's instruction to "preserve every existing test exactly as-is" is incorrect for these cases.
**Fix:** Card 4 must also update those three tests: add `patch("mill_vscode._vscode_processes.find_open_vscode_paths", return_value=set())` and `patch("mill_vscode.input", return_value="1", create=True)` to each.

## Verdict

REQUEST_CHANGES — one breaking gap between Card 3 and Card 4 on existing single-worktree tests; easy to patch.
