## Findings

### [BLOCKING] Card 4: test fixture branch mismatch causes push to fail
**Location:** Batch 1, Card 4  
**Issue:** `_make_git_repo(tmp, branch="main")` leaves the repo on branch "main". `write_initial_status` is then called with `branch="hanf/task-one"`, and the new push command `git push --set-upstream origin hanf/task-one` will fail: there is no local branch "hanf/task-one", so git errors "src refspec does not match any". The plan claims "the push succeeds" but the fixture never creates or checks out that branch.  
**Fix:** Either (a) add `subprocess.run(["git", "-C", str(repo), "checkout", "-b", "hanf/task-one"], ...)` to `_make_git_repo` before returning (when the `branch` param differs from the default init branch), or (b) change the push command to use `HEAD:{branch}` refspec (`["git", "-C", str(worktree_path), "push", "--set-upstream", "origin", f"HEAD:{branch}"]`) so the current HEAD is pushed as the named remote branch regardless of local branch name.

### [BLOCKING] Cards 6 & 7: lazy import incompatible with specified patch target
**Location:** Batch 2, Cards 6 and 7  
**Issue:** Card 6 instructs patching `_gh_issues._paths.resolve_git_root`. Card 7 instructs a lazy `import _paths` inside the function body. A function-level `import _paths` does not add `_paths` as an attribute on the `_gh_issues` module object, so `_gh_issues._paths` does not exist and the patch raises `AttributeError`. The note "NOT `_paths.resolve_git_root` directly" in Card 6 misdirects: `patch('_paths.resolve_git_root')` IS the correct mechanism for a lazy function-body import, because `unittest.mock.patch` replaces the attribute on the already-imported module in `sys.modules`, which the lazy `import _paths` inside the function would then find.  
**Fix:** Either (a) change Card 7 to import `_paths` at module level (making `_gh_issues._paths` exist as an attribute and keeping Card 6's patch target valid), or (b) change Card 6's test to use `patch('_paths.resolve_git_root')` and remove the "NOT `_paths.resolve_git_root` directly" guidance (correct for a true lazy import pattern).

## Verdict

REQUEST_CHANGES — two blocking implementation gaps would cause test failures if the plan is followed literally.
