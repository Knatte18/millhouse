### [NIT] `$CLAUDE_PLUGIN_ROOT` vs `${CLAUDE_PLUGIN_ROOT}` inconsistency in mill-go SKILL.md
**Location:** `plugins/mill/skills/mill-go/SKILL.md` — step 4.5 vs. Holistic step 3.5
**Issue:** Step 4.5 uses `"$CLAUDE_PLUGIN_ROOT"` (no braces); Holistic step 3.5 uses `"${CLAUDE_PLUGIN_ROOT}"` (with braces). Card 20 plan says "Use `${CLAUDE_PLUGIN_ROOT}` syntax." The Execute loop and Resume section also use the no-brace form, so the Holistic section is the odd one out.
**Fix:** Standardise all instances to one form; either works in bash, but consistency aids copy-paste by operators.

### [NIT] `aggregate_verdict` docstring note "aggregate is never ERROR" is now misleading
**Location:** `plugins/mill/scripts/_review_common.py` — `aggregate_verdict` docstring
**Issue:** The note states "ERROR appears only inside `reviews[]` entries; aggregate is never ERROR." After this batch, callers (`_review_code.py` via `_aggregate_top_verdict`, `_review_plan.run()` via inline override) can produce top-level ERROR verdicts. The function itself still never returns ERROR, so the statement is technically accurate for the function, but future readers of the call sites will be confused.
**Fix:** Amend the note to: "ERROR appears only inside `reviews[]` entries; `aggregate_verdict` itself never returns ERROR — callers that need all-ERROR propagation must apply `_aggregate_top_verdict` or an equivalent override after calling this function."
