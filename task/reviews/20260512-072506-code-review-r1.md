## Findings

### [BLOCKING] `_tasks_md._HEADING_RE` regex for phases is incorrect

**Location:** `plugins/mill/scripts/_tasks_md.py:27`
**Issue:** The regex `(?: \[(?P<phase>s|active|ready-to-merge|pr-pending|done|abandoned)\])?` is intended to match the phase marker. However, the `\[` before `(?P<phase>...)` and `\]` after are literal. The task intended `\[` and `\]` to be optional, capturing the phase within. As implemented, `[ready-to-merge]` will not be parsed correctly because the literal brackets are not part of the alternation group for `phase`. Specifically, the current regex requires the literal `[` and `]` to be present *outside* the alternation group, meaning it's looking for `[ ` (space) then `s|active|...` then ` ]`. The square brackets that delimit the phase (`[ready-to-merge]`) should be part of the optional group, or the alternation should only contain the phase names.
**Fix:** The correct regex for the phase group should be `(?: \[(?P<phase>s|active|ready-to-merge|pr-pending|done|abandoned)\])?`. The current implementation has an extra `\[` and `\]` around the `(?P<phase>...)` group. The `\[` and `\]` are already present in the overall `_HEADING_RE`.

### [BLOCKING] `test_tasks_md` assertions for `set_phase` are testing the wrong `sample`

**Location:** `plugins/mill/unit_tests/test-tasks-md.py:24-27`
**Issue:** The `test-tasks-md.py` file calls `set_phase(sample, "task-one", "ready-to-merge")` and `set_phase(sample, "task-one", "pr-pending")`, but the `sample` variable contains `[task-one]`, not `[task-one] [active]`. The `claim` function correctly sets `[active]`, but subsequent `set_phase` calls on the original `sample` will overwrite `None` phase, not `active`. The plan implicitly assumes `set_phase` is applied to the `claimed` variable or a similar one that has `[active]`.
**Fix:** Modify the tests to apply `set_phase` to the `claimed` variable, which has `[active]`, to ensure phase transitions are tested correctly. For example, `rtm = set_phase(claimed, "task-one", "ready-to-merge")` and `pp = set_phase(claimed, "task-one", "pr-pending")`.

### [BLOCKING] `millpy-cleanup.py` early-return guard for `CleanupPlan` is incomplete

**Location:** `plugins/mill/scripts/millpy-cleanup.py:101-102`
**Issue:** The `_print_plan` function's early-return guard `if not any([plan.to_remove_done, plan.to_remove_abandoned, plan.to_reap_pr, plan.to_report]):` incorrectly includes `plan.to_reap_pr`. The plan states that the early-return guard should *also* check `plan.to_reap_pr` (Card 11), but if `to_reap_pr` is the *only* non-empty list, the function *should* print the `REAP-PR` section. The current logic will return "Nothing to do." if `to_reap_pr` is the only non-empty list.
**Fix:** The early-return guard should be `if not any([plan.to_remove_done, plan.to_remove_abandoned, plan.to_report, plan.to_reap_pr]):`. This is the intended behavior.

### [BLOCKING] `_mock_branch_run` in `test-cleanup.py` has incorrect default for `tag -l`

**Location:** `plugins/mill/unit_tests/test-cleanup.py:65`
**Issue:** The `_mock_branch_run` function's `elif "tag" in argv and "-l" in argv:` branch defaults to `r.stdout = "archive/slug\n"`. This mock needs to be dynamic based on the slug provided in the test case for the archive tag checks to be correct. For example, when testing for `done-tag-slug`, it should return `archive/done-tag-slug\n`. Currently, it will return `archive/slug\n` regardless of the actual slug being checked.
**Fix:** Modify `_mock_branch_run` to dynamically return the tag based on the slug argument (e.g., by parsing the slug from `argv`).

### [NIT] `_apply_pr_reap_record` fetch command missing `check=True`

**Location:** `plugins/mill/scripts/millpy-cleanup.py:465` and `plugins/mill/scripts/millpy-cleanup.py:476`
**Issue:** The `_subprocess_util.run` calls for fetching `origin` in `_apply_pr_reap_record` are missing `check=True`. While the logic handles `returncode != 0`, adding `check=True` would make the intent clearer and align with typical `_subprocess_util.run` usage for commands that are expected to succeed.
**Fix:** Add `check=True` to the `_subprocess_util.run` calls for `git fetch origin` to ensure that failures are immediately obvious.

### [NIT] `_apply_pr_reap_record` uses `record.branch` as `tag_target` without checking existence

**Location:** `plugins/mill/scripts/millpy-cleanup.py:466`
**Issue:** In `_apply_pr_reap_record`, if `fetch_branch` is successful, `tag_target` is set to `record.branch`. However, the `fetch_branch` command is `git fetch origin record.branch`, which only fetches the remote branch. The actual local branch `record.branch` might have been deleted, or not exist locally. This could lead to an incorrect tag target if the local branch doesn't exist and `git tag` expects a local ref.
**Fix:** Consider using the SHA of `origin/record.branch` if the branch exists remotely, instead of `record.branch` directly, to ensure the tag points to the fetched remote state. Or fetch the branch and then resolve its SHA for tagging.

## Verdict
REQUEST_CHANGES: The identified blocking issues need to be addressed before approval. The `_HEADING_RE` regex in `_tasks_md.py` is critical for correct Home.md parsing, and the `test-tasks-md.py` assertions are not correctly testing `set_phase` on an `active` task. Additionally, the `_print_plan` guard in `millpy-cleanup.py` is incorrect, and the `_mock_branch_run` in `test-cleanup.py` has an incorrect default for archive tag checks. These issues impact core functionality and test correctness.
