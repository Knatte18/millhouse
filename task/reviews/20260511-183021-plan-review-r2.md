## Findings

### [BLOCKING] `to_reap_pr` field without default breaks all existing test constructions
**Location:** Batch 3, Card 11
**Issue:** Adding `to_reap_pr: list[SlugRecord]` to the frozen dataclass without `field(default_factory=list)` will raise `TypeError` on all 7+ existing `CleanupPlan(to_remove_done=..., to_remove_abandoned=..., to_reset_home=..., to_report=...)` constructions in `test-cleanup.py`. Card 11's `Edits:` lists only `millpy-cleanup.py`, so the test file is not updated, and `verify:` fails immediately after Card 11.
**Fix:** Declare the field as `to_reap_pr: list[SlugRecord] = dataclasses.field(default_factory=list)` so existing callers omitting the argument get an empty list by default.

### [BLOCKING] Old git-log guard tests become incompatible after Card 12; Card 17 doesn't remove them
**Location:** Batch 3, Cards 12 and 17
**Issue:** Card 12 replaces the `git log parent..branch` teardown guard with `git tag -l archive/<slug>`. Four existing tests (`guard-slug-1` through `guard-slug-4`) mock only `--show-current` and `log --oneline` calls via `_mock_branch_run`. After Card 12, the production code calls `git tag -l` instead of `git log`, so all four tests break: `guard-slug-2`, `guard-slug-3`, and `guard-slug-4` would land in `to_report` (tag absent) rather than `to_remove_done`, and `guard-slug-1`'s assertion `"unmerged commits" in plan.to_report[0]` fails because the new message is `"archive tag absent"`. Card 17 extends `_mock_branch_run` with tag handling for new tests, but never removes or rewrites the stale guard tests. `verify:` fails after every card in Batch 3 through at least Card 17.
**Fix:** Card 12 must add `test-cleanup.py` to its `Edits:` and explicitly rewrite `guard-slug-1` (→ "archive tag absent" scenario) and update `guard-slug-2/3/4` to mock `git tag -l` returning the tag (or remove them, since Card 17's new tests supersede them). Alternatively, Card 17 must explicitly say "remove or rewrite `guard-slug-1` through `guard-slug-4` blocks."

### [NIT] mill-merge Step 1 still says "or not [active]" after slug_from_branch relaxation
