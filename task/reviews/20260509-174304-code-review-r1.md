### [NIT] test-vscode-processes.py deviates from plan's import style
**Location:** `plugins/mill/unit_tests/test-vscode-processes.py:8`
**Issue:** Plan says "Import `_vscode_processes` directly (plain `import _vscode_processes` works)" but the file uses `from _vscode_processes import _path_matches_cmdline, find_open_vscode_paths`. Patch targets (`_vscode_processes._subprocess_util.run`, `_vscode_processes.os.name`) remain correct either way so this is functionally safe.
**Fix:** Change to `import _vscode_processes` and call `_vscode_processes.find_open_vscode_paths()` / `_vscode_processes._path_matches_cmdline()` to match the stated convention.

### [NIT] `--list` branch placed after `--new` rather than immediately after discover
**Location:** `plugins/mill/scripts/millpy-vscode.py:105–112`
**Issue:** Plan says to move the `--list` printing block "immediately after `discover_active_worktrees`" so the filter never runs in `--list` mode. In the implementation, `if args.new:` precedes the list-print block, meaning `--new --list` (with non-empty active) runs spawn-and-open silently ignoring `--list`. The invariant that the filter doesn't run under `--list` is maintained (filter is in the deep `else`), so this is a structural deviation only.
**Fix:** Move the list-printing block before the `if args.new:` guard.
