### [BLOCKING] Flow test fixtures will crash — backends call `_reviewers.load()` but fixtures create no `reviewers.yaml`

**Location:** Batch 2, Cards 8/9/10 + Card 13

Cards 8, 9, and 10 each specify that the review backends call `_reviewers.load(...)` at the **top of `run`** before calling `_reviewers.resolve`. `_reviewers.load` raises `ReviewerError("Missing registry at {path}")` when the file is absent (Card 1 spec). The existing flow-test fixture helpers — `_make_fixture` in all three `test-review-*-flow.py` files plus the ad-hoc worktree setups in individual test cases — do not create `reviewers.yaml` in any wiki directory. The `test_stub` carve-out lives in `_reviewers.resolve`, not in `_reviewers.load`; the load error fires before resolve is reached. Every backend call in those tests raises before any stub interaction occurs.

Card 13 migrates cfg dict shapes and rewires stubs but says nothing about creating `reviewers.yaml`. The batch 2 verify (`run-all.py`) would fail on the first flow test invocation.

**Fix:** Card 13 must explicitly state that each fixture helper creates a minimal `reviewers.yaml` at the relevant wiki path. Concretely:

- For `_review_code` and `_review_plan` tests: the backends naturally receive `wiki_root` as a parameter; if `_reviewers.load(wiki_root)` is used (the natural choice for those backends), the fixture needs `(wiki_root / "reviewers.yaml").write_text("# minimal\n")` or a valid single-entry YAML — `test_stub` bypasses the registry dict in `resolve`, so an empty-but-valid YAML (`{}` is rejected by the validator; use a named single entry) suffices.
- For `_review_discussion` tests: Card 8 explicitly says to resolve via `_paths.resolve_wiki_path(_paths.resolve_git_root())`. From the discussion fixture's worktree at `tmp/container/wts/test-slug/`, `resolve_wiki_path` returns `tmp/container/wiki/` (sibling of `wts/`). That path is distinct from the code/plan tests' `tmp_path / "wiki"`. The discussion `_make_fixture` must create `reviewers.yaml` there.
- For the ad-hoc worktree setups inside individual code-flow tests (tests 3, 4, 7, 12, 14c/14d/14e): each also calls `code_run` and hits the same failure. Card 13 must either extend the inline fixture setup or redirect them to share `_make_fixture`.
