## Findings

### [BLOCKING] `_test_registry.write_to` spec omits directory creation; fixtures never mkdir `wiki_root`
**Location:** Batch 1 Card 3 (`write_to` spec); Batch 2 Card 13 (all three `_make_fixture` helpers)
**Issue:** Every flow-test `_make_fixture` assigns `wiki_root = tmp_path / "wiki"` (or `Path(tmpdir) / "wiki"`) but never calls `.mkdir()`. Card 3's `write_to` spec says "writes the result to `wiki_root / 'reviewers.yaml'`" with no directory-creation step — calling `write_to(non_existent_dir)` raises `FileNotFoundError`, crashing every batch-2 flow test at first run.
**Fix:** In Card 3, prepend `wiki_root.mkdir(parents=True, exist_ok=True)` to `write_to`'s implementation body; or add an explicit "create `wiki_root` before calling `write_to`" step to each fixture block in Card 13.

### [NIT] Card 13 omits updating `discussion_run` call sites after Card 8 inserts `wiki_root` as positional arg
**Location:** Batch 2 Card 13 (`test-review-discussion-flow.py` section)
**Issue:** Card 8 changes `run`'s signature to `run(cfg, slug, mill_dir, wiki_root, project_root, ...)`. Card 13 says to add `_test_registry.write_to(wiki_root)` inside `_make_fixture` but never says to update the existing `discussion_run(cfg, SLUG, mill_dir, project_root)` call sites to include `wiki_root`. All three discussion flow tests would raise `TypeError`.
**Fix:** Add: "Update every `discussion_run(cfg, SLUG, mill_dir, project_root)` call to `discussion_run(cfg, SLUG, mill_dir, wiki_root, project_root)` where `wiki_root` is the path passed to `_test_registry.write_to`."

### [NIT] Card 13 Edits list includes `test-llm-claude.py` and `test-review-cli.py` with no identifiable schema changes
**Location:** Batch 2 Card 13 (Edits list)
**Issue:** `test-llm-claude.py` tests `_llm_claude` in isolation with no cfg-building fixtures; `test-review-cli.py` tests only `print_error`. Neither contains `cfg["review"]` references. The card's "Rewrite every cfg-builder fixture" requirement applies to nothing in either file — the Edits list appears over-inclusive and risks confusing the implementer about what change is expected.
**Fix:** Remove both from Card 13's Edits list; or add explicit "no changes needed" notes; or assign the validate-role-refs unit test mentioned in discussion.md's Testing section to `test-review-cli.py` if that was the intent.

### [NIT] `_reviewer_test_stub.MODE = "bulk"` becomes unreferenced dead code after Card 14
**Location:** Batch 2 Card 14 (deletes `test-reviewer-modules.py`)
**Issue:** The plan retains `_reviewer_test_stub.MODE = "bulk"` "for test compatibility," but the only assertion on `stub.MODE` lives in `test-reviewer-modules.py`, which Card 14 deletes. The constant is dead code post-deletion.
**Fix:** Either remove `MODE = "bulk"` from `_reviewer_test_stub.py` in Card 14, or add an inline comment noting the constant is retained for external consumers that import the stub outside this repo.

### [NIT] Card 1 `resolve_role` spec unguarded against missing `cfg["roles"]` or `cfg["roles"][role]` parent keys
**Location:** Batch 1 Card 1 (`_reviewers.py` `resolve_role` spec)
**Issue:** The spec raises `ReviewerError("Missing roles.{role}.{scope}")` only when the subsection `cfg["roles"][role][scope]` is absent. If `cfg["roles"]` or `cfg["roles"][role]` itself is missing (stale local overlay, partial config), Python raises `KeyError` instead of `ReviewerError`, bypassing the API scripts' `except ReviewerError` handler.
**Fix:** Guard with `if role not in cfg.get("roles", {}) or scope not in cfg["roles"][role]: raise ReviewerError(f"Missing roles.{role}.{scope} in config")` before reading `reviewer` and `rounds`.
