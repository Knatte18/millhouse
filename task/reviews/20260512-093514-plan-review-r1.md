## Findings

### [BLOCKING] Mill-go Entry Phase Gate `done` row still references /mill-merge
**Location:** Batch 3 / Card 4
**Issue:** The Entry Phase Gate table in mill-go (`| done | tell user the task is complete; suggest /mill-merge if auto-merge was off |`) is not updated. Card 4 updates Handoff Step 5, Step 6, and the Entry Step 3 config-key description but misses this row. In PR mode, a user following the `done` gate's suggestion would invoke `/mill-merge` directly, bypassing mill-finalize's PR dispatch and squashing instead of creating a PR.
**Fix:** Add a fourth change to Card 4 that replaces `/mill-merge` with `/mill-finalize` in the Entry Phase Gate `done` row.

### [BLOCKING] Null dereference in mill-merge Home.md fallback (task not found)
**Location:** Batch 2 / Card 3, Change A
**Issue:** The fallback code does `task = next((t for t in tasks if t.slug == slug), None)` and then immediately evaluates `task.phase == "pr-pending"`. If the slug is absent from Home.md (e.g., orphaned state after manual Home.md edit or wiki corruption), `task` is `None` and `task.phase` raises `AttributeError` instead of surfacing the helpful halt message.
**Fix:** Insert `if task is None: halt(...)` before the `task.phase` check, using the already-drafted error message "task/status.md absent and Home.md does not show pr-pending for `<slug>`; cannot determine merge state."

### [NIT] Mill-go frontmatter description not updated; SKILLS.md regen will be stale
**Location:** Batch 3 / Card 4 and Card 6
**Issue:** Mill-go's frontmatter still reads "Hand off to mill-merge." Card 6 regenerates SKILLS.md from frontmatter, so the mill-go row will continue to say "mill-merge" after the regen.
**Fix:** Add a change to Card 4 that updates the mill-go frontmatter description to "Hand off to mill-finalize."

### [NIT] Card 4 "Step 19" label references a non-existent step number
**Location:** Batch 3 / Card 4
**Issue:** The plan says "Also find and remove or update the Handoff config-key reference in Step 19" but mill-go has no step numbered 19. The target text (`pipeline.auto_merge — whether to invoke mill-merge after success`) lives in Entry Step 3. While the implementer can locate it by text match, the wrong label adds confusion.
**Fix:** Replace "Step 19" with "Entry Step 3."

## Verdict

REQUEST_CHANGES — two blocking issues (one functional regression in PR mode, one null dereference), two NITs.
