## Findings

### [NIT] Card 4 — `_make_git_repo` extension conflicts with push-failure test
**Location:** Batch 1 / Card 4
**Issue:** The plan directs extending `_make_git_repo` to always add a bare remote, then separately says the push-failure test needs "NO origin remote (build a stripped helper or skip the bare-remote setup)." If `_make_git_repo` always sets up a remote, the failure test cannot use it — the push would succeed and the `RuntimeError` assertion would not fire.
**Fix:** State explicitly that the failure test must NOT call the modified `_make_git_repo`; instead, build a minimal inline repo (3–4 `subprocess.run` calls: `git init`, configure identity, make an initial commit, `git checkout -b hanf/task-one`) directly inside that test, without adding a remote. The plan already implies this with "stripped helper or skip the bare-remote setup" but leaving it implicit creates a real risk of a silent test inversion.

### [NIT] Card 6 — `_gh_issues._paths` not yet an attribute when TDD test (c) is written
**Location:** Batch 2 / Card 6
**Issue:** Test (c) patches `_gh_issues._paths.resolve_git_root`, but `_paths` is not a top-level attribute of `_gh_issues` until Card 7 adds `import _paths`. Executing test (c) before Card 7 raises `AttributeError` (not `AssertionError`), which may crash `main()` mid-run and prevent any tests added after (c) from executing.
**Fix:** Place tests (a) and (b) before (c) in `main()`, so they run and produce clean assertion failures before the crash. Alternatively, note that running the partial suite between Card 6 and Card 7 is expected to crash, not gracefully fail. Either clarification removes implementer ambiguity.

### [NIT] Card 6 — "test-runner driver" terminology implies a `tests = []` list that does not exist
**Location:** Batch 2 / Card 6
**Issue:** The plan says "register all three in the test-runner driver at the bottom of the file (existing pattern)." `test-gh-issues.py` has no `tests = [...]` registration list; its tests are inline code within `main()`. The wording wrongly implies the `test-spawn-core.py` list pattern.
**Fix:** Rephrase to "add all three as inline test blocks within `main()`, following the `errors += 1` pattern already used in that file."

## Verdict

APPROVE — no blocking findings; the three NITs are clarification-level and do not prevent correct implementation.
