### [NIT] Test case 4 in test-autofix.py underspecified
**Location:** Batch 1, Card 4, test case (4)
**Issue:** "a title that produces a slug longer than 30 chars → truncated at the last `-` boundary within 30 chars" gives no concrete input/expected-output pair. An implementer who misapplies the truncation logic (e.g. always hard-cutting at 30) could write a test that passes against their own wrong implementation.
**Fix:** Supply a specific example: `"Fix the null-pointer exception in the database connection pool"` → raw slug `"fix-the-null-pointer-exception-in-the"` (38 chars) → expected `"fix-the-null-pointer-exception-in"` (32... no, let's say supply a title whose raw slug is exactly 35 chars with a `-` at position 28).  Any concrete title/expected pair nails the algorithm.

### [NIT] existing_home_slugs computation timing unspecified
**Location:** Batch 3, Card 8
**Issue:** Requirement (d) says "extract `existing_home_slugs`… from Home.md" but doesn't say whether this happens once at Entry or fresh per bug. If extracted once, slugs added by earlier bugs in the same run are invisible, and the collision-avoidance suffix won't fire for intra-run duplicates (millpy-add.py will catch the duplicate, but the slug will be presented to the user without the disambiguating suffix).
**Fix:** State explicitly in requirement (d): "re-read Home.md at the start of each per-bug iteration to compute the current `existing_home_slugs`; do not cache the set from Entry."
