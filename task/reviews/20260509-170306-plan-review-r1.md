## Findings

### [NIT] Decision documents inconsistent discover signatures
**Location:** 00-overview.md "Decision: `home_tasks` parameter for `discover_active_worktrees`" vs 02-migration.md batch-local decisions / Card 8
**Issue:** Shared decision documents `discover_active_worktrees(worktrees_dir, home_tasks)` (2 params) while Card 8 implementation specifies `discover_active_worktrees(worktrees_dir, home_tasks, branch_prefix)` (3 params). Batch-local correctly overrides, but readers will get confused.
**Fix:** Update the Shared Decision in 00-overview.md to include `branch_prefix: str` so both documents match.

### [NIT] millpy-migrate-layout.py `import _active` not explicitly addressed
**Location:** Card 18 (discovery callers) and Card 24 (delete _active)
**Issue:** `millpy-migrate-layout.py` has `import _active` at the top with no apparent usages in the file body. Card 18 lists migrate-layout among callers but only mandates the `discover_active_worktrees` signature update. Card 24's `grep -r "import _active"` verification step would flag this, requiring the implementer to drop the import as part of Card 24, but the plan reads cleaner if Card 18 explicitly mentions dropping the unused import alongside the docstring update.
**Fix:** Add to Card 18 Requirements: "Drop `import _active` if unused after the discover-signature update."

### [NIT] Strict-active phase check narrows mill-merge re-run window
**Location:** Shared Decision "MarkerError semantics" (per-slug strict-active reads only); Card 31 (mill-merge SKILL.md update)
**Issue:** `_marker.task_data` raises `MarkerError` when Home.md phase is not `[active]`. mill-merge SKILL.md Step 1 calls `task_data` *before* the Step 6 phase gate. If a user re-runs mill-merge between Step 7 (Home.md flip to `[done]`) and Step 8 (worktree/branch teardown) — a narrow but real recovery window — Step 1 now halts where the old marker-based code's idempotent path proceeded through Step 6 phase gate. The error message ("Run mill-claim to convert...") is also misleading for this state.
**Fix:** Either (a) accept the narrowed re-run window as a deliberate side-effect (document in 00-overview.md as a known semantic change), or (b) restructure Card 31's SKILL.md update so the Step 6 phase-gate check runs before the Step 1 active-data lookup.
