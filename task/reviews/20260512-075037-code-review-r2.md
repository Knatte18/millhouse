### [BLOCKING] `_forward_output` git rev-parse uses wrong cwd
**Location:** `plugins/mill/scripts/_implementer_common.py:30-31`
**Issue:** The first `git rev-parse HEAD` call (in the JSON-found branch) is invoked without `cwd=project_root`. It runs in the caller's cwd, which may not be the worktree. The inferred-success branch (line 41) correctly passes `cwd=project_root`. This is a pre-existing bug the plan did not address, but it now matters because the new inference path correctly sets `cwd` while the older path does not — inconsistent behaviour for the same operation in the same function.
**Fix:** Change line 30 to `result = _subprocess_util.run(["git", "rev-parse", "HEAD"], cwd=project_root)`.

### [NIT] Test case 3 assertion drift from plan
**Location:** `plugins/mill/unit_tests/test-implementer-common.py:103-127`
**Issue:** The plan (04, Card 13, Case 3) requires the test to modify the already-tracked `README.md` after a new commit so `compute_new_dirt` sees ` M README.md`. The test does this correctly, but the snapshot is captured BEFORE the new commit (line 109), meaning the snapshot is empty. After the new commit + dirty README.md, `git status --porcelain --untracked-files=no` returns ` M README.md`, and `post - pre = {' M README.md'}` — non-empty, so inference is skipped. This works, but the test doesn't actually exercise the "snapshot has pre-existing dirt, post has same dirt + new dirt" semantics that `compute_new_dirt` is designed for. Consider seeding pre-existing dirt into the snapshot to match real mill-go usage.
**Fix:** Optional — add a second variant of Case 3 where the snapshot is captured with pre-existing ` M README.md` already present, then modify a second tracked file to verify only the new dirt is flagged. The current test passes, so this is a NIT.
