## Findings

### [NIT] Card 7 & 10 — test setups omit creating wiki/config.yaml on disk
**Location:** batch 2 card 7 (test-plan-validate.py), batch 3 card 10 (test-millpy-validate-plan.py)
**Issue:** Any batch with `wiki/config.yaml` in `Edits:` also triggers `non-existent-path` (resolved via `wiki_root / "config.yaml"`) unless that file exists on disk. Both card 7's "filters" and "does not suppress other checks" tests, and both of card 10's tests, would produce unexpected `non-existent-path` errors that aren't in `skip_checks`, causing assertions `result == []` / `return code 0` to fail. Card 7 has implicit guidance ("study existing tests" — `test_wiki_config_mutation_modifies` in the same file does create the file); card 10 has no precedent in its file.
**Fix:** Add `(wiki_dir / "config.yaml").write_text("# placeholder", encoding="utf-8")` to test setup for all four affected tests in cards 7 and 10.

### [NIT] Batch 1 scope prose implies batch 4 depends on batch 1 but DAG does not
**Location:** batch 1 scope section ("Batch 4…depends on this batch's ERROR entry being produced correctly")
**Issue:** The prose states batch 4 has a dependency on batch 1, but the DAG only has `depends-on: [3]` for batch 4. In practice batches 1 and 2 run at the same level so batch 1 always finishes before batch 4; the claim is not wrong but is confusing to a reader checking the DAG for the stated dependency.
**Fix:** Remove or qualify the prose sentence ("batch 1 always finishes before batch 4 due to execution order, not a DAG edge") so it doesn't imply a missing `depends-on` entry.

APPROVE
